## 项目概述

herdr 是一个运行在终端内的智能体多路复用器。它解决了开发者在同时管理多个编码智能体（coding agent）时面临的混乱问题——你需要知道每个智能体当前是受阻、正在工作还是已完成。herdr 让你能够在一个终端窗口中运行所有编码智能体，并一目了然地掌握它们的状态。

目标用户是频繁使用 AI 编码助手（如 Claude Code、GitHub Copilot CLI 等）的开发者，以及需要在本地或远程服务器上并行管理多个自动化任务的工程师。它不依赖任何图形界面、Electron 外壳或特定操作系统，仅需一个 Rust 二进制文件即可运行。

## 核心功能

- **真正的终端环境**：每个智能体获得一个真实的终端（而非应用模拟的终端），因此全屏 TUI 应用也能正确渲染
- **灵活的面板管理**：支持点击、拖拽、拆分面板，可创建工作区和标签页进行组织
- **状态可视化**：直观显示每个智能体的状态——受阻（blocked）、工作中（working）、已完成（done）
- **会话持久化**：关闭笔记本电脑后会话不会丢失，可以从另一台终端或通过 SSH 从手机重新连接
- **跨平台访问**：智能体可以运行在本地机器、远程服务器或任何可通过 SSH 访问的环境中
- **轻量级实现**：单个本地 Rust 二进制文件，无需 GUI、Electron、macOS 专用封装、账号或遥测

## 技术架构

herdr 的核心设计理念是“为智能体重建的 tmux”。它借鉴了 tmux 的会话持久化和终端复用能力，但针对 AI 编码智能体的工作模式进行了专门优化。

项目使用 Rust 语言开发，确保了高性能、低资源消耗和跨平台兼容性。Rust 的内存安全特性也减少了潜在的系统级错误。架构上，herdr 为每个智能体分配独立的真实终端进程，并通过多路复用层统一管理。这意味着智能体看到的不是受限的伪终端，而是完整的终端环境，支持任意 TUI 交互。

终端之间的状态信息通过高效的信道机制同步，使得用户可以实时了解每个智能体的运行状态。herdr 的架构设计强调零配置和即开即用，不依赖外部服务或守护进程。

## 安装与使用

**安装步骤**：

1. 确保系统已安装 Rust 工具链（可选，但推荐用于编译安装）
2. 从 [GitHub Releases](https://github.com/ogulcancelik/herdr/releases) 下载对应平台的预编译二进制文件
3. 将二进制文件放入系统 PATH 中（例如 `/usr/local/bin`）

**最小可用示例**：

```bash
# 启动 herdr
herdr

# 在 herdr 会话中启动一个新智能体（例如 Claude Code）
herdr new claude

# 查看智能体状态列表
herdr list

# 连接到指定智能体的终端
herdr attach claude

# 在后台分离当前会话（让智能体继续运行）
# 按 Ctrl+B, D
```

## 适用场景

- **并行编码任务管理**：同时让多个编码智能体处理不同模块（如重构后端、编写测试、生成文档），在统一界面中监控进度
- **远程开发环境**：在 SSH 连接的远程服务器上运行智能体，关闭本地终端后智能体继续工作，之后可从任何设备重新连接
- **智能体调试与协作**：观察智能体的实时输出和推理过程，当智能体受阻时及时介入调整指令
- **持续集成本地化**：在本地或 CI 环境中并行运行多个自动化任务（代码审查、静态分析、自动修复），统一管理输出日志

## 项目亮点

与同类项目相比，herdr 的差异化优势在于：

1. **真正的终端体验**：不同于其他工具模拟的伪终端，herdr 提供真实的终端环境，智能体可以运行完整的 TUI 程序而不会出现渲染问题
2. **极简依赖**：单个 Rust 二进制文件，无 Electron、无 GUI、无账号系统、无遥测，启动快速且资源占用低
3. **会话持久化**：会话在后台持续运行，支持从不同终端甚至手机 SSH 重新连接，适合长时间运行的智能体任务
4. **状态感知设计**：专门为智能体工作流设计的状态指示（受阻/工作中/已完成），让多智能体管理更加直观高效
5. **跨平台与零开销**：可在任何 Rust 支持的平台上运行，无需安装额外运行时或依赖
