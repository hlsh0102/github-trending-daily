## 项目概述

Sonarr 是一款面向 Usenet 与 BitTorrent 用户的智能 PVR（Personal Video Recorder，个人视频录制）工具，使用 C# 编写并开源。它解决的问题是：用户追更美剧、英剧等剧集时，需要频繁手动搜索资源、判断画质、下载、整理并重命名文件，过程繁琐且容易遗漏。Sonarr 通过自动监控 RSS 源、按预设规则抓取、分类、重命名剧集文件，将这一流程自动化。

其目标用户主要是自建媒体服务器（如配合 Plex、Emby、Jellyfin 使用）的爱好者、需要管理大量剧集库的用户，以及希望减少手动操作、追求画质自动升级的下载用户。项目以 GPL-3.0 协议开源，目前在 GitHub 上获得约 1.6 万颗星，是自托管媒体自动化领域的主流方案之一。

## 核心功能

- **多源监控与自动抓取**：可同时监控多个 RSS 订阅源，自动发现用户所关注剧集的新剧集并抓取下载。
- **库扫描与缺失补齐**：能扫描已有媒体库，识别缺失的剧集，并按配置自动下载补全。
- **画质自动升级**：当出现更高画质的版本（例如从 DVD 升级到 Blu-Ray）时，自动下载并替换旧文件，实现画质的持续提升。
- **自动整理与重命名**：对下载完成的文件按用户定义的命名规则进行排序、重命名并归入正确的目录结构。
- **失败下载处理**：当某个资源下载失败时，自动尝试其他可用发布版本作为替补。
- **跨平台支持**：兼容 Windows、Linux、macOS、Raspberry Pi 等主流平台，部署方式灵活。

## 技术架构

Sonarr 使用 C# 开发，基于 .NET 技术栈构建，属于典型的服务端后台应用，通常以常驻服务形式运行。其架构围绕“索引器—下载客户端—媒体库”三段式流程设计：

- **索引器（Indexer）**：对接各类 Usenet 索引站与 BitTorrent 追踪器，负责搜索与获取发布信息。
- **下载客户端（Download Client）**：与 SABnzbd、NZBGet、qBittorrent、Deluge 等下载工具集成，负责实际的下载任务。
- **媒体库管理**：监控文件系统变化，完成导入、重命名、画质判定与升级判断。

项目提供公开的 REST API，文档托管在官网，便于与其他工具集成或进行二次开发。同时采用社区翻译平台支持多语言本地化。这种松耦合的插件式设计，使得各类索引器和下载客户端都能通过配置接入，而不必修改核心代码。

## 安装与使用

Sonarr 的安装方式依平台而异，官方下载页提供了各系统的安装包与说明。常见做法如下：

1. 访问 Sonarr 官网的下载页面，选择对应操作系统（Windows、Linux、macOS 等）的安装包。
2. 在 Linux 上，通常可通过官方仓库或 Docker 镜像部署；Windows 与 macOS 则提供安装程序。
3. 安装完成后启动服务，通过浏览器访问默认的 Web 管理界面（通常为本机指定端口）。

最小可用配置流程：

- 在设置中添加至少一个索引器（Indexer）。
- 添加一个下载客户端（如 SABnzbd 或 qBittorrent）。
- 添加需要追更的剧集，并设置画质偏好。
- 指定媒体库根目录与命名规则，保存后 Sonarr 即开始按 RSS 自动监控与抓取。

首次使用时，建议先完成下载客户端与索引器的连通性测试，再批量导入已有剧集库。

## 适用场景

- **追更连载剧集**：自动监控新剧集发布，无需人工搜索下载。
- **媒体库整理**：对已有的、命名混乱的剧集文件批量重命名并归类。
- **画质自动升级**：随着更高清版本发布，自动替换旧的低画质文件。
- **自建媒体中心配套**：作为 Plex、Emby、Jellyfin 等媒体服务器的上游自动化组件，负责内容获取与管理。

## 项目亮点

与同类工具相比，Sonarr 的差异化优势体现在：

- **成熟稳定**：长期活跃维护，社区规模大，问题响应与文档完善。
- **画质自动升级机制**：不止于下载新剧集，还能持续优化已入库文件的画质，这一能力在实际使用中价值较高。
- **失败自动重试**：内置失败下载的替补策略，降低因单个资源失效导致追更中断的概率。
- **跨平台与开放 API**：覆盖主流操作系统，并提供 REST API 便于与其他自托管工具组合成完整工作流。
- **多语言支持**：通过社区翻译平台持续完善界面本地化，降低非英语用户的使用门槛。
