## 项目概述

SmartTube（曾用名 SmartTubeNext）是一款面向 Android TV 与机顶盒设备的开源媒体客户端，主要用途是在大屏电视上浏览和播放媒体内容。项目由 yuliskov 开发并维护，使用 Java 编写，采用 MIT 许可证发布，目前在 GitHub 上已获得超过 3.3 万颗星。

该项目针对的核心问题是：官方客户端在电视端的体验并不理想，广告较多、部分功能受限于设备认证或系统版本，且缺乏面向大屏的定制能力。SmartTube 提供了替代方案，让用户能够以自定义规则浏览媒体内容，例如跳过赞助片段、屏蔽广告、调整播放参数等。其目标用户是拥有 Android TV、NVIDIA Shield、Chromecast with Google TV 等设备的用户，尤其是希望获得更干净播放体验、更多可控选项的进阶用户。

根据 README 中的公告，作者曾遭遇开发环境被恶意软件感染的事件，部分构建产物可能受到影响。作者已完成磁盘清理和环境重建，目前所有构建都会经过 VirusTotal 扫描，F-Droid 版本在发布前也会额外验证。由于使用了**一次性连接码**（one-time connection codes），这类授权权限有限，例如无法修改账号密码，因此用户一般不需要额外操作；如仍希望彻底撤销授权，可在 Google 账号安全页面中移除对 YouTube TV 或 Google Drive 的访问权限。

## 核心功能

- **无广告播放与赞助片段跳过**：内置 SponsorBlock 支持，可自动或手动跳过视频中的赞助、片头、片尾等标记片段。
- **账号登录与内容同步**：支持通过一次性连接码登录账号，同步订阅、播放历史与播放列表，避免直接输入密码。
- **大屏适配的交互界面**：面向电视遥控器与方向键操作设计，布局、焦点管理与播放控制针对大屏使用场景优化。
- **播放参数自定义**：可调整分辨率上限、编解码器、帧率、音频轨道等选项，适配不同性能的电视与机顶盒。
- **多平台分发渠道**：通过 F-Droid 与 GitHub Releases 提供安装包，用户可按需选择更新来源。
- **备份与恢复**：支持导出和恢复应用数据，便于更换设备或重装后保留设置。

## 技术架构

SmartTube 使用 Java 作为主要开发语言，基于 Android 平台的媒体播放框架构建，整体架构围绕 Android TV 的 Leanback 交互模式设计。项目在实现上关注以下几个方面：

一是**播放器层的可配置性**，通过对底层解码器与渲染管线的封装，允许用户在运行时选择不同的编解码策略，以兼顾老设备的兼容性与新设备的性能表现。

二是**客户端侧的规则处理**，广告屏蔽与片段跳过逻辑在本地完成，不依赖额外的中间服务，降低了对外部接口的耦合。

三是**授权机制的安全性设计**，登录采用一次性连接码而非直接存储账号凭据，减少了密码泄露风险，也便于用户在必要时单独撤销授权。

四是**多渠道构建与签名管理**，F-Droid 版本与 GitHub 版本分别构建，并在发布前进行安全扫描，以应对供应链层面的风险。

## 安装与使用

SmartTube 需要运行在 Android TV 或基于 Android 的电视盒子上（Android 5.0 及以上较为常见）。基本安装步骤如下：

1. 在电视设备上启用“允许安装未知来源应用”。
2. 通过 F-Droid 客户端搜索安装，或在电视浏览器中访问 GitHub Releases 页面下载最新 APK。
3. 也可使用 Downloader 等工具在电视端直接输入 APK 下载地址完成安装。
4. 首次启动后，按提示进入登录流程，使用一次性连接码在手机或电脑上完成账号授权。
5. 进入设置界面，按需开启 SponsorBlock、广告屏蔽、默认分辨率等选项。

最小可用示例：安装完成后打开应用，无需登录即可浏览和播放公开内容；若需同步订阅与历史记录，则完成连接码授权即可。

## 适用场景

- **家庭电视观影**：在客厅大屏上浏览视频内容，减少广告干扰，获得更连贯的观看体验。
- **老款电视盒子再利用**：为性能有限或系统版本较旧的设备提供可调节的播放参数，延长设备使用周期。
- **需要跳过赞助片段的用户**：依靠 SponsorBlock 集成，自动跳过创作者标记的赞助段落。
- **多设备账号同步**：在电视与移动端之间同步订阅与播放进度，便于跨设备接续观看。

## 项目亮点

与同类电视端客户端相比，SmartTube 的差异主要体现在三点：一是完全开源且免费，代码公开可审计，用户可自行构建；二是功能自定义程度高，播放参数、广告处理、片段跳过等均可按需配置；三是分发渠道与安全措施相对透明，提供 F-Droid 与 GitHub 双渠道，并在遭遇安全事件后启动了构建扫描与验证流程。此外，项目社区活跃，更新频率较高，能够较快跟进上游接口变化。
