## 项目概述

Superpowers 是一套为代码代理设计的完整软件开发方法论，它构建在一组可组合的技能和初始指令之上，确保你的编程代理能够正确运用这些技能。该项目解决了当前 AI 编码工具普遍存在的问题——代理在没有明确方法论指导的情况下直接编写代码，导致代码质量低下、设计混乱、缺乏测试。Superpowers 的目标用户包括使用 Claude Code、Cursor、GitHub Copilot CLI 等 AI 编码工具的开发者和团队，希望通过一套系统化的流程提升代理开发的代码质量和工程规范性。

## 核心功能

- **需求澄清引导**：代理启动后会主动提问，引导用户明确真正的需求，避免直接跳到代码实现。它会将需求分解为易读的短片段，让用户能够仔细审阅。
- **详细实现计划生成**：在确认设计后，代理会制定清晰的实施计划，遵循 TDD（红/绿测试驱动开发）、YAGNI（你不会需要它）和 DRY（不要重复自己）原则，计划对初级工程师也足够明确易懂。
- **子代理驱动开发**：用户批准计划后，项目启动子代理驱动流程，多个代理协作处理每个工程任务，相互检查和审查工作，实现数小时的自主开发运行。
- **可组合技能体系**：提供一系列可组合的技能模块，代理可以根据项目需求灵活选择和使用，不同工具（Claude Code、Cursor、Gemini CLI 等）有对应的使用指南。
- **设计与实现分离**：强制将设计阶段和实现阶段分开，先共识设计方案再开始编码，避免常见的边设计边编码导致的返工。
- **多工具适配**：专门为 Claude Code、Cursor、Gemini CLI、GitHub Copilot CLI、Factory Droid、Kimi Code、OpenCode 等主流 AI 编码工具提供了定制化集成指南。

## 技术架构

Superpowers 的核心是一个 Shell 脚本框架，它决定了如何将技能、指令和规则组合成一个完整的代理工作流。设计思路基于以下原则：代理不应直接执行代码，而应首先理解问题域、形成设计共识、生成实施计划，再通过子代理完成编码、测试和审查。项目采用 YAGNI 和 DRY 原则来避免过度工程化和代码重复，同时强调真正的红/绿 TDD 流程——先编写测试（红），再编写最小实现让其通过（绿）。架构上支持多个子代理并行工作，每个代理负责特定任务，并配有审查和反馈机制。使用 MIT 许可证发布，便于社区贡献和定制。

## 安装与使用

大多数情况下，Superpowers 不需要传统意义上的安装。使用方式取决于你选择的 AI 编码工具：

1. **选择工具**：根据你使用的编码工具（Claude Code、Cursor、Gemini CLI 等）选择对应的 Superpowers 版本。
2. **配置初始化**：按相应工具的说明将 Superpowers 的指令和技能注入到工具的工作环境中。通常需要将 `.superpowers` 目录和初始指令添加到项目根目录或工具配置中。
3. **开始使用**：启动你的编码代理，当代理检测到项目时，它会按照 Superpowers 流程工作——首先提问需求、形成设计规范、生成实施计划，然后通过子代理完成实现。

**最小可用示例**（以 Claude Code 为例）：
```bash
# 克隆仓库
git clone https://github.com/obra/superpowers.git
cd superpowers

# 将技能和指令复制到你的项目目录
cp -r .superpowers /path/to/your/project/

# 在项目目录中启动 Claude Code
# 它会自动识别并应用 Superpowers 工作流
```

## 适用场景

- **大型项目启动阶段**：新项目初期使用 Superpowers，可以确保从一开始就建立清晰的设计文档和测试体系，避免后续重构成本。
- **代码代理托管复杂任务**：当需要代理自主完成数小时的开发工作时，Superpowers 的子代理协作机制能够有效管理多个任务和检查点。
- **团队使用 AI 编码工具标准化**：团队需要统一 AI 编码工具的工作方法时，Superpowers 提供了一套可复用的流程和规范，保证产出质量一致。
- **测试驱动开发实践**：希望强制代理遵循 TDD 和 YAGNI 原则的项目，Superpowers 将核心流程嵌入到代理的工作模式中。

## 项目亮点

与同类项目相比，Superpowers 的差异化优势在于它不仅仅是一个提示词集合，而是一套完整的软件开发方法论。它将传统的软件工程实践（设计文档、实施计划、TDD、代码审查）转化为代理可执行的工作流，而非简单地要求代理“写好代码”。项目强调“先设计后实现”和“测试驱动”，从源头减少低质量代码的产生。使用 MIT 许可证，具有高度的可定制性和社区扩展潜力，支持多种主流 AI 编码工具，降低了不同团队的使用门槛。
