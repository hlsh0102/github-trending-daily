## 项目概述

LoopX 是一个面向长时间运行的 AI Agent 团队的轻量级循环工程状态内核，旨在解决多代理协作场景中目标漂移、状态丢失、交接混乱等核心痛点。它定位为本地控制平面，与 Codex、Claude Code、Cursor 等主流编码代理完全兼容，但不替代任何代理运行时本身。

在当下 AI 编程代理日益复杂的背景下，一个任务往往跨越多个回合、多个工具甚至多个代理完成。LoopX 的核心价值在于：在代理执行有界回合时，保持目标（Objectives）、门禁（Gates）、待办事项（Todos）、证据（Evidence）、配额（Quota）和交接（Handoffs）的稳定性与可追溯性。它让“会干活的 Agent”变成“可管理、可复盘、可持续改进的数字员工”。

项目采用 MIT 许可证，基于 Python 开发，目前已在 GitHub 上获得近 3000 星标，并登上 Trendshift 趋势榜，显示出社区对循环工程这一新兴方向的强烈关注。

## 核心功能

- **持久化目标管理**：支持将长期目标持久化存储，避免代理在长对话中遗忘原始任务，确保工作始终围绕既定方向推进。

- **配额感知自动唤醒**：内置配额（Quota）机制，可感知当前资源消耗情况，在达到预设阈值时自动唤醒代理继续工作，实现无人值守的自主推进。

- **可执行待办事项**：将复杂任务拆解为可逐项验证的待办清单，每个待办都拥有明确的状态与负责人，支持跨回合追踪执行进度。

- **证据日志（Evidence Logs）**：系统自动记录每个关键决策、代码变更或验证结果，形成完整的证据链，为后续复盘和审计提供可靠依据。

- **可验证的交接机制**：支持在代理之间、回合之间进行结构化交接，交接内容包含进度快照、待办状态、遗留风险等信息，确保“接手即续跑”。

- **代理无关的设计**：不绑定任何特定代理运行时，无论是 Codex、Claude Code、Cursor 还是自建运行时，均可无缝对接。

## 技术架构

LoopX 采用“状态内核 + 控制平面”的分层架构设计。底层是一个轻量级状态内核，负责管理持久化的目标、待办、证据等核心数据结构；上层是代理无关的控制平面，通过与不同代理运行时的 API 或 CLI 接口交互，将状态注入到代理的工作循环中。

从实现角度看，LoopX 选择了 Python 作为主要开发语言，并遵循了“公共边界与私有边界分离”的设计原则，这一设计在项目的 `docs/public-private-boundary.md` 文档中有详细阐述。这种边界划分确保了外部集成面保持稳定，而内部实现可以灵活演进，极大地减少了升级时的破坏性变更。

架构的另一个关键特点是无状态运行时的有状态包装。代理运行时本身保持无状态，而 LoopX 将状态持久化到本地存储，使得整个系统可以被随时暂停、回溯、恢复，甚至在 crash 后从最近的检查点重新启动。这一设计让长周期任务不再受限于单次会话的长度和稳定性。

## 安装与使用

LoopX 的安装非常简洁，推荐使用 pip 进行安装：

```bash
pip install loopx
```

安装完成后，创建一个简单的工作目录并初始化循环：

```python
from loopx import LoopState, Goal, Todo

# 定义目标
goal = Goal(
    description="为库存系统实现自动补货逻辑",
    acceptance_criteria=["补货阈值可配置", "触发后自动生成采购单"]
)

# 初始化状态内核
state = LoopState(
    project_dir="./my_project",
    goal=goal,
    quota={"max_turns": 50, "max_cost": 10.0}
)

# 启动代理循环（以 Claude Code 为例）
state.run_with("claude-code", prompt="开始实现自动补货模块")
```

执行完成后，LoopX 会生成完整的执行报告，包含待办完成情况、关键证据链以及交接快照。若任务未完成，可以随时使用 `resume` 命令恢复：

```bash
loopx resume --snapshot latest
```

对于更复杂的多代理协作场景，LoopX 提供了 Python SDK 和 CLI 双接口，用户可以根据自身工作流灵活集成。

## 适用场景

- **跨夜/跨日长任务**：当单个对话会话无法完成任务时，LoopX 能够自动保存状态并在次日或配额重置后自动唤醒代理继续执行，无需人工干预。

- **多代理协作开发**：在同时使用 Codex 和 Claude Code 进行联合开发的场景中，LoopX 通过统一的交接机制，让不同代理可以接力完成前端、后端或测试工作。

- **企业级审计合规**：对于金融、医疗等行业，每一行代码变更通常需要可追溯的决策依据。LoopX 的证据日志功能为合规审查提供了完整的决策链路。

- **复杂重构或迁移项目**：大规模代码重构往往跨越数周，LoopX 能够将整体重构拆解为可验证的里程碑，并通过门禁机制控制每一步的质量准入。

## 项目亮点

与同类 Agent 编排工具相比，LoopX 有几个显著的差异化优势：

- **极致的轻量性**：不同于重型的 Agent 框架，LoopX 本身只做状态管理，不试图“包办”所有事情，这使它可以以极低的侵入成本嵌入现有工作流。

- **真正代理无关**：许多工具声称支持多代理，但在实际接口和状态格式上仍然绑定特定运行时。LoopX 通过严格控制公共边界，实现了对 Codex、Claude Code、Cursor 等工具的透明适配。

- **证据驱动可信执行**：LoopX 将“发生了什么”与“为什么发生”作为一等公民对待，每条待办都有对应的证据支持，从根本上解决了 AI 生成代码难以验证和追溯的问题。

- **配额机制与成本控制**：通过可配置的配额参数，LoopX 让团队能够有效控制 Agent 的资源消耗，避免失控的 API 调用或不必要的长时间运行。
