## 项目概述

Cua（读作 "kua"）是一个面向计算机使用型 AI 代理（computer-use agents）的开源基础设施项目，由 trycua 团队维护，采用 MIT 许可证。它的核心目标是让 AI 代理能够像人一样操作计算机——包括点击、输入、滚动、切换窗口等完整桌面交互行为。

当前 AI 领域的大模型大多擅长文本推理，但要让它们在真实图形界面中执行任务，往往需要一整套底层支撑：可控的操作系统环境、稳定的远程桌面通道、能感知屏幕状态的决策模型，以及可复现的评测基准。Cua 正是为填补这一层缺口而设计：它提供开源驱动、跨操作系统集群（fleets）、隔离的云桌面、本地 macOS 虚拟机，以及针对计算机使用代理的基准测试工具，覆盖训练、评估和数据生成三个关键环节。

目标用户主要包括：研究计算机使用代理的 AI 研究者与工程师、需要大规模生成 GUI 操作数据的数据团队、以及希望在产品中集成桌面自动化能力的开发者。

## 核心功能

- **开源桌面自动化驱动**：提供操作桌面环境的底层驱动能力，支持模拟与真实环境中的键鼠控制、屏幕读取等交互。
- **跨操作系统集群管理（Fleets）**：允许用户以集群方式调度和管理多个桌面环境，支持跨 OS 的规模化操作，适合批量任务与并行实验。
- **隔离云桌面与本地虚拟机**：既可使用云端隔离桌面，也可在本地运行 macOS 虚拟机，兼顾可扩展性与隐私、合规需求。
- **专用决策模型**：提供针对计算机使用场景优化的 specialist decision models，用于将屏幕状态转化为可执行动作。
- **基准测试与评测体系**：内置面向 computer-use agents 的 benchmark，用于量化代理在真实桌面任务中的表现。
- **数据生成能力**：支持在受控环境中批量采集操作轨迹与屏幕数据，服务于代理模型的训练与微调。

## 技术架构

从仓库信息与项目描述看，Cua 采用了分层设计：底层是与操作系统交互的驱动层，负责键鼠、屏幕、窗口等原语；中间层是环境编排层，负责云桌面、本地 VM 以及跨 OS 集群的创建与调度；上层则是决策与评测层，包含专用模型接口与 benchmark 工具链。

这种分层的意义在于，训练、评估与数据生成可以复用同一套环境抽象，避免为每个环节重复搭建基础设施。项目描述中强调的 "cross-OS fleets" 表明其对多操作系统环境的统一编排有明确设计考量，而 "isolated" 则说明环境隔离是架构中的一等公民，这对并行实验和安全性都很关键。

值得注意的是，仓库主语言标记为 HTML，说明项目本身包含较多前端或文档页面内容，而并非单纯的后端库——这与它面向桌面交互和可视化的定位相符。

## 安装与使用

由于上下文未提供具体的安装命令，以下为基于常见开源 AI 基础设施项目的通用步骤概述，实际请以官方文档为准：

1. 从 GitHub 克隆仓库：
   ```bash
   git clone https://github.com/trycua/cua.git
   cd cua
   ```
2. 根据官方文档安装依赖（通常是 Python 环境或容器镜像）。
3. 配置运行环境：选择本地 macOS VM 或云端隔离桌面。
4. 按文档运行最小示例，例如启动一个桌面环境并让代理执行简单操作。

最小可用示例通常包括：创建/连接一个桌面会话、向决策模型提供当前屏幕状态、接收并执行返回的动作指令。若希望快速体验，官方提供了在线入口 run.cua.ai，可直接试用 Fleets 功能，无需本地搭建。

## 适用场景

- **计算机使用代理的训练与微调**：在受控桌面环境中批量生成操作轨迹，作为训练数据。
- **代理能力评测**：使用内置 benchmark 对不同模型或策略进行标准化对比。
- **GUI 自动化测试与研究**：在隔离桌面中运行可复现的界面交互实验。
- **跨 OS 规模化任务执行**：借助 fleets 在多种操作系统环境中并行运行自动化流程。

## 项目亮点

与单一的桌面自动化脚本库或单纯的 benchmark 项目相比，Cua 的差异点在于其覆盖面的完整性：它同时提供环境（云桌面、本地 VM）、驱动、决策模型与评测工具，形成从数据生成到训练再到评估的闭环。跨操作系统集群的支持使其具备规模化能力，而隔离设计则为并行实验提供了基础。MIT 许可证也降低了商业与研究场景中的使用门槛。
