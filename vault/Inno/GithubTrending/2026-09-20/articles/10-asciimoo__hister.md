## 项目概述

Hister 是一个自托管的私有搜索引擎，用于检索用户浏览过的网页和本地保存的文件。与依赖外部爬虫和公共索引的传统搜索引擎不同，Hister 只索引用户自己产生和访问过的内容——通过浏览器扩展自动收录访问过的网页，并对本地文件建立全文索引，从而让用户能够重新找到曾经看过、但记不清出处的信息。

它解决的核心问题是：浏览器历史记录和书签只能基于标题、URL 或时间检索，无法对网页正文做全文搜索；而本地文件检索又往往分散在系统自带的搜索工具中。Hister 将这两类数据统一到一个全文索引里，并提供统一的查询入口。

目标用户是需要频繁回溯资料的研究人员、开发者、写作者，以及重视数据隐私、不希望浏览记录和文件内容上传到第三方服务的个人用户。

## 核心功能

- **网页全文索引**：通过 Firefox / Chrome 浏览器扩展，自动将访问过的页面内容送入本地索引，支持按正文中的任意短语检索。
- **本地文件索引**：对用户指定的目录和文件建立全文索引，使文档、代码、笔记等本地内容可被统一搜索。
- **多入口查询**：提供 Web 界面（默认监听 `127.0.0.1:4433`）、终端命令，以及通过 MCP（Model Context Protocol）接入的 AI 助手查询方式。
- **零配置本地运行**：针对个人本地使用场景，默认无需额外配置即可启动并开始索引。
- **单文件二进制分发**：以独立可执行文件的形式发布，覆盖主流平台，无需依赖外部数据库或运行时环境。

## 技术架构

Hister 使用 Go 语言开发，这一选择与其分发方式直接相关：Go 可以编译为单一静态二进制文件，用户下载后重命名、赋予执行权限即可运行，避免了 Python、Node.js 等项目常见的依赖安装步骤。

从架构上看，Hister 采用典型的「服务端 + 客户端插件」模式：

- **服务端**：`hister listen` 启动一个长期运行的本地 HTTP 服务，负责接收索引请求、维护全文索引、对外提供搜索接口。文档明确提示该终端需要保持打开，因为服务必须持续运行才能索引和检索页面。
- **浏览器扩展**：作为数据采集端，将用户访问的页面内容提交给本地服务，是网页索引的主要来源。
- **本地文件索引**：由服务端直接读取用户指定位置的文件夹或文件并纳入索引。
- **查询层**：Web 界面、终端命令和 MCP 接口共享同一套索引与检索能力，MCP 的接入使 AI 助手能够把 Hister 当作一个可调用的检索工具。

由于数据全部存储在本地、服务仅监听本机地址，默认部署下不存在内容外传的环节。

## 安装与使用

以官方快速开始为基础，最小可用流程如下：

1. 从最新 Release 页面下载对应平台的可执行文件，并重命名为 `hister`（Windows 下为 `hister.exe`）。
2. 在 Linux 或 macOS 上赋予执行权限：

   ```bash
   chmod +x hister
   ```

3. 启动服务：

   ```bash
   ./hister listen
   ```

   Windows 用户在 PowerShell 中运行 `.\hister.exe listen`。使用期间需保持该终端开启。

4. 打开 `http://127.0.0.1:4433`，并安装 Firefox 或 Chrome 浏览器扩展。
5. 在启用扩展的情况下访问任意网页，回到 Hister 搜索该页面中的某个短语，即可验证首个索引结果。

本地个人使用无需额外配置。若需自定义索引目录、监听地址等参数，可参考官方完整快速开始文档。

## 适用场景

- **资料回溯**：想起某篇文章中的一句话却记不清来源时，直接搜索正文内容而非标题。
- **个人知识库检索**：将笔记、文档、代码等本地文件纳入统一索引，替代分散的系统搜索。
- **隐私敏感环境**：不希望浏览历史和文件内容经过第三方服务的用户，可在完全本地的前提下获得全文搜索能力。
- **AI 助手增强**：通过 MCP 将个人索引接入 AI 助手，使模型能够基于用户自己的资料作答。

## 项目亮点

与浏览器自带的「历史记录搜索」相比，Hister 的关键差异在于**索引正文而非元数据**，因此可以用内容片段直接命中目标页面。与 Recoll、DocFetcher 等本地文件搜索工具相比，它在本地文件之外还统一纳入了网页浏览记录，覆盖两类主要的信息来源。与各类云端「个人搜索」服务相比，Hister 的索引与查询全部在本机完成，且以单二进制形式分发，部署成本低。此外，MCP 接口使其能够作为检索工具直接服务于 AI 工作流，这是多数同类工具尚未提供的能力。
