## 项目概述

Agent Skills 是一个面向 AI 编码代理（AI Coding Agents）的工程技能库，由 Addy Osmani 发起并维护。它的核心思路是：将资深工程师在日常开发中形成的工作流程、质量门禁（quality gates）和最佳实践，抽象为可被 AI 代理直接调用和遵循的“技能（Skills）”集合。

当前 AI 编码工具（如各类 CLI 代理、IDE 助手）在生成代码方面已经相当成熟，但在工程纪律上仍有明显短板：容易跳过需求澄清、忽略拆分任务、缺乏验证环节，导致产出看似完整却难以维护。Agent Skills 正是针对这一问题，把从需求定义到发布上线的完整开发周期拆解成标准化阶段，并让代理在每个阶段自动激活相应的技能。

项目的目标用户包括：希望提升 AI 代理输出质量的个人开发者、需要在团队内统一 AI 辅助开发规范的工程团队，以及正在构建或定制 AI 编码代理工具链的开发者。

## 核心功能

- **生命周期斜杠命令**：提供 9 个与开发流程对应的 slash commands，覆盖 `/spec`、`/plan`、`/build`、`/test`、`/review`、`/ship` 等关键环节，每个命令自动激活相应技能组合。
- **分阶段工作流映射**：将开发过程划分为 DEFINE、PLAN、BUILD、VERIFY、REVIEW、SHIP 六个阶段，从 Idea Refine 到 Go Live，形成一条可追踪的链路。
- **质量门禁与约束**：通过 `/constraints` 等命令设定质量标准，让代理在实现过程中主动对齐项目规范，而不是事后补救。
- **原子化任务拆分**：`/plan` 阶段强调将工作拆成小而独立的原子任务，降低单次改动范围，便于审查与回滚。
- **测试即证明**：`/test` 阶段把测试定位为“证明代码可用”的手段，而非可选项，促使代理在交付前完成验证。
- **技能可组合、可扩展**：技能以模块化方式组织，便于按团队或项目需要裁剪、替换或新增。

## 技术架构

项目使用 JavaScript 编写，MIT 协议开源。从 README 展示的结构看，其设计核心是“命令—技能—阶段”三层映射：

1. **命令层**：斜杠命令作为用户与代理交互的入口，语义直接对应开发动作。
2. **技能层**：每个技能封装某一类工程实践，包含流程说明、检查清单和约束条件，供代理在特定情境下读取并执行。
3. **阶段层**：六个阶段构成从想法到上线的宏观框架，命令与技能都挂载在阶段之下，形成一致的推进节奏。

这种设计的目的是保持代理行为的可预测性——在任意阶段，代理应遵循哪些步骤、产出什么工件、通过哪些检查，都有明确定义，从而减少“自由发挥”带来的质量波动。

## 安装与使用

仓库未提供完整安装说明，基于常见做法可概述如下：

1. 克隆仓库到本地：
   ```
   git clone https://github.com/addyosmani/agent-skills
   ```
2. 根据所使用 AI 代理工具的文档，将技能目录或配置文件接入代理的配置路径（不同工具接入方式不同，通常需要在工具的配置文件中引用本仓库的技能定义）。
3. 在代理会话中使用斜杠命令，例如：
   - `/spec`：澄清并定义要构建的功能
   - `/plan`：把需求拆分为原子任务
   - `/build`：按切片逐步实现
   - `/test`：编写并运行验证
   - `/review`：执行质量审查
   - `/ship`：准备发布

最小可用示例：先从 `/spec` 描述一个功能想法，再依次执行 `/plan` 与 `/build`，观察代理是否按阶段推进而非直接生成大量代码。

## 适用场景

- **AI 辅助的日常开发**：让代理按规范流程推进功能开发，减少返工。
- **团队 AI 规范统一**：把团队的质量标准和流程固化为技能，供所有成员共享。
- **代理工具链定制**：作为构建或增强自有 AI 编码代理的基础组件库。
- **教学与示范**：用于演示资深工程师的工作流如何被结构化为代理可执行步骤。

## 项目亮点

与零散的 prompt 模板相比，Agent Skills 的差异在于其系统性：它不是单一提示词，而是一套覆盖完整开发生命命周期的技能体系，且每个技能都绑定到明确的阶段与质量门禁。同时，项目由具有丰富前端与工程经验的作者维护，内容更贴近真实生产实践。近十万的 Star 数也反映出开发者对“让 AI 代理更像工程师”这一方向的普遍需求。
