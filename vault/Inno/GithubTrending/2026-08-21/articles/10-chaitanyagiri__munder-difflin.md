## 项目概述

Munder Difflin 是一个本地运行的多智能体（multi-agent）编排框架，它的核心目标非常直白：把你日常使用的终端编码 CLI 变成“你的克隆体”，在你离线或忙碌时，让这个克隆体持续工作，并协调一整个“办公室”的智能体在你的机器上协同完成任务。

项目名称致敬了经典美剧《办公室》（The Office）中的虚构纸业公司，而“你的克隆”在项目中被称为 Michael——既是剧中的区域经理，也是这套系统的总协调者。Munder Difflin 本身是免费、开源的，它不试图取代你正在使用的 AI 编码工具，而是将你已有的订阅和 API 额度充分利用起来，在你本机的计算资源上构建一个虚拟的“智能体办公室”。

项目目前处于可用的原型阶段（v0.4.4），支持 macOS、Windows 和 Linux 三大主流平台。需要注意的是，尽管它包装了多种商业 AI 服务的 CLI，但其核心价值在于“编排”而非“替代”——它不提供新的模型，而是提供一套让现有多模型协作的机制。

## 核心功能

- **多 CLI 适配层**：原生支持包装 Claude Code、OpenAI Codex、xAI Grok、Kimi Code、Qwen、OpenCode、Crush、pi.dev 以及 GitHub Copilot CLI，同时也兼容 Antigravity（Gemini）。用户既可以携带自己的 API Key，也可以接入本地 LLM（如 Ollama）。
- **代理间消息路由**：智能体之间可以互相传递消息、分配任务，并基于共享记忆进行上下文关联，不再作为孤立的会话存在。
- **“克隆体”协调机制**：由 Michael（你的数字克隆）作为总指挥，负责分析任务、拆解步骤并分发给不同专长的智能体执行。
- **可视化办公室界面**：基于 Pixi.js 渲染的 2D 办公室场景，每个智能体以“工位上的头像”形式呈现，你可以直观地看到谁在忙碌、谁在等待、谁在汇报。
- **终端级实时交互**：通过 xterm.js 和 node-pty 实现伪终端（PTY）支持，每个智能体都有独立的交互终端，用户可以随时介入任何任务流。
- **热插拔与本地优先**：全部运行在你自己的机器上，数据不出本机，也不依赖云端编排服务器。

## 技术架构

Munder Difflin 的技术栈选择体现了对“桌面应用性能”和“实时交互”的重视。底层采用 Electron 构建跨平台桌面壳，UI 层使用 React 进行状态管理，而渲染层则引入 Pixi.js 处理高频画面更新（如智能体状态动画），有效避免了 DOM 操作在频繁刷新时的瓶颈。

关键在于其进程模型：每个被托管的 CLI（如 Claude Code）都运行在由 node-pty 创建的独立伪终端中。这意味着 Munder Difflin 并非通过简单的 API 调用发消息，而是模拟了真实用户的键盘输入和终端输出解析。这种设计带来两个直接好处：一是对上游 CLI 的兼容性极强，只要这些 CLI 有终端交互能力即可接入；二是用户可以看到每个智能体实时的“思考过程”——即终端里的原始输出，而不是黑盒结果。

在编排逻辑上，Michael 节点维护了一个任务队列和智能体注册表。它通过监听各终端输出的结构化标记（例如代码块、决策节点）来判断任务进展，并通过注入命令的方式来委派下一步工作。这种“终端即协议”的设计虽然朴素，但极大简化了系统架构——不需要复杂的 gRPC 或消息中间件，只需要一个事件总线即可完成全双工通信。

此外，项目采用了 TypeScript 全栈编写，保证了类型安全；状态管理则交给了轻量级的 zustand 模式（未特别指明但符合 React 生态惯例）。整体架构倾向于“单机多进程”，避免引入重型的分布式系统依赖，使得安装和部署非常轻量。

## 安装与使用

由于项目处于原型阶段，官方提供预构建的桌面安装包（可从 GitHub Releases 获取），同时也支持从源码运行。

**从源码运行（开发模式）**：

```bash
# 克隆仓库
git clone https://github.com/chaitanyagiri/munder-difflin.git
cd munder-difflin

# 安装依赖
npm install

# 启动开发环境
npm run dev
```

**最小可用配置**：

1. 确保你已安装并配置好至少一个受支持的 CLI（例如 `claude` 或 `codex` 命令可在终端直接调用）。
2. 启动 Munder Difflin，在主界面中添加一个新的“员工”（Agent）。
3. 在员工配置中指定要使用的 CLI 名称、工作目录以及可选的 API Key（若 CLI 本身已登录，则可留空）。
4. 在输入框中给你的克隆体 Michael 下达一个任务，例如：“调研某某仓库的架构，并输出总结”。
5. 观察办公室视图：Michael 会自动拆解任务，分发给合适的下游智能体，并在各自终端中执行。

## 适用场景

- **异步编码任务**：当你需要离开电脑或专注其他工作目标时，让 Michael 带着若干 Claude/Codex 实例持续处理积压的代码审查、测试补充或小型重构。
- **多模型协同竞赛**：同一个任务不同侧重点（比如一个负责设计、另一个负责实现、第三个负责找 bug），通过该框架并发运行多个 CLI 并汇总结果，比较不同模型的表现。
- **个人自动化流水线**：例如定时抓取邮件、生成日报、自动整理技术资料，无需部署云端 CI 或服务端 Agent，完全利用本地订阅额度。
- **团队离线协作者空间**：在共享机器上作为无人值守的“数字员工”，当你休假时，它仍能通过协作 API 完成部分可自动化的开发辅助工作。

## 项目亮点

- **真正的本地离线编排**：与云端的 Agent 服务不同，它完全运行在你的机器上，数据隐私可控，且不依赖外部调度器。
- **“终端即协议”的兼容哲学**：因为是通过 PTY 包装而不是 API 对接，所以它对上游工具的版本更新不敏感，且能支持任何有终端 UI 的 AI 工具。
- **资源利用最大化**：它瞄准的是你已购买的订阅的“闲置额度”，例如 Claude Code 的每 5 小时用量上限，通过合理调度让这些额度在睡眠时间依然产生价值。
- **极低的上手门槛**：使用 Electron 桌面应用形态，非开发者也能通过图形界面管理智能体；而可视化办公室让多智能体的运行状态变得一目了然，降低了理解成本。
- **开源与生态友好**：MIT 许可证意味着任何人都可以基于自己的需求修改前端界面或增加新 CLI 的适配器，形成自己的“办公室氛围”。
