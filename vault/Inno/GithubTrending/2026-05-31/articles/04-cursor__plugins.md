## 项目概述

Cursor plugins 是 Cursor 团队维护的官方插件仓库，旨在为开发者提供一套高质量、标准化的 Cursor 插件规范与实现。该仓库解决了开发者在使用 Cursor 编辑器时，需要扩展 AI 编程助手能力、集成第三方工具和工作流的问题。目标用户是使用 Cursor 进行日常开发的软件工程师、技术团队负责人，以及希望为 Cursor 生态贡献插件的第三方开发者。

## 核心功能

- **标准插件规范**：提供了 `.cursor-plugin/plugin.json` 清单文件格式定义，确保所有插件具有统一的元数据、入口点和配置方式。
- **官方插件集合**：浏览器预置了多种经过验证的官方插件，覆盖持续学习、团队协作、代码审查、CLI 集成等场景。
- **插件创建工具**：`create-plugin` 插件提供脚手架功能，帮助开发者快速生成符合规范的插件项目结构并进行验证。
- **代理兼容性检测**：`agent-compatibility` 插件可自动扫描仓库运行环境，确保 Cursor 代理启动、验证和文档与实际开发环境一致。
- **CLI 代理执行**：`cli-for-agent` 插件提供了一套可靠的设计模式，使编码代理能够安全、可重复地运行命令行工具。
- **团队工作流集成**：`cursor-team-kit` 插件实现了 Cursor 开发者内部使用的 CI/CD、代码审查、自动化部署等工作流。

## 技术架构

项目基于 TypeScript 开发，采用模块化的单仓库（monorepo）架构。每个插件作为仓库根目录下的独立子目录存在，拥有自包含的 `plugin.json` 清单文件和必要的运行时资源。这种设计保证了插件的可插拔性和独立版本控制。技术栈方面，插件可以利用 Cursor 提供的 API 与编辑器交互，部分插件还集成了外部 CLI 工具，通过子进程调用来扩展代理能力。`create-plugin` 插件使用模板引擎实现快速脚手架生成，而 `agent-compatibility` 采用 CLI 扫描与代理审计相结合的双轨模式，确保兼容性检查的准确性。

## 安装与使用

1. **克隆仓库**：`git clone https://github.com/cursor/plugins.git`
2. **选择插件**：进入目标插件目录，例如 `cd continual-learning`
3. **查看清单**：阅读 `.cursor-plugin/plugin.json` 了解插件配置要求
4. **安装插件**：将整个插件目录复制到 Cursor 的插件目录中（通常位于 `~/.cursor/plugins/`）
5. **激活插件**：重启 Cursor 编辑器，或在编辑器中通过命令面板激活插件

**最小可用示例**：使用 `continual-learning` 插件时，只需将插件目录放置到正确位置，Cursor 会自动读取 `plugin.json` 中的声明，启动增量记忆更新功能。开发者无需额外配置即可启用基于转录的上下文记忆机制。

## 适用场景

- **个人开发效率提升**：通过 `continual-learning` 插件自动整理开发过程中的关键信息，避免重复询问相同上下文。
- **团队协作规范化**：利用 `cursor-team-kit` 插件统一团队成员的工作流，从代码提交到 CI 检查实现自动化。
- **代码审查与安全审计**：`thermos` 插件适用于需要严格安全审查的代码库，通过并行子代理执行深层审计。
- **第三方工具集成**：当需要将自定义 CLI 工具或内部工作流嵌入 Cursor 时，参考 `cli-for-agent` 的设计模式快速实现集成。

## 项目亮点

- **官方认证质量**：由 Cursor 团队直接维护，所有插件都经过生产环境验证，避免了第三方插件可能存在的兼容性问题。
- **高度可扩展性**：清晰的 `plugin.json` 规范降低了插件开发门槛，开发者可以根据需要快速创建自定义插件。
- **聚焦代理场景**：与其他编辑器插件不同，这些插件特别优化了 Cursor 代理的交互模式，确保 AI 代理能够可靠地执行复杂工作流。
- **活跃更新生态**：仓库日增超过 200 颗星，社区关注度高，说明其解决的是开发者真实痛点。
