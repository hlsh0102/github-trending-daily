## 项目概述

Diagram Design 是一个面向 AI 编程助手（Claude Code、Codex、Factory Droid、Pi 以及兼容 Agent Skills 的宿主环境）的图表生成技能包。它提供 39 种编辑级（editorial）图表类型，输出为自包含的 HTML + SVG 文件。项目针对的核心问题是：主流 AI 助手在生成图表时往往依赖 Mermaid 等工具，产出风格千篇一律、视觉粗糙的流程图，而设计师往往不愿将其直接用于正式文档或演示。Diagram Design 试图用一套有明确视觉规范的图表语法替代这种“Mermaid slop”。

其目标用户是需要在文档、演示、技术说明中快速生成可交付图表的开发者、技术写作者与设计师。用户无需打开 Figma，也不必花费大量时间调整配色与阴影，只需向 AI 助手描述需求，即可获得语义清晰、风格统一的图表文件。

## 核心功能

- **39 种编辑级图表类型**：涵盖架构图、循环图、Sankey 图、鱼骨图、Wardley 地图、看板、用户旅程、部署图、依赖图、UML 类图、故事地图、数据库 schema 等，覆盖技术、产品与业务场景。
- **自包含 HTML + SVG 输出**：生成的文件不依赖外部 CDN 或运行时，可直接嵌入网页或离线打开，便于归档与分享。
- **语义模式与布局分离**：排队、策略追踪、信任边界等行为可用“语义模式”描述，并复用最接近的现有布局类型，从而在不增加图表类型数量的前提下表达复杂语义。
- **可选动态效果**：静态 HTML 是默认输出，但针对有序解释（如步骤演示）可启用可访问的动态效果，兼顾信息层次与可读性。
- **源文件重绘**：支持读取 draw.io、Mermaid 或 Excalidraw 源文件，并按指定的格式、尺寸与细节级别重新绘制为 Diagram Design 风格。
- **明确的视觉规范**：无阴影、无通用圆角矩形、无冗长的配色挑选环节，强调编辑级排版与克制的美学。

## 技术架构

项目以 HTML 与 SVG 为核心技术栈，所有图表输出均为纯静态前端资源，不需要后端服务或构建工具链。这种设计使得图表文件既可以在浏览器中直接查看，也可以作为嵌入对象放入 Markdown、静态站点或文档系统。

架构上的关键决策是“语义与布局解耦”。传统图表工具通常将“图表类型”与“视觉布局”绑定，导致类型数量膨胀。Diagram Design 将行为语义（如队列、策略追踪、信任边界）抽象为可复用的语义模式，再映射到最近的布局语法上。这样既控制了类型数量，又提升了表达力。此外，项目对动态效果采取渐进增强策略：默认输出静态 HTML，仅在需要有序解释时启用可访问的动态，避免因动画影响信息获取。

## 安装与使用

项目以 Agent Skill 形式分发，通常需要将仓库克隆到 AI 助手支持的技能目录中，或通过宿主环境的技能注册机制引入。具体安装路径因宿主而异（Claude Code、Codex、Pi 等各有约定），建议参考仓库 README 中对应平台的说明。

一个最小可用示例是向 AI 助手发出指令，例如：“用 Diagram Design 生成一张三层架构图，主题为 API 网关、服务层与数据库。”助手会调用该技能，在指定目录下输出一个自包含的 `.html` 文件，其中包含内联 SVG。用户可直接用浏览器打开，或将其嵌入文档。若已有 Mermaid 或 draw.io 源文件，则可要求助手按指定尺寸与细节级别重绘。

## 适用场景

- **技术文档与架构说明**：为 README、设计文档、RFC 生成风格统一的架构图与依赖图。
- **产品与业务演示**：使用用户旅程、故事地图、看板等图表类型制作编辑级演示素材。
- **数据流与流程分析**：通过 Sankey 图、鱼骨图、Wardley 地图表达资源流向、因果分析与战略定位。
- **图表源文件迁移**：将现有 Mermaid、draw.io、Excalidraw 图表批量重绘为更精致的统一风格。

## 项目亮点

与 Mermaid 等代码化图表工具相比，Diagram Design 的核心差异在于视觉质量与语义抽象。它不追求“能用就行”的默认渲染，而是提供接近设计稿的编辑级输出，同时通过语义模式避免图表类型爆炸。与 Figma 等设计工具相比，它无需手动操作，完全由 AI 助手驱动，且输出为可版本控制的文本文件。项目明确反对通用圆角矩形与阴影堆砌的“模板感”，在风格上保持克制与一致。此外，对 draw.io、Mermaid、Excalidraw 的重绘支持，使其可以作为现有图表资产的升级通道，而非完全替代方案。
