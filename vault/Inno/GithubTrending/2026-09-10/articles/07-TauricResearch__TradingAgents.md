## 项目概述

TradingAgents 是由 TauricResearch 开发的一个多智能体（Multi-Agents）大语言模型金融交易框架。该项目的核心目标是将真实交易公司中的分工协作模式抽象为多个由 LLM 驱动的智能体角色，让它们在一个协同流程中完成市场分析、投资辩论、交易决策与风险控制等环节。

传统的量化交易系统通常依赖单一模型或固定规则流水线，难以同时兼顾基本面、技术面、情绪面与风险管理等多维信息。TradingAgents 通过引入多个具备不同职责与视角的智能体，模拟投研团队的协作与辩论过程，从而在决策中纳入更全面的考量，并输出带有推理依据的交易建议。

该项目的目标用户包括：对 LLM 智能体应用感兴趣的 AI 研究者、希望探索 AI 辅助投研流程的量化从业者，以及需要可扩展多智能体框架进行实验的开发人员。项目以 Apache-2.0 协议开源，相关方法论文发布于 arXiv（编号 2412.20138）。

## 核心功能

- **多角色智能体协作**：框架内置分析师、研究员、交易员、风险管理等多类智能体，各自承担基本面分析、技术指标解读、新闻与情绪研判等不同任务。
- **结构化辩论机制**：研究员智能体之间可围绕看多与看空观点展开多轮辩论，通过对抗式讨论收敛出更具说服力的投资判断。
- **交易决策与风险控制分离**：由交易员智能体生成交易提案，再由风险管理团队进行评估与调整，避免单一视角下的过度冒险。
- **可配置的 LLM 后端**：支持接入多种主流大语言模型，用户可根据成本、延迟与效果选择不同模型组合。
- **模块化流程编排**：各智能体的角色、提示词与协作顺序均可配置，便于研究者替换或扩展特定环节。
- **面向研究的实验接口**：提供便于复现与对比实验的调用方式，方便在学术或工程场景中验证多智能体策略的效果。

## 技术架构

项目主要使用 Python 实现，整体架构围绕“智能体 + 协作图”这一设计思路展开。每个智能体封装了独立的角色提示词、可调用的工具集合以及对应的 LLM 实例。框架通过一个编排层定义智能体之间的消息传递与执行顺序，形成从数据获取、分析、辩论到决策的完整链路。

在数据层面，框架可对接行情、财报与新闻等外部信息源，并将这些信息作为上下文注入到相关智能体的推理过程中。在决策层面，研究员之间的辩论结果会作为交易员智能体的输入，交易提案再交由风险团队审议，形成分层决策结构。这种“分析—辩论—决策—风控”的分工，使每个环节的推理过程都相对可解释、可追踪。

依赖方面，项目基于 Python 生态，通常需要配置相应的 LLM API 密钥与数据源凭证。模块化设计使得替换模型、工具或智能体角色时无需改动整体流程。

## 安装与使用

一般而言，使用该框架的基本步骤如下：

1. 克隆仓库并进入项目目录：
   ```bash
   git clone https://github.com/TauricResearch/TradingAgents.git
   cd TradingAgents
   ```

2. 创建虚拟环境并安装依赖（项目通常提供 requirements 或 pyproject 配置）：
   ```bash
   python -m venv venv
   source venv/bin/activate   # Windows 使用 venv\Scripts\activate
   pip install -r requirements.txt
   ```

3. 配置环境变量，填入所选大语言模型与数据源的 API 密钥：
   ```bash
   export OPENAI_API_KEY=your_key_here
   ```

4. 运行最小示例，指定待分析的股票代码与分析日期，启动多智能体协作流程：
   ```bash
   python -m tradingagents --ticker AAPL --date 2024-01-01
   ```

具体命令、参数名称与支持的模型列表请以仓库 README 与源码为准。建议先在少量标的与短时间窗口上验证流程，再逐步扩展实验规模。

## 适用场景

- **AI 辅助投研实验**：研究者可用其验证多智能体辩论机制对投资判断质量的影响，并与单智能体基线进行对比。
- **量化策略原型开发**：开发者可将框架输出的交易建议作为信号来源之一，融入已有的回测或组合管理流程。
- **LLM 智能体教学与研究**：其角色分工与协作编排适合作为多智能体系统设计的教学案例。
- **金融文本与情绪分析应用**：借助新闻、财报等信息的智能体解读能力，用于探索事件驱动型的分析场景。

## 项目亮点

与同类 LLM 交易项目相比，TradingAgents 的主要差异在于其明确的“团队协作 + 对抗辩论 + 分层风控”结构。它并非让单一模型直接给出买卖结论，而是通过多角色分工与辩论过程提升决策的全面性与可解释性。同时，框架保持模块化与可配置，便于研究者替换模型、工具与角色设定，兼顾了研究复现与工程扩展的需要。项目采用 Apache-2.0 协议，社区活跃度较高。
