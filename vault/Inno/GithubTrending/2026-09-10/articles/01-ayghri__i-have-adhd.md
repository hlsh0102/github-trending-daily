## 项目概述

i-have-adhd 是一个面向 AI 编码助手的「输出风格技能」（skill/plugin），用于约束代码智能体在回答问题时不要将关键结论埋没在冗长的铺陈之中。它针对的是当前主流大模型在对话中普遍存在的表达习惯：先复述问题、再展开背景、最后才给答案，并在结尾附上大量客套话。对于需要快速获取可执行结果的开发者而言，这种输出方式显著增加了阅读与检索成本。

项目的名称取自注意力缺陷多动障碍（ADHD）的通俗隐喻，但如 README 所述，使用它并不需要任何相关诊断。它本质上是一份输出契约：让助手先给出动作或结论，再以编号步骤呈现过程，并去除「希望这对你有帮助」之类的填充语。目标用户是日常使用 Claude Code、Cursor、Codex 等编码代理的开发者，以及任何希望降低 AI 回复噪音的人。

## 核心功能

- **结论前置**：要求助手把可直接执行的答案或命令放在回复开头，背景信息后置。
- **步骤编号**：将操作流程拆解为带序号的条目，便于逐步执行与核对。
- **去客套化**：移除「好问题」「让我想想」「希望有帮助」等无信息量的开场与收尾语句。
- **跨助手兼容**：以 skill/plugin 形式分发，可接入支持该机制的多类编码助手。
- **多语言文档**：仓库提供简体中文、葡萄牙语、日语、越南语、韩语、泰语等 README 版本。
- **轻量无依赖**：以提示词与配置为主，不引入额外运行时开销。

## 技术架构

项目以 Python 作为主要语言，但其核心并非复杂算法，而是一套结构化的行为指令集。实现思路是将期望的输出规范固化为可被助手加载的技能文件，并通过仓库中的 `AGENTS.md` 描述安装与生效方式。

从设计上看，它遵循「约定优于配置」：不要求用户修改助手本体，也不依赖模型微调，而是利用编码代理已有的技能加载机制，在会话上下文中注入输出约束。这种做法的好处是兼容性强、可移植性高——同一份规范可以适配不同的代理实现，只要对方支持读取技能描述。仓库同时提供 `INSTALL.md` 与多语言 README，降低了分发与本地化成本，而 MIT 许可证则允许自由修改与再分发。

## 安装与使用

最简方式是将安装指令直接粘贴到编码助手的命令行提示中：

```text
Install the i-have-adhd skill/plugin from https://github.com/ayghri/i-have-adhd, refer to the repo's AGENTS.md for instructions.
```

助手会依据仓库中的 `AGENTS.md` 完成技能加载。若需手动安装，可先克隆仓库：

```bash
git clone https://github.com/ayghri/i-have-adhd
```

随后参照 `INSTALL.md` 将技能目录放入对应助手的 skills 路径。启用后无需改变既有提问习惯，助手的回复结构会自动遵循「动作优先、步骤编号、无客套」的规范。如果希望验证效果，可以对比启用前后对同一问题的回答差异，README 中的对比表格展示了典型的前后变化。

## 适用场景

- **快速排障**：在 CI 失败、构建报错等场景中，第一时间拿到修复命令而非问题分析。
- **命令行操作**：需要按步骤执行一系列 shell 指令时，编号输出更利于逐条复制与验证。
- **代码评审与重构**：希望助手直接给出改动点与建议，而非长篇背景铺垫。
- **多助手统一风格**：团队在多种编码代理之间切换时，用同一份技能规范保持输出一致。

## 项目亮点

与常见的「提示词模板」相比，i-have-adhd 的差异在于它以可安装技能的形式存在，而非零散的提示词片段，因而更易复用与版本化管理。它不试图提升模型的推理能力，只专注修正输出的信息结构，目标明确且副作用小。多语言文档与较低的接入门槛，使其适合作为团队默认的输出规范基线。此外，MIT 许可证和纯 Python 的轻量实现，也便于按需裁剪或扩展自有的输出约束。
