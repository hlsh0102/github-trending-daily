## 项目概述

spdlog 是一个快速、高效的 C++ 日志库，专为需要高性能日志记录的应用场景而设计。它以“快”为核心设计目标，在保证功能丰富的前提下，实现了极低的写入延迟和开销。该项目采用 C++ 编写，支持 C++11 标准，适用于从嵌入式系统到大型分布式服务的各类项目。无论你是独立开发者还是大型团队的一员，spdlog 都能为你的 C++ 应用提供可靠、灵活的日志记录解决方案。

## 核心功能

- **极速性能**：经过精心优化的异步日志记录器，每秒可处理数百万条日志消息，性能远超大多数同类库。
- **双模式支持**：同时提供仅头文件（header-only）和编译版两种使用方式，满足不同项目对编译速度和分发形式的需求。
- **丰富的日志格式**：支持自定义消息格式，包括时间戳、线程 ID、日志级别、源文件名和行号等元信息。
- **灵活的日志输出目标**：内置多种 sink，可输出到控制台、文件、轮转文件、系统日志（syslog）、Windows 事件日志等。
- **异步日志记录**：提供异步日志器，将日志写入操作放入后台线程，避免阻塞主业务逻辑。
- **模式匹配与过滤**：支持日志级别动态调整和基于名称的模式匹配规则，便于运行时配置。
- **异常安全**：在日志记录过程中不会抛出异常，保证程序稳定性。

## 技术架构

spdlog 的设计架构围绕性能和可扩展性展开。其核心是一个由 `logger` 和 `sink` 组成的双层结构：`logger` 负责接收日志消息并进行格式化处理，`sink` 则负责将格式化后的消息输出到具体的目标设备。这种分离式的设计使得添加新的输出目标变得非常简单，只需实现一个 `sink` 接口即可。

库内部采用了多项性能优化技术：基于预先分配的缓冲区避免频繁的内存分配；使用`fmt`库进行高效的格式化操作；异步模式通过有界队列和专用线程池实现非阻塞写入。在编译层面，spdlog 同时提供头文件版本和静态/动态库版本，头文件版本便于快速集成，编译版本则能显著减少项目的编译时间开销。

此外，spdlog 还引入了称为“registry”的中心注册表机制，用于管理所有创建的 logger 实例，支持全局级别的配置和控制。这种架构使得在大型项目中统一管理日志策略变为可能，比如全局调整日志级别或重新加载配置。

## 安装与使用

spdlog 的安装非常灵活，可根据项目需求选择不同的方式。

**方式一：仅头文件（header-only）**

直接将 `include/spdlog` 目录复制到你的构建目录中，并在代码中包含 `<spdlog/spdlog.h>` 头文件即可使用。这种方式适合小型项目或对编译速度不敏感的快速原型开发。

**方式二：编译版（推荐）**

使用 CMake 构建系统，编译安装库文件：

```console
$ git clone https://github.com/gabime/spdlog.git
$ cd spdlog && mkdir build && cd build
$ cmake .. && cmake --build .
```

安装完成后，在项目的 CMakeLists.txt 中链接 `spdlog` 目标。

**最小使用示例：**

```cpp
#include <spdlog/spdlog.h>

int main() {
    // 创建控制台日志器
    auto console = spdlog::stdout_color_mt("console");

    // 基本日志输出
    console->info("Welcome to spdlog!");
    console->warn("An warning message: {}", 42);
    console->error("An error occurred");

    // 异步文件日志器
    auto file_logger = spdlog::basic_logger_mt("file_logger", "logs/log.txt");
    file_logger->info("Logging to a file");

    // 动态修改全局日志级别
    spdlog::set_level(spdlog::level::debug);
    console->debug("This is a debug message");

    spdlog::shutdown(); // 优雅关闭所有日志器
    return 0;
}
```

## 适用场景

- **高性能服务端程序**：如网络服务器、游戏服务器、消息队列等，需要在不影响主流程的前提下记录海量日志。
- **桌面应用与工具开发**：提供清晰的运行日志，便于调试和问题追踪，同时保持应用的启动速度和响应性。
- **嵌入式系统**：支持交叉编译，资源占用可控，适用于资源受限的嵌入式环境。
- **微服务与分布式系统**：异步日志记录能够降低 I/O 阻塞风险，配合日志采集工具实现集中式日志管理。
