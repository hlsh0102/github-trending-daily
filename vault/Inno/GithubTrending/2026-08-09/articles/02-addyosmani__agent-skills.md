## 项目概述

Agent Skills 是一个面向 AI 编码代理的生产级工程技能库，由 Google Chrome 团队工程经理 Addy Osmani 开发并开源。该项目将资深软件工程师在开发过程中使用的工作流程、质量门禁和最佳实践进行编码，打包成 AI 代理可以遵循的标准化技能。其核心目标是为 AI 编码代理提供一套与人类高级工程师一致的开发方法论，确保 AI 生成代码的质量和流程符合生产级软件的标准。

该项目的目标用户包括：使用 AI 辅助编码工具的软件工程师、需要为团队制定 AI 开发规范的工程管理者、以及 AI 编码工具的开发者和研究者。

## 核心功能

- **八个开发生命周期命令**：提供 `/spec`、`/plan`、`/build`、`/test`、`/review`、`/ship` 等 8 个斜杠命令，分别对应需求定义、方案规划、增量构建、测试验证、审查门禁和发布上线等开发阶段。
- **自动技能激活**：每个斜杠命令会自动激活相应阶段所需的技能集，无需手动切换或配置。
- **规范先行原则**：通过 `/spec` 命令强制在编码前完成需求规格和 PRD 的编写，避免"先写码再想需求"的反模式。
- **原子任务拆分**：`/plan` 命令将复杂任务拆解为小而原子化的子任务，降低实现复杂度和出错概率。
- **增量构建策略**：`/build` 命令强调一次只交付一个垂直切片，确保每步都可验证、可回滚。
- **测试即证明**：`/test` 命令将测试编写视为实现正确性的证明，而非可选的附加工作。

## 技术架构

Agent Skills 采用分层设计的架构思想。底层是经过编码的技能定义，包含质量门禁、工作流规则和最佳实践；中间层是命令分发机制，将 8 个斜杠命令映射到对应的技能集；顶层是与 AI 代理交互的接口层。

项目全量使用 JavaScript 编写，体现了轻量化、无依赖的设计理念。技能定义采用结构化的 Markdown 和 YAML 格式，便于 AI 代理理解和执行。生命周期流程设计上，Agent Skills 将软件开发划分为 DEFINE → PLAN → BUILD → VERIFY → REVIEW → SHIP 六个阶段，每个阶段都有明确的输入输出和验收标准，形成了完整的闭环。

一个值得注意的设计特点是其"命令即工作流"模式。用户输入简短的斜杠命令，系统自动展开为完整的技能链，这降低了使用门槛，同时保证了执行的标准化。

## 安装与使用

由于 Agent Skills 主要面向 AI 编码代理，安装方式取决于所使用的代理平台。以 Claude Code、Cursor 等支持技能导入的代理为例：

**安装步骤：**

1. 克隆或下载仓库到本地工作区：
```bash
git clone https://github.com/addyosmani/agent-skills.git
```

2. 将技能目录放置到 AI 代理可访问的路径（通常为项目根目录下的 `.agent/skills` 或代理配置中指定的目录）。

3. 根据代理工具的文档，在配置中启用技能加载。

**最小使用示例：**

在支持的 AI 代理对话中，直接输入斜杠命令：

```
/spec "实现用户登录功能"
```

代理会自动激活规格定义技能，引导完成 PRD 编写；随后继续使用：

```
/plan
/build
/test
```

逐步推动开发流程。如果代理环境不支持自动发现命令，也可以直接引用仓库中的技能文件，将相应 Markdown 内容粘贴到对话中触发对应技能。

## 适用场景

- **AI 辅助的项目初始化**：在项目启动阶段使用 `/spec` 和 `/plan`，确保 AI 代理在编码前明确需求范围和实现路径，减少返工。
- **自动化代码审查门禁**：在 CI/CD 流水线中引入 `/review` 命令，让 AI 代理按照资深工程师的标准在合并前进行质量审查。
- **团队 AI 开发规范统一**：工程团队可以将此仓库作为基准，定制自己的技能集，确保所有成员使用 AI 代理时遵循一致的开发流程。
- **教育与培训**：作为 AI 时代软件工程教学资源，展示资深工程师的思维框架和质量标准。

## 项目亮点

Agent Skills 最大的差异化优势在于它并非简单的提示词集合，而是系统化的工程方法论编码。它将"规范先行""小步快跑""测试即证明"等原则转化为 AI 代理可强制执行的工作流和门禁，而非依赖模型的自觉性。

其次，项目的生命周期六阶段模型具有极强的通用性，适用于各种规模和类型的软件项目。命令设计简洁直观，学习成本低，且与现有 AI 编码工具天然兼容。截至 2025 年底，该项目在 GitHub 上已获得超过 8 万颗星标，日增约 800 颗，反映了开发者社区对 AI 辅助工程化方法论的强烈需求。

此外，MIT 许可证允许自由使用和修改，团队可以轻松定制适应自身流程的技能集，而不是被工具厂商的固定工作流所绑定。
