## 项目概述

OpenCodeReview 是阿里巴巴开源的一款代码审查工具，旨在将自动化代码审查集成到日常开发流程中。它解决的核心问题是：传统静态分析工具规则固定、误报率高，而纯大模型审查又存在成本高、结果不稳定、难以定位到具体代码行等缺陷。OpenCodeReview 通过“确定性流水线 + LLM Agent”的混合架构，在保留规则引擎精确性与可复现性的同时，借助大模型补充语义层面的判断能力。

该项目由阿里巴巴内部经过大规模工程实践打磨后开源，采用 Go 语言编写，遵循 Apache-2.0 协议。其目标用户包括：需要为团队搭建自动化 Code Review 流程的研发工程师、关注代码质量与安全合规的技术负责人，以及希望把审查能力接入 CI/CD 或自建平台的平台工程团队。

## 核心功能

- **混合审查引擎**：将确定性的规则流水线与 LLM Agent 结合，规则负责可枚举、可验证的缺陷模式，Agent 负责需要上下文推理的语义问题，二者结果统一输出。
- **行级精确评论**：审查结果可定位到具体的文件与代码行，便于在 Pull Request 或本地直接查看和修复，而非仅给出笼统的整文件建议。
- **内置多语言规则集**：覆盖空指针引用（NPE）、线程安全、XSS、SQL 注入等常见缺陷类别，开箱即用，无需从零编写规则。
- **多模型兼容**：支持 OpenAI 与 Anthropic 兼容的接口协议，可对接公有云模型服务或自建推理端点，便于按团队合规要求选择模型。
- **多入口接入**：提供 npm 包与命令行方式，方便在本地开发、CI 流水线或自建平台中调用。

## 技术架构

项目主体使用 Go 实现，这一选择使其在单机执行和 CI 环境中具备较低的运行时开销与较好的分发便利性。架构上的关键设计是**分层解耦**：底层是确定性的分析流水线，负责词法/语法层面的规则匹配与缺陷识别，输出结构化、可复现的结果；上层是 LLM Agent，接收流水线提供的上下文（如变更片段、相关代码、规则命中信息）后进行推理，补充规则难以覆盖的判断。

这种设计的意图在于控制成本与稳定性：并非所有代码都需要送入大模型，规则能够确定的缺陷直接产出，只有需要语义理解的部分才触发 Agent 调用，从而减少 token 消耗并降低结果波动。同时，由于规则层输出是确定的，同一份代码在不同时间、不同模型下的基础结论保持一致，便于在团队内建立可信的审查基线。模型接入层抽象为 OpenAI / Anthropic 兼容协议，因此模型替换不影响上层流程。

## 安装与使用

项目提供 npm 分发方式，适合已有 Node.js 环境的团队：

```bash
npm install -g @alibaba-group/open-code-review
```

安装后可通过命令行对目标代码目录执行审查，并按需配置所使用的模型服务地址与密钥（具体参数以仓库文档为准，通常通过环境变量或配置文件注入 OpenAI / Anthropic 兼容端点）。

若希望从源码构建，可克隆仓库后使用 Go 工具链编译：

```bash
git clone https://github.com/alibaba/open-code-review.git
cd open-code-review
go build ./...
```

最小可用流程为：配置模型端点 → 指定待审查的代码路径或变更范围 → 执行审查命令 → 读取行级评论结果。在 CI 场景中，可将该命令挂载到 Pull Request 触发的工作流里，实现提交即审查。

## 适用场景

- **Pull Request 自动化审查**：在代码合并前自动产出评论，拦截空指针、注入类等高危问题。
- **本地开发自检**：开发者提交前运行一次审查，减少进入评审环节的低级缺陷。
- **存量代码质量扫描**：对历史代码库批量运行，识别安全隐患与技术债分布。
- **自建研发平台集成**：通过命令行或包接口嵌入企业内部的代码托管与流水线系统。

## 项目亮点

与纯静态分析工具相比，OpenCodeReview 的差异化在于引入 LLM 处理需要语义推理的审查项，同时用确定性流水线约束成本与结果稳定性；与纯 LLM 审查方案相比，它的行级定位能力和内置多语言规则集使其结论更具体、更易落地。此外，“经过阿里大规模工程实践验证”意味着其规则集与流程设计来源于真实业务场景，而非实验室环境。项目以 Go 编写、支持 OpenAI 与 Anthropic 兼容接口，在部署成本与模型选型灵活性上对团队较为友好。
