## 项目概述

VoiceStudio 是一个完全本地运行的开源语音与音频处理平台，定位为 ElevenLabs 的自托管替代方案。它把语音克隆、语音设计、视频配音、听写、转录和有声书制作整合到同一套界面与 API 中，支持 646 种语言的语音合成与识别。项目前身名为 OmniVoice-Studio，采用 Python 为主要开发语言，以 AGPL-3.0 协议开源。

其核心目标是解决云端语音服务在隐私、成本和使用配额上的限制。在本地工作流下，VoiceStudio 不需要账号注册、API Key、订阅付费或用量计费，音频数据与克隆出的声纹模型都保留在用户自己的硬件上。目标用户包括对数据合规有要求的企业与机构、需要长期批量生成音频的内容创作者、研究者，以及希望把语音能力集成进自有系统的开发者。项目支持 macOS、Windows、Linux 以及 Docker 部署，桌面端目前正在向 Electron 重写。

## 核心功能

- **语音克隆**：基于少量参考音频复现目标音色，用于个性化配音或角色语音。
- **语音设计**：通过参数或描述性输入生成新的音色，无需现成录音样本。
- **视频配音**：识别视频中的语音内容并替换为其他语言或音色，保留时间轴对齐。
- **听写与转录**：将音频或视频转写为文本，用于会议记录、字幕生成等。
- **有声书制作**：面向长文本的批量合成，输出适合长时播放的音频内容。
- **多引擎调度**：内置 16 个 TTS 引擎和 11 个 ASR 引擎，可按语言、质量和硬件条件切换。

## 技术架构

VoiceStudio 在架构上采用“引擎抽象层 + 统一接口”的设计思路。16 个 TTS 引擎与 11 个 ASR 引擎被封装为可插拔的适配器，上层功能（克隆、配音、转录等）通过统一的任务管线调用它们，从而避免与某一具体模型深度耦合。用户可以在不同语言与硬件条件下选择更合适的后端。

服务层以 Python 实现，对外提供 API，前端与桌面应用通过该 API 交互，因此本地工作流与自动化脚本可以复用同一套能力。语言覆盖方面，项目维护了 646 种语言的目录，用于匹配各引擎的实际支持范围。部署形态覆盖桌面端与 Docker，既支持个人单机使用，也支持在服务器或容器环境中集中运行。由于推理在本地执行，实际性能与可用引擎取决于显卡显存和内存等硬件条件。

## 安装与使用

项目提供 macOS、Windows、Linux 与 Docker 多种安装路径，官方 README 中的 Install 章节给出了分平台的详细步骤，同时也提供简体中文文档（README_CN.md）。一般流程为：

1. 按官方说明克隆仓库并安装 Python 依赖。
2. 根据硬件情况下载所需 TTS/ASR 模型权重。
3. 启动本地服务，通过浏览器界面或 API 访问功能。

最小可用示例（以转录为例，具体命令以官方文档为准）：

```bash
# 启动本地服务后，调用转录接口
curl -X POST http://localhost:8000/transcribe \
  -F "file=@sample.wav"
```

语音克隆通常需要上传一段参考音频，再输入待合成文本；视频配音则上传视频文件并指定目标语言或音色。所有处理默认在本地完成，不经过外部服务。

## 适用场景

- **隐私敏感的语音处理**：法律、医疗、金融等场景中，音频不便上传到第三方云服务。
- **批量内容生产**：播客、有声书、多语言视频配音等需要长时间、大批量生成音频的工作。
- **离线或受限网络环境**：在没有稳定外网连接的设备上仍可使用转录与合成能力。
- **开发者集成**：通过本地 API 把转录、克隆能力接入自有应用或自动化流水线。

## 项目亮点

与多数依赖云端 API 的同类方案相比，VoiceStudio 的主要差异在于完全本地化和零账户门槛：不需要账号、密钥、订阅或用量计量。它同时集成了语音克隆、语音设计、视频配音、听写、转录和有声书六类功能，并可在 16 个 TTS 引擎与 11 个 ASR 引擎之间灵活切换，配合 646 种语言的目录覆盖，避免了单一模型在语种和质量上的局限。跨平台与 Docker 支持也让同一套能力可以覆盖个人桌面和服务器部署。需要说明的是，桌面端正处于 Electron 重写阶段，项目维护者已提示暂不要提交与桌面应用相关的 issue 和 PR。
