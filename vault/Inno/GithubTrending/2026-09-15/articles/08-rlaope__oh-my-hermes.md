## 项目概述

oh-my-hermes 是面向 Hermes Agent（由 NousResearch 开发的编码智能体）的一体化插件。Hermes Agent 本身提供了基础的智能体执行能力，但在长期项目协作中往往会遇到上下文丢失、任务规划松散、模型调用不经济等问题。oh-my-hermes 的目标是在不替换 Hermes Agent 的前提下，为其叠加一层更贴近真实工程场景的“操作层”，让规划、调研、创作、编码交接、运维操作与项目记忆能够被统一组织，并明确区分哪些结论有证据支撑、哪些属于推测。

该项目主要面向长期使用 Hermes Agent 进行开发的工程师与团队，尤其是需要在多轮会话中保持项目上下文一致性、希望复用一套经过调优的工作流与模型配置的用户。

## 核心功能

- **长期记忆系统**：跨会话保存项目相关的决策、约定与背景信息，减少重复说明与上下文重建成本。
- **编码智能层**：将任务拆解、代码交接与验证步骤串联成可追踪的流程，降低智能体“凭空发挥”的概率。
- **模型优化工作流包**：为不同任务类型预置模型与参数组合，在效果与成本之间提供可调整的默认方案。
- **证据边界标注**：在输出中区分已验证事实与推断内容，便于使用者判断结论的可信度。
- **多语言文档支持**：仓库提供英文、韩文、日文与中文 README，降低非英语用户的上手门槛。

## 技术架构

项目以 Python 为主要实现语言，整体设计遵循“插件而非分叉”的思路：不修改 Hermes Agent 的核心代码，而是通过其扩展机制注入额外能力。这种做法的好处是升级 Hermes Agent 时不会与插件产生冲突，用户始终保留上游版本。

在结构上，项目大致分为三个层次。底层是记忆存储与检索模块，负责持久化项目级信息；中间层是工作流编排，将规划、调研、编码等任务映射为可复用的步骤序列；上层是面向使用者的命令与配置入口，包括模型优化包的加载与切换。证据边界机制贯穿各层，用于在生成结果时标注信息来源与置信度。

## 安装与使用

由于仓库未在 README 摘要中给出完整的安装指令，以下为基于常见 Python 插件项目的通用流程概述：

1. 确认已安装 Hermes Agent 及对应的 Python 运行环境。
2. 从 GitHub 克隆仓库或通过 pip 安装包。
3. 在 Hermes Agent 的配置中启用 oh-my-hermes 插件。
4. 初始化项目记忆目录，并按需选择工作流包。

最小可用示例通常包括：在项目根目录启动一次初始化命令，随后在 Hermes 会话中直接调用插件提供的命令来创建任务、记录决策或触发编码工作流。具体命令名称与参数请以仓库 README 和文档为准。

## 适用场景

- **长期维护的中大型代码库**：需要智能体记住架构约定与历史决策，避免每次会话重新解释背景。
- **多步骤研发任务**：从调研、方案设计到编码交接的完整链条，希望流程可追踪、可复用。
- **成本敏感的个人开发者**：希望通过模型优化包在保证效果的前提下控制调用开销。
- **需要证据可追溯的团队协作**：要求智能体输出标注信息来源，便于评审与复核。

## 项目亮点

与单纯的提示词集合或独立智能体框架相比，oh-my-hermes 的差异化在于“叠加而非替代”。它保留 Hermes Agent 的原有能力与升级路径，同时补齐长期记忆与工作流编排这两块在真实项目中容易缺失的部分。2249 颗星标与持续增长的关注度，也从侧面反映了这类“操作层”需求的存在。明确的证据边界设计，使其在需要严谨性的工程场景中比通用智能体更容易被接受。
