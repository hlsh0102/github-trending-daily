## 项目概述

OpenCodeReview 是阿里巴巴开源的一款代码审查工具，采用确定性流水线与 LLM Agent 相结合的混合架构。它主要解决传统代码审查中两类常见问题：一是纯静态规则引擎虽然稳定、可复现，但难以理解上下文语义；二是纯大模型审查虽然灵活，却容易产生幻觉、注释定位不精确、结果不可控。OpenCodeReview 通过将两者拆分协作，在保证审查结果稳定性的同时引入语义理解能力。

项目使用 Go 语言开发，已在阿里巴巴内部经过大规模工程实践验证，具备较高的性能和并发处理能力。其目标用户包括：需要为团队搭建自动化代码审查流程的研发团队、希望在 CI/CD 中嵌入静态检查的工程效能人员，以及关注 AI 辅助研发工具的开发者。工具内置多语言规则集，覆盖空指针异常（NPE）、线程安全、XSS、SQL 注入等常见缺陷类型，并兼容 OpenAI 与 Anthropic 两类主流大模型接口。

## 核心功能

- **混合审查架构**：确定性流水线负责语法与规则层面的检测，LLM Agent 负责语义与上下文相关的判断，两者结果合并输出，兼顾稳定性与覆盖面。
- **精确到行的评论定位**：审查结论直接映射到代码的具体行，便于在 Pull Request 或本地文件中直接查看问题位置，减少人工二次定位成本。
- **内置多语言规则集**：开箱提供针对空指针异常、线程安全问题、XSS、SQL 注入等典型缺陷的检测规则，覆盖多种主流编程语言。
- **多模型兼容**：支持 OpenAI 与 Anthropic 兼容接口，可接入自建或第三方模型服务，便于在数据合规与成本之间做取舍。
- **命令行与集成能力**：以 CLI 方式运行，可通过 npm 分发安装，便于嵌入本地开发流程或持续集成流水线。

## 技术架构

项目核心采用 Go 编写，这一选择使其在解析大型仓库、并发处理多个文件时具备较好的性能表现。架构上分为两个主要层次：

第一层是确定性流水线。该层承担规则匹配与静态分析职责，输入为代码文本或文件集合，输出为结构化的问题列表。由于不依赖模型推理，这一层的结果具备可复现性，适合作为审查基线。

第二层是 LLM Agent。该层在需要语义理解、跨文件推理或规则难以覆盖的场景中介入，通过对代码上下文的分析给出补充意见。Agent 的输出同样被规范化为结构化结果，并与确定性层的输出进行合并、去重和排序。

两层之间通过明确的接口约定协作，避免相互耦合。这种设计使得团队可以按需启用或禁用某一层：在成本敏感或模型不可用的环境中，仅运行确定性流水线即可获得基础审查能力；在需要更深入分析时再引入 LLM。此外，项目对模型接口做了抽象，通过兼容 OpenAI 与 Anthropic 协议的方式降低对特定供应商的绑定。

## 安装与使用

项目通过 npm 发布，可使用包管理器全局安装：

```bash
npm install -g @alibaba-group/open-code-review
```

安装完成后，可通过命令行对目标文件或目录发起审查。基本调用形式如下：

```bash
open-code-review --path ./src
```

如需启用 LLM Agent 能力，需配置相应的模型服务信息（例如 API Key 与接口地址），具体参数因所用模型提供方而异。对于仅需静态规则检查的场景，可不配置模型直接运行，以降低使用门槛和调用成本。

在持续集成环境中，可将该命令作为独立步骤嵌入流水线，对变更文件或全量代码执行审查，并将结果输出到日志或评论系统中。

## 适用场景

- **Pull Request 自动审查**：在代码合并前自动运行，将问题定位到具体行，辅助评审人快速识别潜在缺陷。
- **CI/CD 质量门禁**：作为流水线中的检查环节，对空指针、SQL 注入等高危问题设置拦截规则。
- **本地开发自查**：开发者提交前在本地运行，提前发现规则可覆盖的常见问题，减少往返评审次数。
- **AI 辅助研发工具集成**：借助其多模型兼容特性，作为上层研发平台中的代码分析能力组件。

## 项目亮点

与同类工具相比，OpenCodeReview 的差异化主要体现在三点。其一，混合架构在"可控"与"智能"之间做了明确分工，既避免了纯 LLM 方案的结果漂移，也弥补了纯规则引擎的语义盲区。其二，行级评论定位使审查结果可直接落地到代码上下文，而非停留在笼统的建议层面。其三，项目背靠阿里巴巴内部的大规模实践，规则集与工程细节经过真实业务场景打磨，具备较强的实用性。此外，采用 Apache-2.0 许可证，便于企业在其基础上做二次开发与集成。
