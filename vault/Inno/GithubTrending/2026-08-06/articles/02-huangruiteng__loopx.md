## 项目概述

LoopX 是一个面向长时间运行 AI Agent 团队的轻量级循环工程状态内核。在当下的 AI 编程实践中，单个 Agent 可以在一次会话内完成一个明确的子任务，但当工作跨越多个会话、多个工具、甚至多个不同的 Agent 时，目标漂移、上下文丢失、证据过期和重复开销便成为常态。LoopX 以“本地控制平面”的定位介入这一环节，在不替代任何 Agent 运行时（如 Codex、Claude Code、Cursor）的前提下，为长周期 Agent 工作提供持久化的目标、门禁、待办、证据、配额与交接管理。

项目的核心哲学是“保持循环运转，保持判断在人类手中”。LoopX 的目标用户包括：依赖 AI 编程代理进行多轮迭代开发的工程师、需要多 Agent 协作完成复杂任务的团队，以及在自动化程度不断提高的前提下依然希望保留人工复核节点的技术管理者。

## 核心功能

- **持久化目标（Durable Goals）**：将目标从一次性会话中解耦，跨会话、跨 Agent 保持目标稳定，避免每次重启后重新解释上下文。
- **配额感知的自动唤醒（Quota-Aware Auto-Wake）**：当配额（如 API 消耗额度）允许时，自动唤醒处于暂停状态的循环，继续未完成的工作，杜绝无谓的持续消耗。
- **可执行待办（Executable Todos）**：将目标拆解为粒度适中的待办项，每个待办可直接绑定到具体的 Agent 调用，形成可追踪的执行链。
- **证据日志（Evidence Logs）**：每一步的执行结果、产出物和验证信息自动记录，为后续审计和对齐提供不可篡改的参考。
- **可验证交接（Verifiable Handoffs）**：Agent 之间、人与 Agent 之间的工作交接附带可验证的状态和上下文，避免“翻烧饼”式的重复劳动。
- **引擎无关（Agent-Loop Agnostic）**：不绑定任何特定 Agent 产品，Codex、Claude Code、Cursor 均可接入，未来也可以接入自研运行时。

## 技术架构

LoopX 采用 Python 实现，定位为本地运行的控制平面，而非云服务或插件体系。从架构设计上看，它包含以下几个关键层次：

- **状态核心（State Kernel）**：以文件或轻量数据库的形式持久化循环状态，包括当前目标、待办列表、证据链、配额余量以及交接记录。所有状态在重启后保持完整。
- **调度与唤醒模块**：监控配额消耗和任务进度，在条件允许时主动唤醒循环，推进待办项，并在配额不足时优雅降级。
- **适配层（Adapter Layer）**：通过 CLI 包装或 API 接口与不同 Agent 运行时通信，将通用目标翻译成具体 Agent 可执行的指令，同时回收执行结果作为新的证据。
- **验证与审计接口**：每一次交接和证据记录都带有校验信息，确保人和 Agent 都能验证状态的真实性和时效性。

这种架构的显著特点是松耦合：Agent 运行时只是执行器，LoopX 才是状态的管理者。即使 Agent 本身崩溃或更换品牌，循环的状态也不会丢失。

## 安装与使用

LoopX 以 Python 包的形式分发，可以通过 pip 安装：

```bash
pip install loopx
```

初始化一个新的循环工作区：

```bash
loopx init my-project
cd my-project
```

定义目标并启动循环：

```bash
loopx goal "重构认证模块并补充集成测试"
loopx run --agent-codex --max-turns 20
```

在运行过程中，LoopX 会把执行进度、证据日志和当前待办持久化到本地。中断后重新唤醒：

```bash
loopx status        # 查看循环状态
loopx resume        # 继续之前的循环
```

对于更精细的控制，可以在配置文件中指定配额上限、目标 Agent 品牌、交接策略等参数。最小可用的示例仅需以上三个命令，即可完成一次受控的多轮 Agent 执行。

## 适用场景

- **多轮代码重构**：跨多个会话完成大型模块的重构，期间穿插人工审查和决策，LoopX 负责保持上下文和目标连续性。
- **多 Agent 协作开发**：需求分析、代码生成、测试修复分别由不同的 Agent 完成，LoopX 的交接机制确保每个环节都清晰可验证。
- **限额受控的自动化迭代**：对 API 调用费用敏感的场景下，通过配额感知的唤醒机制控制预算，在额度用尽时自动暂停，待补充后继续。
- **可复盘的生产巡检**：对长周期运行中的变更进行证据留存，事后可以完整回溯哪些步骤由哪个 Agent 做了什么事、产出什么结果。

## 项目亮点

LoopX 与同类方案（如简单的任务管理工具或 Agent 内置的上下文机制）相比，差异化优势明显：

- **引擎无关性是第一原则**：不像某些工具深度绑定特定 Agent 产品，LoopX 的设计让用户保留 Agent 选择自由，并且可以混合使用多个 Agent。
- **状态先于执行**：把目标、待办、证据作为一等公民管理，而不是依赖 Agent 自身的有限上下文窗口，从根本上解决长任务中的记忆丢失问题。
- **人性化控制点**：在自动循环中嵌入人工可干预的门禁，确保重要的判断节点由人决定，避免全自动流程的失控风险。
- **完备的交接验证**：交接不是简单的“粘贴上下文”，而是携带验证信息的结构化状态，接收方无需猜测前序工作的完成度。
- **轻量本地化**：不需要部署服务端、不需要云数据库，本地即可运行，对隐私和合规要求高的团队尤为友好。
