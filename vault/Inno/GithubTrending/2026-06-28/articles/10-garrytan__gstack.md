## 项目概述

**gstack** 是由 Y Combinator 现任总裁兼 CEO Garry Tan 个人开发并开源的一套 Claude Code 工具集。该项目旨在将一位拥有二十年经验的创始人兼工程师的“AI 原生”工作流系统化，让任何开发者都能复用这套经过实战验证的 23 个工具，以 CEO、设计师、工程经理、发布经理、文档工程师和 QA 等多重角色协作的方式，实现“一人成军”的软件交付效率。

项目的核心驱动力来自于 Andrej Karpathy 在 2026 年 3 月的一次公开分享：他自去年 12 月以来几乎没有手写一行代码，却依然保持了极高的产出。Garry Tan 受此启发，将自己过去六十天内的实践——在 full-time 管理 YC 的同时，以 part-time 方式交付了 3 个生产服务和 40+ 功能——抽象成这套可复制的工具链。根据公开数据，Garry 2026 年的逻辑变更速率已达到 2013 年的约 810 倍，仅 2026 年前四个月的产出就超过了 2013 年全年的 240 倍。

gstack 的目标用户是所有希望借助 AI 代理（AI Agent）实现高效个人开发的技术人员，尤其是独立开发者、小团队创始人以及希望在组织内部推广“AI 原生”工作模式的工程师。

## 核心功能

- **23 个高度特化的工具**：覆盖从高层战略到执行细节的完整链路，包括 CEO 视角的决策分析、工程经理视角的任务拆解、设计视角的 UI/UX 评审、QA 视角的自动化测试生成、文档工程师的写作与校对，以及发布经理的版本管理与环境部署。
- **Claude Code 原生集成**：所有工具均为 Claude Code 的 Tool Use 模式量身定制，可直接嵌入日常工作流，无需额外学习复杂框架。
- **可定制的角色模板**：每个工具都对应一个清晰的“角色”描述和结构化提示，用户可根据项目规模和阶段，灵活启用或禁用某一角色，或调整其行为参数。
- **全链路自动化**：从需求澄清、技术方案设计、代码生成、测试覆盖到文档输出和发布上线，整套流程在单一条 prompt 下即可驱动执行。
- **透明的可追溯性**：每个工具在执行过程中都会输出详细的思考过程和决策依据，便于用户审查、修改或回退。
- **极低的启动成本**：无需复杂的安装或配置，只需在 Claude Code 中加载对应工具定义即可立即使用。

## 技术架构

gstack 基于 **TypeScript** 开发，整体架构围绕“工具定义 + 提示模板”两大核心组件构建。每个工具本质上是一个结构化的 JSON 配置文件，包含工具名称、描述、输入参数 schema 和触发条件。Claude Code 的 Agent 会自动根据对话上下文选择合适的工具进行调用。

项目遵循“小而专”的设计哲学：没有过度封装，不依赖复杂的中间件或运行时。每个工具只做一件事，并将这件事做到极致。例如，`ceo-review` 工具只负责从商业价值、风险平衡、资源投入等维度对功能需求提出质疑与建议；`qa-generate` 工具则纯粹关注测试用例的覆盖率和边界条件。

架构上，gstack 并未将工具与任何特定 CI/CD 系统或云服务深度绑定，而是保持了对标准开发工作流的兼容性——用户可以在本地终端、远程开发环境甚至 Docker 容器中运行 Claude Code，然后按需加载 gstack 工具集。这种松耦合设计降低了维护成本，也方便用户将 gstack 与其他工具（如 GitHub Actions、VS Code 插件等）集成。

## 安装与使用

gstack 的安装极为简单，核心依赖只有 Claude Code（需要确保你的 Claude Code 版本支持 Tool Use 模式）。

1. 克隆仓库到本地：
   ```bash
   git clone https://github.com/garrytan/gstack.git
   cd gstack
   ```

2. 安装依赖（如有需要）：
   ```bash
   npm install
   ```

3. 启动 Claude Code 并加载工具集：
   ```bash
   claude-code --tools ./gstack-tools.json
   ```

4. 或者，在 Claude Code 会话中直接引入所有工具：
   ```
   请加载 gstack 工具集，路径为 ./gstack-tools.json。然后，以“CEO”角色对以下需求进行评审：...
   ```

一个最小可用示例如下：
- 你想为现有项目添加一个新功能。你可以用一条 prompt 启用 `ceo-review` 工具对需求进行评审，然后启用 `eng-manager-plan` 工具将评审通过的需求拆解为可执行的开发任务。
- 完成开发后，使用 `qa-generate` 生成单元测试，用 `doc-engineer` 更新 README 和 API 文档，最后用 `release-manager` 执行发布流程。

整个过程只需要在一个 Claude Code 会话中完成，无需切换多个工具或界面。

## 适用场景

- **从零到一的 MVP 开发**：创业者或 side project 作者可以通过 gstack 模拟小型创业团队的协作流程，在缺乏实际团队成员的情况下快速将想法转化为可交付的产品。
- **大型项目的独立维护**：对于已经有一定代码库规模、但难以组建完整团队的个人开发者，gstack 可以帮助你精准定位变更影响范围，生成全面的回归测试，并自动生成发布说明，从而降低维护风险。
- **远程或异步工作模式的补充**：在跨时区团队中，gstack 可作为“24 小时待命的虚拟队友”，在团队休息期间完成代码检查、文档更新或测试补充工作。

## 项目亮点

gstack 与同类项目（如 Devin、Cursor Agent 或自定义的 AI 工作流）相比，最显著的差异化优势在于**创始人的实战基因**。它不是由一个 AI 工具公司或研究团队从理论出发设计的，而是 Garry Tan 本人过去二十年创业经验与最近几个月高强度 shippping 实践的结晶。23 个工具的角色分工直接映射了真实创业团队中不同职能的思考方式和决策逻辑。

其次，gstack 保持了**极高的可理解性与可控性**。每个工具定义清晰、职责单一，用户可以在几分钟内理解整套工具体系并开始定制。相比之下，许多全自动化的 AI 开发平台往往像黑盒一样遮蔽了过程，而 gstack 则鼓励用户参与每一个关键决策节点。

最后，gstack 的**后发优势**在于它借鉴了包括 OpenClaw 在内多个领先 AI 原生开发项目的实践，并结合了 YC 生态中数千个 startups 的共性需求。这套工具集在诞生时就经过了“一人团队”这一极限场景的测试，而非仅仅作为学术演示或实验性项目。
