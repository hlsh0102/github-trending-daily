## 项目概述

DESIGN.md 是一个专门为编码代理（coding agents）设计的设计系统描述格式规范。在 AI 辅助开发日益普及的今天，编码代理对项目的视觉语言缺乏结构化的理解，往往只能通过零散的 CSS 变量或临时提示来生成 UI，导致输出不一致、风格偏离。DESIGN.md 解决了这一核心问题：它提供了一种标准化的方式，让开发者能以机器可读且人类可理解的格式，将完整的视觉身份一次性交付给编码代理。

目标用户包括：使用 AI 编码工具进行前端开发的工程师、设计系统维护者、产品团队中负责规范 AI 生成 UI 一致性的成员，以及任何希望让 LLM 驱动的编码代理理解并严格遵循特定视觉语言的开发者。

## 核心功能

- **结构化设计标记**：通过 YAML Front Matter 定义精确的设计令牌，包括颜色、字体、间距、圆角等数值，确保代理获得无歧义的设计值。
- **人性化设计文案**：支持 Markdown 正文描述设计理念、色彩含义、使用场景等上下文信息，帮助代理理解“为什么这样设计”以及“如何应用”。
- **分离关注点**：将机器精确值（YAML）与人类设计意图（Markdown）清晰分离，兼顾技术精度与语义理解。
- **零依赖规范**：仅需一个 DESIGN.md 文件即可工作，无需安装额外工具或插件，与任何项目结构兼容。
- **跨代理可移植**：遵循通用 Markdown 和 YAML 标准，理论上可以被所有支持文件上下文读取的编码代理理解和使用。

## 技术架构

DESIGN.md 的技术设计极为简洁，核心是一个定义清晰的 YAML+Markdown 复合文件格式。
- **YAML Front Matter** 位于文件顶部，用于定义精确的、可量化的设计令牌（design tokens）。这些令牌覆盖了设计系统中最常用的 CSS 属性：颜色系统（支持语义命名如 primary、secondary、tertiary、neutral）、排版系统（支持层级如 h1、body、label，并定义 fontFamily、fontSize）、圆角系统（通过语义命名如 sm、md）以及间距系统（同样通过语义命名）。
- **Markdown 正文** 紧随其后，用于书写自然语言描述的设计决策和指南。这部分包括：设计系统概览、色调策略说明（如“高对比度中性色+单一强调色”）、徽记定义与间距规则等。
- **读取逻辑**：编码代理（如 Claude、GPT 等支持文件附件的 AI 工具）在读取这个文件时，会先解析 YAML 获得精确数值，再阅读 Markdown 理解设计上下文，从而能够根据设计意图生成出一致性极高的 UI 代码。

这种“精确数据 + 语义说明”的双层架构是 DESIGN.md 的核心技术特点，它使得代理既能执行精确的样式计算，也能进行符合设计价值观的决策。

## 安装与使用

DESIGN.md 是一个格式规范，无需安装任何工具。使用方式非常简单：

1. **创建文件**：在项目的根目录或设计系统目录下，创建一个名为 `DESIGN.md` 的文件。
2. **定义 YAML 标记**：在文件顶部使用 YAML Front Matter 定义你的设计令牌。推荐至少定义主色、正文字体、基础间距和圆角。
3. **撰写设计文案**：在 YAML 下方使用 Markdown 书写设计说明。包括设计系统名称、色彩策略指导、排版层级说明、适用场景等。
4. **引入代理**：当你使用支持文件上下文的编码代理时，将 `DESIGN.md` 文件的内容作为上下文提供给代理，或直接让代理读取该文件路径。

**最小可用示例**：上述 README 中给出的 Heritage 设计系统示例，即是一个可直接使用的完整范例。

## 适用场景

- **AI 辅助 UI 开发**：当使用编码代理生成组件或页面代码时，DESIGN.md 保证了输出的视觉风格与设计系统严格一致，避免“AI 胡乱配色”的问题。
- **团队设计系统维护**：设计团队可以将 DESIGN.md 作为设计系统的“可读规范”，既作文档，又作 AI 指令，减少开发与设计的沟通成本。
- **多项目设计复用**：将同一个 DESIGN.md 文件复制到多个项目中，即可让编码代理在所有项目中遵循完全相同的视觉语言。
- **原型与产品一致性**：在快速原型阶段使用编码代理生成 UI 时，DESIGN.md 确保即使迭代速度快，输出的界面仍然保持品牌一致性。

## 项目亮点

与传统的设计系统文档（如 Storybook、Figma 导出样式、CSS 变量集）相比，DESIGN.md 对编码代理的建立直接、高效的优势：
- **格式统一**：它可能是唯一一个专门为编码代理优化的设计系统描述格式，而不仅仅是给人阅读的设计文档。
- **无需处理环境**：不需要代理理解项目中的 CSS 文件结构、预处理器变量或 JavaScript 配置，只要读取一个文件即可。
- **精确与灵活并存**：YAML 保证精确数值，Markdown 保证语义理解，两者互补，在机器执行和人类理解之间取得平衡。
- **极低门槛**：无需学习复杂 DSL（领域特定语言），熟悉 Markdown 和 YAML 的开发者可以立即上手。
- **开源且广受认可**：Apache-2.0 许可，超过 22000 颗 Star，说明社区对其价值的高度认可。
