## 项目概述

OpenResearch 是由 alphaXiv 团队开发的一款本地优先（local-first）研究工作空间，其核心目标是“将编码智能体（coding agents）转化为科研智能体（research agents）”。当前主流的 AI 编程工具，如 Claude Code、Codex、OpenCode 和 Cursor，已经在代码生成、重构和调试等任务上展现出较强的能力，但这些工具的设计前提是“代码即产物”，并不天然适配学术研究的完整流程。OpenResearch 正是为弥补这一断层而出现：它在这些编码智能体之上构建了一层面向科研的工作流封装，使其能够完成文献综述、假设生成、实验执行和研究产物整理等任务。

项目的目标用户包括研究生、博士后、独立研究者以及任何希望通过智能体自动化方式推进研究进程的开发者。对于已经熟悉 Claude Code 或 Cursor 的用户，OpenResearch 提供了一条相对平滑的迁移路径——无需更换底层模型或工具链，只需替换工作空间即可进入科研场景。

## 核心功能

- **文献综述与检索**：智能体可以围绕给定主题检索和整理学术文献，形成结构化的综述材料，而不是简单地返回零散链接。
- **假设生成与迭代**：在已有文献和初步数据基础上，辅助研究者提炼可验证的假设，并在后续迭代中修正或推翻。
- **实验执行与记录**：把编码智能体的执行能力延伸到实验脚本层面，运行、记录并复现实验过程。
- **研究产物输出**：将中间结果组织为可交付的研究产物，例如草稿、图表、带有引用关系的笔记。
- **多智能体后端支持**：兼容 Claude Code、Codex、OpenCode 与 Cursor，用户可沿用已有订阅或本地模型配置。
- **本地优先的数据管理**：研究数据默认存储在本地，减少对外部服务的依赖，便于在敏感课题中使用。

## 技术架构

项目主体使用 Rust 编写。选择 Rust 主要出于两点考虑：一是本地优先的定位要求程序在用户机器上长时间稳定运行，Rust 在内存安全和并发模型上的优势较为契合；二是桌面端与 CLI 共用同一套核心逻辑，可以减少跨语言调用带来的复杂度和性能损耗。

整体架构可以理解为三层：底层是智能体适配层，负责对接 Claude Code、Codex、OpenCode、Cursor 等外部工具，将它们统一抽象为可调用的“研究执行单元”；中间是研究工作流层，定义文献、假设、实验、产物之间的状态流转；上层是交互层，包括 macOS 桌面应用和 Windows CLI（Beta）两种入口。这种分层使得新增一个智能体后端或新增一类研究产物时，不需要改动整个系统。

本地优先的设计意味着项目不会强制将研究数据托管到云端，文件系统是主要的状态存储介质，适合对数据隐私或离线可用性有要求的场景。

## 安装与使用

macOS 用户可以直接下载官方发布的 `OpenResearch.dmg` 安装包，Windows 用户目前可使用处于 Beta 阶段的 CLI 压缩包（`openresearch-cli-x86_64-pc-windows-msvc.zip`）。由于项目使用 Rust 编写，具备 Rust 工具链的用户也可以从源码构建。

最小使用流程大致如下：

1. 安装并启动 OpenResearch。
2. 在配置中指定已有的编码智能体后端（例如本地已登录的 Claude Code 或 Cursor）。
3. 创建一个研究项目，输入研究主题或问题。
4. 通过工作空间界面或 CLI 指令，让智能体依次执行文献检索、假设整理、实验脚本运行等步骤。
5. 在工作空间中查看和导出生成的研究产物。

由于工具的定位是“工作空间”而非单一命令行工具，实际使用更接近在一个项目目录中持续推进研究，而非一次性问答。

## 适用场景

- **文献密集型课题的前期调研**：需要快速梳理某一方向的已有工作，并形成可追溯的综述框架。
- **计算类研究的实验迭代**：假设可以通过脚本验证，希望由智能体自动运行实验并记录结果。
- **已有编码智能体的科研化改造**：用户已付费使用 Claude Code 或 Cursor，希望在不更换工具的前提下进入研究流程。
- **对数据本地化有要求的研究**：课题涉及未公开数据或合作方限制，无法将材料上传至第三方云服务。

## 项目亮点

与通用的 AI 研究助手或纯云端方案相比，OpenResearch 的差异主要体现在三个方面。第一是定位上的“转换器”角色：它不重新训练模型，也不绑定某一家智能体，而是把已有的编码能力重新编排为科研流程，降低了用户的上手成本。第二是本地优先的数据模型，在学术场景中对隐私和可复现性更友好。第三是语言与架构选择上的工程一致性，Rust 保证了桌面端和 CLI 共用同一套核心，长期维护成本较低。

需要指出的是，项目目前仍处于较早期阶段，Windows 端为 Beta，功能边界和稳定性会随着版本迭代变化。其价值更多体现在“流程组织”而非“模型能力”上，适合作为研究流程的辅助工具，而非替代研究者的判断。
