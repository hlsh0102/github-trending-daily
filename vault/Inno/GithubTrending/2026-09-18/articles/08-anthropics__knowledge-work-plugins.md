## 项目概述

Knowledge Work Plugins 是 Anthropic 开源的一组插件集合，主要面向知识工作者，用于在 Claude Cowork 中扩展 Claude 的能力。Claude Cowork 本身允许用户设定目标后由 Claude 交付完整的专业成果，而插件机制则进一步回答了几个关键问题：工作应当以什么方式完成、从哪些工具和数据源获取信息、关键流程如何处理、以及对外暴露哪些斜杠命令。

每个插件围绕一个具体的岗位职能组织，将技能（skills）、连接器（connectors）、斜杠命令（slash commands）和子代理（sub-agents）打包在一起。开箱即用时，插件为该职能岗位提供一个较为完整的起点；而当团队根据自身工具、术语和流程进行定制后，Claude 才能更贴近团队真实的工作方式。目标用户包括产品、销售、工程、运营等各类知识工作者及其团队。

## 核心功能

- **按职能打包的插件体系**：每个插件对应一类岗位（如生产力、销售等），将技能、连接器、命令和子代理整合为一个可复用单元。
- **多工具连接器集成**：插件可对接 Slack、Notion、Asana、Linear、Jira、Monday、ClickUp、Microsoft 365、HubSpot、Close、Clay、ZoomInfo、Fireflies 等常用协作与业务系统。
- **斜杠命令与子代理**：通过暴露自定义斜杠命令和子代理，把高频工作流固化为可复用的操作入口。
- **可定制的团队工作流**：插件并非固定模板，团队可替换为自有工具、术语和流程，从而得到一致性更高的产出。
- **官方插件市场**：仓库开源了 11 个由 Anthropic 自身工作实践启发并构建的插件，可直接作为起点使用。
- **双产品兼容**：专为 Claude Cowork 设计，同时兼容 Claude Code，方便开发者在既有环境中复用。

## 技术架构

仓库以 Python 为主要实现语言，采用插件化的组织方式。每个岗位职能对应一个独立目录，目录内包含该插件所需的技能定义、连接器配置、斜杠命令以及子代理定义。技能层负责描述“如何完成某类工作”，连接器层负责与外部系统的数据交互，斜杠命令提供显式的用户触发入口，子代理则承担可拆分的复杂任务。

这种分层使插件既能以开箱即用的形态分发，也便于团队按组件替换——例如只替换连接器以接入公司内部系统，或只调整技能描述以匹配内部术语。插件之间相互独立，可按需安装和启用。项目采用 Apache-2.0 许可证，允许商业使用与修改。

## 安装与使用

仓库未在 README 摘要中提供完整安装细节，以下为基于 Claude 插件常见接入方式的概述：

1. 克隆或下载仓库到本地：
   ```
   git clone https://github.com/anthropics/knowledge-work-plugins.git
   ```
2. 在 Claude Cowork（或 Claude Code）中加载所需插件目录。通常情况下，插件目录包含清单文件，客户端会据此识别技能、连接器与命令。
3. 根据提示完成连接器的授权配置，使插件能访问 Slack、Jira、Notion 等外部系统。
4. 在会话中通过斜杠命令触发对应工作流，或直接让 Claude 使用该插件的技能完成目标。

最小可用示例：假设已加载 `productivity` 插件并连接 Slack 与 Notion，用户可直接要求 Claude 汇总当日任务、整理会议记录并同步到 Notion 页面，Claude 会调用插件中定义的工具与命令完成操作。具体命令名称与配置字段建议以各插件目录内的说明文件为准。

## 适用场景

- **个人日常效率管理**：整合任务、日历与个人上下文，减少重复交代背景信息的时间。
- **销售流程支持**：调研潜在客户、准备通话、审阅销售管道、起草外联内容并构建竞品对比资料。
- **跨工具协同工作流**：在 Slack、Jira、Notion 等多个系统间自动流转信息，减少手工搬运。
- **团队标准化作业**：把团队的术语、流程和工具偏好固化进插件，使不同成员获得一致的产出质量。

## 项目亮点

与通用的提示词模板或单一工具集成方案相比，该项目的差异点在于将岗位职能作为一等公民进行封装。插件不是零散的功能点，而是围绕“某个角色如何工作”整体设计的组件集合，技能、连接器、命令与子代理彼此配合。

此外，项目由 Anthropic 基于自身工作实践开源，11 个插件覆盖了真实使用中反复出现的工作模式，具备较高的可参考性。可定制性也是其核心设计取向：团队无需从零构建，而是在官方插件基础上替换为自有工具与流程，缩短落地路径。Apache-2.0 许可为二次开发和商业集成提供了宽松条件。得益于较高的社区关注度，插件的维护与扩展具备持续迭代的潜力。
