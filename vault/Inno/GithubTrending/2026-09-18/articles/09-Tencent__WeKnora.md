## 项目概述

WeKnora 是由腾讯开源的一套 LLM 知识平台，使用 Go 语言开发。它的核心目标是把分散、非结构化的原始文档转化为三种可用的知识形态：可查询的 RAG（检索增强生成）系统、具备自主推理能力的智能体（Agent），以及能够自我维护的 Wiki。

传统做法中，把一批文档接入大模型问答通常需要自行搭建文档解析、切分、向量化、检索、重排、提示词编排等一整套流水线，工作量大且各部分质量参差。WeKnora 把这些环节整合为一个统一平台，降低了从"一堆文件"到"可用知识服务"之间的工程成本。

目标用户包括：希望快速为内部资料搭建问答系统的企业与团队、需要构建 RAG 应用的开发者、以及关注知识管理与 Agent 能力的研究人员。

## 核心功能

- **文档到 RAG 的转化**：支持将原始文档解析、切分并向量化，构建可供检索的知识库，为后续问答提供上下文。
- **自主推理 Agent**：在检索之上提供具备推理与多步规划能力的智能体，可围绕用户问题自主调用工具、组织信息并给出答案。
- **自维护 Wiki**：将知识内容组织为可自我维护的 Wiki 形态，减少人工整理与更新的负担。
- **多端接入能力**：提供官网、微信对话开放平台、Chrome 扩展、ClawHub Skill 以及 npm 包（`@wxg-prc-cpg/dsh-weknora`）等多种使用入口。
- **开放与可扩展**：作为开源项目，允许开发者基于自身数据与业务场景进行二次开发与集成。

## 技术架构

项目主体采用 Go 语言实现，这一选择使其在并发处理、部署体积和运行性能上具备优势，适合承载文档解析与检索这类 I/O 密集且需要稳定吞吐的任务。

从功能划分看，架构大致围绕三条主线组织：数据侧负责文档的接入、解析与索引构建；检索侧负责向量化与相似度匹配，为 RAG 提供依据；智能侧则在检索结果之上叠加推理与 Agent 调度逻辑，并支撑 Wiki 形态的知识组织。三者共享同一套知识底座，因此文档只需处理一次，即可同时服务于问答、推理与 Wiki 展示。

项目提供了官网、微信生态、浏览器扩展与 npm 包等多渠道接入方式，说明其对外暴露了相对完整的接口层，便于在不同终端复用同一后端能力。

## 安装与使用

仓库未在摘录中给出完整安装命令，通常这类 Go 项目的通用流程如下：

1. 准备 Go 运行环境（建议使用较新版本），并克隆仓库：
   ```bash
   git clone https://github.com/Tencent/WeKnora.git
   cd WeKnora
   ```
2. 按项目文档配置模型与向量化服务的相关参数（如 API Key、服务地址等）。
3. 构建并启动服务：
   ```bash
   go build ./...
   ```
4. 通过官网或提供的客户端入口接入，导入文档后即可进行检索与问答。

由于平台依赖外部大模型与向量服务，实际使用前需先完成相应的凭证配置。建议以仓库内的官方文档为准。

## 适用场景

- **企业内部知识库问答**：将制度、手册、技术文档统一导入，构建可检索、可对话的内部助手。
- **文档密集型业务的智能检索**：面向法律、医疗、金融等需要从大量资料中快速定位信息的场景。
- **RAG 与 Agent 应用开发**：作为基础平台，供开发者在其上搭建自定义的推理与工具调用流程。
- **知识沉淀与 Wiki 维护**：利用自维护 Wiki 能力，降低团队知识整理与更新的持续投入。

## 项目亮点

与同类方案相比，WeKnora 的主要差异点在于把 RAG、Agent 与 Wiki 三种知识形态统一在同一平台中，而非只解决检索或只解决对话的单一环节。其次，Go 语言实现带来的性能与部署特性，使其更适合在生产环境中长期运行。此外，腾讯提供的多端入口（微信生态、Chrome 扩展、npm 包等）降低了终端用户的接入门槛，而 26000+ 的 Star 数也反映出社区对其关注度较高。
