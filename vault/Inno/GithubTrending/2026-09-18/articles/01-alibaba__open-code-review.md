## 项目概述

OpenCodeReview 是阿里巴巴开源的一款代码评审（Code Review）工具，采用“确定性流水线 + LLM Agent”的混合架构，在阿里巴巴内部大规模生产环境中经过长期验证。它要解决的核心问题是：传统静态代码扫描工具误报率高、难以理解上下文语义，而纯大模型评审方案又存在结果不稳定、成本高、难以精确落到代码行等缺陷。

该项目将两类能力结合：确定性流水线负责高召回地定位可疑代码片段，LLM Agent 负责结合上下文进行语义判断与解释，最终输出精确到行级的评审意见，并内置覆盖 NPE（空指针）、线程安全、XSS、SQL 注入等常见缺陷的多语言规则集。目标用户包括需要为团队引入自动化代码评审的研发团队、在 CI 流程中寻求质量门禁的工程效能团队，以及自建研发平台、需要可私有化部署评审能力的组织。

## 核心功能

- **混合评审架构**：确定性流水线负责规则匹配与候选缺陷召回，LLM Agent 负责语义复核，兼顾准确率与稳定性。
- **精确行级评论**：评审结果定位到具体代码行，可直接以评论形式回写到 Pull Request / Merge Request。
- **内置多语言规则集**：覆盖 NPE、线程安全、XSS、SQL 注入等高风险缺陷模式，开箱即用。
- **多模型兼容**：支持 OpenAI 与 Anthropic 兼容接口，可对接公有云服务或自建推理端点。
- **CI 集成能力**：提供命令行入口，便于嵌入持续集成流程作为质量门禁。
- **Alibaba 规模验证**：核心能力已在阿里巴巴内部大体量代码仓库中实际运行。

## 技术架构

项目使用 Go 语言实现，选择 Go 主要出于分发与性能考虑：单二进制、无运行时依赖，适合在 CI 容器中快速启动，也便于在评审高峰期控制资源开销。

架构上最显著的特点是**职责分离**。确定性流水线承担“找得到”的职责：以规则匹配、模式识别等方式对变更代码做扫描，输出的候选集合强调高召回、低门槛，避免因模型能力波动而漏检；LLM Agent 承担“判得准”的职责：在候选片段及其上下文之上进行语义分析，判断是否为真实缺陷、解释成因并给出修复建议。这种分工带来两点收益：一是降低了纯 LLM 方案的 token 消耗与调用次数，二是让评审结论具备可回溯的规则依据，减少“模型幻觉”带来的干扰。

评审粒度方面，工具以代码行为基本单位组织输出，使评论能够准确锚定到 diff 中的具体位置，便于开发者直接响应。规则集采用多语言组织方式，便于按技术栈裁剪和扩展。模型接入层通过兼容 OpenAI / Anthropic 协议实现解耦，用户可在不改动核心逻辑的前提下切换推理后端。

## 安装与使用

项目以 npm 包形式发布（`@alibaba-group/open-code-review`），同时提供二进制发布产物，可按团队习惯选择：

```bash
# 方式一：通过 npm 安装
npm install -g @alibaba-group/open-code-review

# 方式二：从 GitHub Releases 下载对应平台的二进制文件
```

使用前需配置模型服务凭据，指向兼容 OpenAI 或 Anthropic 协议的端点：

```bash
export OCR_API_KEY="your-api-key"
export OCR_BASE_URL="https://api.openai.com/v1"
export OCR_MODEL="gpt-4o"
```

最小可用示例（对当前仓库的变更执行评审）：

```bash
open-code-review review --diff HEAD~1
```

在 CI 中通常结合目标分支比较使用，并将结果以评论形式提交到 PR。具体参数、规则开关与配置项以仓库文档为准。

## 适用场景

- **Pull Request 自动化评审**：在 PR 提交时自动生成行级评论，拦截空指针、SQL 注入等高风险问题。
- **CI 质量门禁**：在流水线中作为检查项运行，对不达标变更阻断合并。
- **研发平台能力集成**：将评审能力作为服务嵌入企业自研 DevOps 平台。
- **遗留代码治理**：对历史代码库批量扫描，梳理安全与并发相关的技术债。

## 项目亮点

与同类工具相比，OpenCodeReview 的差异化主要体现在三点。其一是**架构选择**：市面上多数方案要么是纯规则引擎、要么是纯 LLM 驱动，本项目以“确定性召回 + Agent 复核”的方式在准确率、成本与稳定性之间取得平衡，避免了纯 LLM 方案结果不可复现、成本随规模线性上升的问题。其二是**工程成熟度**：项目并非实验室原型，而是在阿里巴巴内部大规模代码量下打磨过的产品，对性能与误报控制有实际约束。其三是**开放与可控**：Apache-2.0 许可、Go 单二进制分发、兼容主流模型协议，既可对接公有云 API，也支持私有化部署，适配对代码外发有合规要求的团队。
