## 项目概述

`security-audit-skill` 是 Cloudflare 开源的一个编码代理技能（coding-agent skill），用于将通用代码代理转变为具备结构化流程的安全审计器。它解决的核心问题是：传统依靠单次提示让大模型“找漏洞”的方式结果不稳定、覆盖面不足、且难以验证真伪。该项目通过多阶段编排、隔离代理协作与独立复核机制，把安全审计拆解为可重复、可追溯的流程，并最终产出机器可读、经过独立验证的发现记录。

目标用户包括安全工程师、代码审计人员、使用代理进行漏洞挖掘的研究者，以及希望将安全审查自动化集成到开发流程中的团队。项目本身是 Cloudflare 内部漏洞挖掘框架的起点版本，该框架后来演化为跨仓库、多阶段的舰队级系统，而本仓库保留了其最初的单仓库形态。

## 核心功能

- **六阶段结构化审计流程**：依次执行侦察、覆盖导向的漏洞搜寻、候选验证、结构化输出、独立记录验证与目标中立报告，确保每一步都有明确产物。
- **覆盖账本（coverage ledger）驱动搜寻**：在侦察阶段生成 `architecture.md` 与 `coverage-ledger.json`，将系统划分为独立单元并分配给隔离的搜寻代理，同时使用覆盖批评者（coverage critics）查找遗漏区域。
- **独立验证机制**：每个唯一候选漏洞交由全新的验证代理尝试证伪，最终源码声明也由独立代理复核，重要替换结论还需再经一名验证者确认。
- **机器可读输出与模式校验**：将结果写入 `findings.json`，并依据 `report-schema.json` 校验，区分 `confirmed`、`needs_validation` 与 `rejected` 三类状态。
- **目标中立报告生成**：从已验证记录与覆盖账本派生出 `REPORT.md`、`FINDINGS-DETAIL.md` 和 `NEEDS-VALIDATION.md`，不依赖特定目标类型。
- **可复用的代理技能形态**：以技能形式提供给编码代理，便于在不同仓库和不同代理环境中调用。

## 技术架构

项目使用 JavaScript 实现，整体设计围绕“流程编排 + 多代理隔离”展开。其核心思路并非依赖单次模型推理，而是把一个复杂安全审计任务分解为六个顺序化阶段，每个阶段产生显式文件产物（如架构文档、覆盖账本、发现 JSON），使审计过程可检查、可增量推进。

在架构上，它强调“隔离”与“独立验证”：搜寻代理只负责账本中分配到的单元，验证代理由不同实例承担，且无法复用候选提出者的推理路径，从而降低确认偏差。覆盖批评者与账本机制共同保证审计范围不会因模型选择性关注而收缩。最终报告完全从结构化记录派生，避免了自由文本总结带来的信息失真。

## 安装与使用

该仓库作为一个代理技能发布，通常需要先将其克隆到本地，然后按照仓库中的技能描述文件将其注册到你使用的编码代理环境（如支持技能加载的代理框架）中。由于项目本身是技能定义而非独立可执行程序，使用方式依赖于宿主代理。

基本步骤通常为：

1. 克隆仓库：`git clone https://github.com/cloudflare/security-audit-skill`
2. 在代理环境中加载该技能，使其可被调用。
3. 指定待审计的目标仓库或代码路径，触发六阶段审计流程。
4. 审计结束后查看生成的 `findings.json`、`REPORT.md`、`FINDINGS-DETAIL.md` 和 `NEEDS-VALIDATION.md`。

最小可用示例即：在代理中调用该技能并传入目标代码库，审计流程会自动完成各阶段并输出结构化结果。具体调用语法请以仓库文档为准。

## 适用场景

- **开源项目安全自查**：对单一仓库进行系统性漏洞挖掘，获得可验证的发现列表。
- **代码审计教学与演练**：利用其分阶段流程演示覆盖导向审计与独立验证方法。
- **漏洞挖掘框架的原型搭建**：作为构建自有漏洞挖掘工具的起点，按需扩展阶段或替换验证策略。
- **CI/CD 中的安全审查环节**：将结构化发现集成进流水线，对 `needs_validation` 与 `confirmed` 记录做分级处理。

## 项目亮点

与同类依靠单次提示或简单链式调用的代理方案相比，该项目的差异化在于把“验证”提升为一级流程：候选漏洞必须由独立代理尝试证伪，最终结论还要经过记录级复核。覆盖账本与覆盖批评者机制则从流程上对抗模型的选择性忽略，使审计范围可度量。同时，输出完全结构化并受 JSON Schema 约束，便于后续自动化消费，而非依赖自由文本报告。作为 Cloudflare 实际漏洞挖掘框架的起点版本，它保留了经过真实环境检验的设计思路。
