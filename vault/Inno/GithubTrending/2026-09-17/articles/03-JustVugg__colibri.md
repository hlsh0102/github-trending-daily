## 项目概述

Colibrì（colibri）是一个用纯 C 编写的 MoE（混合专家）模型推理引擎，目标是在用户已有的消费级或异构硬件上运行前沿规模的大模型。它支持的模型参数量从 744B 到 2.8T，同时保持引擎本体极小的体积且不依赖任何第三方运行时。项目的核心思路是"AI 内存多层化"：把磁盘存储、系统内存（RAM）和显存（VRAM）视为一个统一的推理层级，将专家权重按需从磁盘流式加载，而不是要求把整个模型一次性放进内存或显存。

它解决的问题很直接：前沿 MoE 模型的参数规模远超单机显存容量，传统推理框架通常需要多卡集群或高内存服务器。Colibrì 通过磁盘流式加载专家参数，让普通工作站甚至单张消费级显卡也能运行这类模型。目标用户包括个人研究者、预算有限的开发者，以及希望在本地环境评估大模型行为而无需云资源的团队。

## 核心功能

- **磁盘流式专家加载**：专家权重存放在磁盘上，推理时按路由结果动态读取，避免全量模型常驻内存或显存。
- **统一内存层级管理**：将存储、RAM、VRAM 抽象为单一推理层级，引擎根据访问频率和设备容量决定放置策略。
- **多模型族支持**：当前覆盖九个模型家族，包括 GLM-5.2/5.3（744B）、GLM-5.3-Flash（321B，带视觉）、Inkling（975B）、Kimi K3（2.8T）、DeepSeek V4 Flash（284B）、DeepSeek V4.1 Flash（552B，带视觉）、Qwen3.8-Flash-Next（125B + 51B n-gram）、Qwen3.6（35B-A3B）和 OLMoE（7B）。
- **统一命令行前端**：同一套 `coli chat`、`coli serve`、`coli web` 接口适用于所有支持的模型，切换模型无需更换工具链。
- **零引擎依赖**：纯 C 实现，不依赖 Python 运行时、CUDA 工具链之外的框架或大型第三方库，便于在异构环境中编译部署。
- **单文件模型适配**：每个模型族对应一个 C 文件，降低新增模型支持的门槛，也使代码结构清晰可审计。

## 技术架构

Colibrì 的设计围绕"内存多层化"展开。MoE 架构的特点是每次前向传播只激活部分专家，这为按需加载提供了天然条件：引擎只需在路由阶段确定被选中的专家，再从磁盘读取对应权重块即可。存储层负责持久化全部专家参数，RAM 作为缓存层保留高频专家，VRAM 则承载当前计算所需的活跃参数和注意力相关张量。

这种分层要求引擎对 I/O 有精细控制。纯 C 实现让项目可以自行管理文件读取、缓冲区分配和生命周期，而不依赖垃圾回收或高层框架的内存抽象。零依赖的另一层含义是可移植性：只要目标平台有 C 编译器和足够的磁盘 I/O 带宽，理论上就能运行。

模型适配以单文件形式组织，意味着每个模型族的张量命名、路由逻辑和特殊结构（如视觉编码器）在独立的 C 文件中实现，共享底层的层级管理和调度代码。这种结构在支持新模型时只需新增一个文件，而不必改动核心引擎。

## 安装与使用

典型安装流程是从 GitHub Releases 获取预编译二进制，或从源码编译。源码编译通常只需 `make` 或等价的 C 构建命令，因为项目没有外部依赖。使用前需要准备对应模型的权重文件，并按文档要求放置在指定目录，引擎会在启动时扫描并建立索引。

最小可用示例（以聊天模式为例）：

```bash
coli chat --model <模型标识> --weights <权重目录>
```

服务模式使用 `coli serve`，Web 界面使用 `coli web`。由于不同模型族的权重格式和加载参数可能不同，具体参数应以仓库文档和各模型说明为准。首次运行时，引擎可能需要建立磁盘索引或缓存元数据，启动时间会相应延长。

## 适用场景

- **本地大模型研究**：研究者希望在自有硬件上观察前沿 MoE 模型的推理行为，而不依赖云 API 或集群。
- **显存受限环境的模型部署**：只有单张消费级显卡或有限内存的工作站，仍可运行参数量远超显存容量的模型。
- **异构硬件验证**：需要在不同存储介质（NVMe、SATA SSD）和内存配置下测试推理吞吐与延迟。
- **教学与实验平台**：由于代码为纯 C 且结构清晰，适合作为 MoE 推理和内存分层策略的教学案例。

## 项目亮点

与常见推理框架相比，Colibrì 的差异化在于极端的依赖极简和内存分层策略。多数支持大 MoE 的方案依赖 Python 生态或特定厂商的推理栈，而 Colibrì 用纯 C 实现完整引擎，减少了部署摩擦。其次，它不要求模型全量驻留内存，而是把磁盘当作推理层级的一部分，这使其支持的参数量上限远高于同硬件上的常规方案。最后，单文件模型适配和统一的命令行前端，让多模型切换的成本显著降低。
