## 项目概述

Tinycast 是一款完全原生的 macOS 启动器（Launcher）应用，将启动器、全局热键与剪贴板历史三项常用能力集成在一个入口下。用户只需按下一个热键，即可访问日常反复使用的功能，而无需在多个工具之间切换。

该项目主要针对 macOS 平台对轻量、隐私友好工具的诉求。它强调“小而快”：根据项目描述，运行时内存占用控制在 100 MB 以内，不依赖 Electron，也不包含任何遥测（telemetry）逻辑。同时，它兼容 Raycast 扩展生态，可将这些扩展以原生 SwiftUI 形式渲染，从而在保留扩展能力的同时避免引入庞大的运行时依赖。

目标用户包括：希望用一个热键统一管理应用启动、快捷操作与剪贴板记录的高频 Mac 用户；对第三方依赖、后台遥测与资源占用较为敏感的开发者或隐私关注者；以及已有 Raycast 扩展、希望以更轻量的宿主继续使用的用户。

## 核心功能

- **应用启动器**：通过单一全局热键唤起面板，快速检索并启动应用或执行命令。
- **全局热键**：提供统一的快捷键入口，减少在菜单栏与 Dock 之间的切换成本。
- **剪贴板历史**：记录并检索剪贴板内容，避免复制内容被覆盖后难以找回。
- **运行 Raycast 扩展**：支持执行真实的 Raycast 扩展，并将其界面渲染为原生 SwiftUI 组件。
- **原生界面与低资源占用**：使用 SwiftUI 与 AppKit 构建，全程无第三方依赖，内存占用控制在 100 MB 以内。
- **无遥测与本地隐私**：不采集遥测数据，隐私相关内容可通过邮件与作者联系。

## 技术架构

Tinycast 以 Swift 6.0 编写，要求 macOS 26 或更高版本，界面层由 SwiftUI 与 AppKit 共同实现。其架构设计围绕“原生优先”展开：

- **零第三方依赖**：项目不引入外部库，减少供应链风险与体积膨胀，同时简化构建与分发。
- **非 Electron 运行时**：与基于 Web 技术栈的启动器不同，Tinycast 直接使用系统原生框架，避免了额外的运行时进程与内存开销。
- **Raycast 扩展兼容层**：项目实现了运行 Raycast 扩展的能力，但并未沿用其原本的渲染方式，而是把扩展输出映射为原生 SwiftUI 视图。这一设计使扩展生态可用，同时保持原生体验与较低的资源占用。
- **隐私与无遥测**：应用不内置遥测上报机制，行为边界相对清晰。

整体而言，项目的设计思路是在功能覆盖与资源消耗之间做取舍：用系统原生能力替代通用运行时，用扩展兼容层替代封闭生态。

## 安装与使用

由于 README 摘录未提供完整的安装命令，以下为基于常见 macOS 开源应用分发方式的概述：

1. 访问项目的 GitHub Releases 页面，下载最新的发布版本。
2. 打开下载的安装包（通常为 `.dmg` 或 `.zip`），将 Tinycast 拖入“应用程序”目录。
3. 首次启动时，按系统提示授予必要的辅助功能或输入监控权限，以便全局热键与剪贴板历史正常工作。
4. 启动后设置或确认唤起面板的全局热键。
5. 按下热键唤起面板，输入关键词检索应用；在剪贴板历史中浏览或粘贴既往内容；如需扩展能力，可导入或启用 Raycast 扩展。

如需从源码构建，通常需要安装 Xcode 与 Swift 6.0 工具链，克隆仓库后使用 Xcode 打开工程进行编译。具体步骤建议以仓库中的构建说明为准。

## 适用场景

- **日常应用快速启动**：用统一热键替代在 Dock、启动台与访达之间反复切换。
- **剪贴板内容管理**：在复制多段内容后，从历史记录中找回此前复制过的文本或片段。
- **复用 Raycast 扩展**：已有 Raycast 扩展工作流的用户，希望在更轻量的宿主中继续使用。
- **低资源占用环境**：在内存有限或对后台进程敏感的设备上，作为替代方案使用。

## 项目亮点

与同类启动器相比，Tinycast 的差异化主要体现在三点：

其一，**完全原生且零第三方依赖**。项目不使用 Electron，也不引入外部库，这使其在内存占用与启动表现上更接近系统原生工具。

其二，**在原生宿主中运行 Raycast 扩展**。多数轻量启动器难以兼容既有扩展生态，而 Tinycast 选择以原生 SwiftUI 渲染扩展界面，兼顾了生态可用性与原生体验。

其三，**无遥测、开源且免费**。项目不采集遥测数据，采用 AGPL-3.0 许可，并明确表示将保持开源与免费。这一点对隐私敏感的用户具有实际意义。

需要说明的是，项目要求 macOS 26 或更高版本，对系统版本有较明确的门槛，使用前需确认设备兼容性。
