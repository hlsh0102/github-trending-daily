## 项目概述

Knowledge Work Plugins 是 Anthropic 开源的一组插件集合，目标是把 Claude 从通用助手转变为面向特定岗位、团队和公司的专业助手。项目主要服务于使用 Claude Cowork 的知识工作者，同时也兼容 Claude Code。

在默认状态下，Cowork 已经能够根据用户设定的目标交付相对完整的专业成果。但对于真实的企业场景而言，这还不够：不同团队有自己的工作习惯、工具链、术语体系和关键流程。Knowledge Work Plugins 通过插件机制把上述信息封装起来，让 Claude 知道“工作应该怎么做”“该从哪些工具和数据源取信息”“哪些关键流程需要特殊处理”“暴露哪些斜杠命令”，从而让团队获得更一致、更可预期的产出。每个插件围绕一个具体的职能角色组织，包含技能（skills）、连接器（connectors）、斜杠命令（slash commands）和子代理（sub-agents）。开箱即用的版本提供了一个良好的起点，真正的价值在于团队基于自身工具、术语和流程进行定制。

## 核心功能

- **按职能打包的插件体系**：每个插件对应一个具体岗位，例如生产力、销售等，将该角色所需的技能、连接器、命令和子代理打包在一起，形成可直接使用的能力单元。
- **多工具连接器集成**：插件内置对主流协作与业务工具的连接支持，例如 Slack、Notion、Asana、Linear、Jira、Monday、ClickUp、Microsoft 365、HubSpot、Close、Clay、ZoomInfo、Fireflies 等，使 Claude 能够从真实数据源中读取信息。
- **斜杠命令与子代理**：通过预定义的斜杠命令快速触发常见工作流，并借助子代理拆分复杂任务，提升交互效率。
- **面向企业定制的可扩展结构**：插件的内容可以被团队替换或扩展，包括术语、流程、工具配置等，让 Claude 的行为贴合组织实际。
- **官方开源插件市场**：首批开源 11 个插件，均源自 Anthropic 内部实践或受其启发，作为可直接参考和改造的基础模板。

## 技术架构

项目以 Python 为主要实现语言，采用插件化架构。每个插件是一个独立的目录单元，内部组织技能、连接器、斜杠命令与子代理等组件，形成清晰的功能边界。这种设计使插件之间相互解耦，便于单独安装、替换或二次开发。

连接器层负责与外部 SaaS 工具对接，是插件获取上下文数据的关键路径；技能层描述 Claude 在特定任务中应遵循的方法和规则；斜杠命令和子代理则提供交互入口与任务编排能力。整体思路不是把能力写死在核心系统中，而是通过声明式与模块化的组合，让用户在不改动底层的前提下调整 Claude 的行为。

项目遵循 Apache-2.0 许可证，允许商业使用与修改，适合企业内部沉淀自己的插件资产。

## 安装与使用

仓库本身是插件的集合，使用方式通常有两种：直接采用官方提供的插件，或基于官方模板为自己的团队定制。基本流程如下：

1. 克隆仓库：
   ```
   git clone https://github.com/anthropics/knowledge-work-plugins
   ```
2. 进入所需的插件目录，例如 `productivity` 或 `sales`，阅读该目录下的说明，了解它包含的技能、连接器和命令。
3. 在 Claude Cowork（或 Claude Code）中加载并启用对应插件，按其要求配置所依赖的连接器（如 Slack、Notion、Jira 等）的凭据与访问权限。
4. 根据团队实际情况修改插件内容，例如替换术语、调整工作流程、增删斜杠命令或子代理。

最小可用示例：选择 `productivity` 插件，完成 Slack 与 Notion 的连接配置后，即可通过该插件暴露的斜杠命令让 Claude 执行任务管理、日程安排和日常流程处理，而无需每次重复说明上下文。

## 适用场景

- **岗位级助手搭建**：为销售、项目管理、日常生产力等不同职能快速配置面向该角色的 Claude 助手。
- **企业流程标准化**：把公司特有的术语、审批流程和工作规范固化进插件，让团队成员获得一致的输出。
- **多工具信息整合**：在 Slack、Notion、Jira、HubSpot 等工具之间统一取数与操作，减少人工切换。
- **插件二次开发**：把官方插件作为模板，改造为契合自身业务的自定义插件，并沉淀为内部资产。

## 项目亮点

与通用的提示词模板或零散脚本相比，Knowledge Work Plugins 的主要差异在于结构化和可定制性。它把“角色能力”拆解为技能、连接器、命令和子代理四类可组合组件，并提供官方维护的 11 个插件作为参考实现。这种设计让团队能够在官方基础上渐进式定制，而不必从零构建。同时，它对 Claude Cowork 与 Claude Code 的双兼容，以及 Apache-2.0 的宽松许可，使其在企业内部推广和改造时具备较低的采用门槛。
