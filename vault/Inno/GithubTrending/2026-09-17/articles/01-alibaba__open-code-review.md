## 项目概述

OpenCodeReview 是阿里巴巴开源的一款代码审查工具，采用混合架构设计：由确定性流水线负责静态规则扫描，再由 LLM Agent 负责语义层面的分析与解释。项目使用 Go 语言编写，遵循 Apache-2.0 协议，已在阿里巴巴内部大规模、长时间使用，具备经受过海量代码库验证的工程稳定性。

它主要解决的问题是传统代码审查的两类痛点。纯静态分析工具（如各类 Linter）规则明确、速度快，但只能发现预设模式的问题，无法理解上下文语义，误报与漏报并存；纯 LLM 审查工具则相反，具备语义理解能力，但成本高、结果不稳定、难以覆盖大规模代码。OpenCodeReview 将两者结合，把确定性规则用于高置信度问题的快速筛查，把 LLM 用于需要理解意图与上下文的复杂判断，从而在准确率、召回率和成本之间取得平衡。

目标用户包括：需要在大规模代码库中落地自动化审查的工程团队、希望把审查能力集成进 CI/CD 流水线的平台工程师，以及关注代码安全（如空指针、线程安全、注入类漏洞）的研发与安全团队。

## 核心功能

- **混合审查引擎**：确定性流水线负责规则匹配与模式识别，LLM Agent 负责语义推理与修复建议，两者结果合并输出，兼顾稳定性与智能性。
- **行级精确评论**：审查结果定位到具体代码行，可直接以评论形式回写至代码托管平台，减少人工定位成本。
- **内置多语言规则集**：覆盖空指针引用（NPE）、线程安全问题、XSS、SQL 注入等常见缺陷类别，支持多语言代码库。
- **多模型兼容**：接口兼容 OpenAI 与 Anthropic 系列模型的调用协议，可灵活切换或自托管模型服务。
- **工程化集成能力**：提供命令行与流水线接入方式，便于嵌入现有的代码评审流程与持续集成环节。

## 技术架构

项目以 Go 语言实现，主要出于性能与部署便利性的考虑：单二进制产物、低运行时依赖、便于在 CI 容器中分发。整体架构可分为三层。

第一层是确定性流水线（deterministic pipelines）。这一层不依赖模型，按照预设规则集对代码进行解析与匹配，输出结构化的问题条目。由于结果可复现，适合作为门禁类检查，避免因模型波动导致流水线不稳定。

第二层是 LLM Agent。它在流水线结果与代码上下文的基础上进行语义分析，识别规则难以覆盖的问题，并生成解释与修复建议。Agent 通过统一抽象接入不同模型供应商，屏蔽 OpenAI 与 Anthropic 协议的差异。

第三层是结果聚合与输出层。两路结果经过去重、优先级排序后，映射到具体的文件与行号，最终以行级评论、结构化报告或流水线状态的形式输出。

这种分层设计的核心思路是"确定性优先、模型增强"：能用规则可靠判定的问题不消耗模型调用；只有需要语义理解的部分才交给 LLM，从而控制成本与延迟。

## 安装与使用

项目同时提供 Go 源码与 npm 包两种分发方式，后者便于前端或 Node 生态的项目直接接入。

通过 npm 安装：

```bash
npm install -g @alibaba-group/open-code-review
```

或从源码构建（需要 Go 环境）：

```bash
git clone https://github.com/alibaba/open-code-review.git
cd open-code-review
go build ./...
```

使用前需配置模型服务凭据，将 API Key 与模型端点通过环境变量或配置文件注入。随后对目标代码目录执行审查命令，工具会输出定位到文件与行号的问题列表。在 CI 场景中，可将该命令加入流水线步骤，根据返回状态码决定是否阻断合并。具体命令参数与配置项建议以仓库 README 与官方文档为准。

## 适用场景

- **持续集成门禁**：在合并请求阶段自动运行审查，拦截空指针、注入类等高危缺陷。
- **大规模代码库治理**：对历史仓库进行批量扫描，定位安全与并发相关的存量问题。
- **多语言混合项目**：同一套规则集与流程覆盖多种编程语言的代码仓库，降低工具链维护成本。
- **自托管模型环境**：对数据出境有要求的团队，可对接内部部署的兼容 OpenAI/Anthropic 协议的模型服务。

## 项目亮点

与同类工具相比，OpenCodeReview 的差异化主要体现在三点。其一，混合架构而非单一模型驱动，规则层保证了结果的可复现性，使工具能够作为流水线门禁使用。其二，"battle-tested at Alibaba's scale"意味着它并非实验室原型，而是经过超大规模代码库与真实团队流程检验的工程产物。其三，内置规则集直接面向高价值缺陷类别（NPE、线程安全、XSS、SQL 注入），而非泛化的代码风格检查，审查产出更贴近实际风险。此外，对 OpenAI 与 Anthropic 协议的双兼容降低了模型供应商锁定风险。
