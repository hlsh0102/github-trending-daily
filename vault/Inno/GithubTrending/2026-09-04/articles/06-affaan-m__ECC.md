## 项目概述

ECC（Enhanced Claude Code）是一个面向 AI 代理（Agent）运行时的性能优化与能力增强系统。它本质上是一个“代理操作系统的外壳层”，通过注入技能（Skills）、直觉（Instincts）、记忆（Memory）、安全机制（Security）与研究优先的开发范式，显著提升 Claude Code、Codex、Opencode、Cursor 等主流 AI 编码工具的执行效率与输出质量。

该项目解决了当前 AI 编码代理普遍存在的几个核心痛点：上下文窗口利用率低、重复性错误难以根除、跨会话记忆缺失、安全边界模糊以及多工具切换时技能无法复用。ECC 将这些问题统一抽象为“代理运行时优化”问题，并提供一套系统性的解决方案。目标用户是重度依赖 AI 编码助手进行软件开发的工程师、技术团队负责人以及 AI 应用研究者，特别是那些希望在现有工具链上获得更深层控制力与更高自动化水平的用户。

## 核心功能

- **技能（Skills）动态注入框架**：支持将自定义技能以结构化方式注入不同的 IDE 或命令行代理工具，技能按领域分组，可跨工具共享，构建一次编写、处处运行的能力库。
- **直觉（Instincts）规则引擎**：允许用户定义项目特定的编码模式与偏好规则，代理在生成代码时会自动遵守这些约束，从源头减少风格不一致与架构偏离问题。
- **持久化记忆层**：提供跨会话的记忆存储机制，代理可以记住项目历史决策、用户偏好、常见修复模式，避免每次对话从零开始，大幅减少重复性沟通成本。
- **安全边界控制套件**：内置沙箱级权限管理，针对代理执行的操作提供细粒度的审批流程与敏感操作拦截，包括危险命令检测、文件系统写入白名单等特性。
- **研究优先（Research-First）开发流水线**：将“先研究后编码”的实践固化为工作流，代理在执行编码任务前强制进行相关代码库搜索、依赖分析或 API 文档查阅，显著降低盲目编码带来的返工率。
- **多工具适配层**：原生支持 Claude Code、Codex、Opencode、Cursor 等多个主流代理环境，并提供统一的配置接口与行为抽象。

## 技术架构

ECC 的核心架构遵循“配置即代码”与“运行时织入”两大设计理念。项目基于 JavaScript/TypeScript 技术栈构建，利用 Node.js 的异步与事件驱动特性来实现对多种代理工具的工具链适配。

在具体实现层面，ECC 通过一个轻量级的内存驻留代理服务与各编码工具的插件系统通信。技能与直觉规则被定义为结构化的 JSON Schema（内嵌可执行脚本或 prompt 模板），在代理每次会话初始化或任务切换时动态加载并注入提示词上下文。记忆模块采用分层存储策略：热数据保存在内存缓存中以降低延迟，冷数据持久化到本地文件系统或用户配置的远端存储（如 SQLite 或文件 embed）。

安全模块独立于功能模块运行，作为中间件拦截代理的 I/O 请求，通过正则规则库与命令解析器对操作风险进行分级。系统在启动时可对现有代理工具链进行自动探测（如检查 claude-code 或 cursor 的 CLI 配置文件），实现零摩擦初始化。所有组件均遵循 MIT 协议，核心逻辑与工具适配层解耦，使社区开发者能够轻松为新的代理工具编写适配器。

## 安装与使用

**安装前提**：需要已安装 Node.js 16+ 以及任意一种受支持的编码代理工具（如 Claude Code 或 Cursor）。

**全局安装 ECC CLI**：

```bash
npm install -g ecc-cli
```

**项目初始化**：

```bash
cd your-project
ecc init
```

执行上述命令后，ECC 会在项目根目录生成 `ecc.config.json` 配置文件，具体结构示例如下：

```json
{
  "agent": "claude-code",
  "skills": ["code-review", "test-generation"],
  "memory": { "enabled": true, "storage": "local" },
  "security": { "blocklist": ["rm -rf /", "git push --force"] }
}
```

**启动代理会话**：

```bash
ecc run
```

此时 ECC 会启动包装层，自动加载技能库与记忆索引，并建立安全监控。在 IDE 或 CLI 中正常编码即可感受到增强效果。无需编码与 ECC 交互——所有注入逻辑在底层透明完成。

## 适用场景

- **大型遗留代码库的现代化改造**：面对缺少文档与测试的历史项目，ECC 的研究优先模式会强制代理在修改前搜索相关调用链与业务逻辑，记忆层则确保跨文件的重构步骤保持一致，显著降低大型改动引入新 bug 的风险。
- **团队级编码规范一致性落地**：技术负责人可通过直觉规则引擎将团队内定的命名规范、异常处理模式与架构约束注入所有成员的 AI 辅助工具中，大幅简化 Code Review 的负担。
- **高复杂度跨工具工作流编排**：如果团队日常在 Cursor（IDE 补全）与 Claude Code（终端代理）之间切换，ECC 的技能共享层可以确保两个工具遵循同一套开发习惯与项目知识。
- **安全敏感环境下的自动化辅助**：在涉及生产数据或合规要求的研发环境中，ECC 的安全套件能有效阻止 AI 代理执行具有破坏性的高危命令，并提供含时间戳的审计日志。

## 项目亮点

与单纯针对某一个 IDE 的插件（如 JetBrains AI Assistant 或 VS Code Copilot Chat extensions）相比，ECC 的差异化优势在于其“运行时操作系统”的定位。它不锁定于某一工具厂商，而是位于工具之上，提供一种横向的编排能力。

此外，其“研究优先”理念与市面上主流的“生成优先”实践形成鲜明对比。通过强化编码前的调研步骤，ECC 所生成的代码在架构契合度与可维护性上通常高于零上下文直接生成的代码。最后值得一提的是其开放的配置哲学——整个系统不设置私有格式，所有技能与规则均为人类可读的 JSON/JS 文件，用户对系统内部运作拥有完全的透明度和可控性，这在同类产品中较为罕见。
