## 项目概述

`croc` 是一款开源的命令行工具，旨在让任意两台计算机之间能够简单、安全地传输文件和文件夹。它由 Go 语言编写，采用 MIT 许可证发布，由开发者 schollz 维护，在 GitHub 上已获得超过 37,000 颗星标。

在跨设备文件传输的场景中，用户常常面临诸多痛点：需要配置复杂的网络环境、依赖第三方云服务、传输过程缺乏加密保障，或者在不同操作系统之间遇到兼容性问题。`croc` 正是为解决这些问题而生。它通过中继服务器建立连接，无需用户具备端口转发或公网 IP 的知识，即可在两台设备之间完成点对点的数据传输。

项目的目标用户包括需要频繁在个人设备间传输文件的普通用户、需要快速向同事或客户发送资料的远程工作者，以及希望在终端环境中高效传输数据的开发者和运维人员。`croc` 提供了一键式的命令行操作体验，降低了文件传输的技术门槛。

## 核心功能

- **任意两台计算机之间的传输**：借助内置的中继服务器，`croc` 能够穿越 NAT 和防火墙，实现两台设备之间的直接或中继传输，无需双方同时在线或拥有公网 IP。
- **端到端加密**：采用密码认证密钥交换（PAKE）协议，确保传输过程中的数据在发送端加密，仅在接收端解密，中继服务器无法窥探文件内容。
- **跨平台支持**：提供 Windows、Linux 和 macOS 的预编译二进制文件，并支持通过包管理器安装，确保不同操作系统之间的无缝互传。
- **多文件与文件夹传输**：支持一次性传输单个或多个文件，以及包含子目录的整个文件夹，保持文件结构完整。
- **断点续传**：如果传输过程中因网络中断或程序停止而中断，`croc` 可以从中止处继续传输，避免重复发送已成功传输的数据。
- **IPv6 优先与代理支持**：默认优先使用 IPv6 连接，并在 IPv6 不可用时自动回退到 IPv4。同时支持通过 Tor 等代理进行传输，满足匿名性需求。

## 技术架构

`croc` 的核心架构由三部分组成：发送端、接收端和中继服务器。

- **中继服务器**：`croc` 使用一个公共的中继服务器来协调连接。发送端和接收端通过该服务器交换连接信息和加密参数。中继服务器本身不存储文件内容，仅作为信令通道和可选的数据转发节点。
- **PAKE 协议**：传输过程采用 PAKE（Password-Authenticated Key Exchange）协议进行身份验证和密钥协商。用户在发送端生成一个随机短码（codephrase），接收端提供相同短码后才能建立连接。PAKE 协议确保即使中继服务器被攻破，攻击者也无法解密传输内容。
- **加密传输**：协商完成后，数据使用对称加密算法进行端到端加密。发送端加密文件后传输，接收端解密后写入本地磁盘，中间节点无法获取明文数据。
- **断点续传机制**：`croc` 在传输过程中记录已成功接收的数据块（chunk）的哈希值。当传输中断时，接收端向发送端报告已接收的数据范围，发送端仅重传缺失部分，避免重复发送。
- **网络穿透**：通过中继服务器和 STUN 风格的网络探测，`croc` 能够自动检测 NAT 类型并选择最优的传输路径。优先尝试直连，若失败则通过中继转发数据。

## 安装与使用

`croc` 的安装方式非常灵活，支持多种途径。

**通过脚本一键安装（Linux/macOS）：**

```bash
curl https://getcroc.schollz.com | bash
```

**通过包管理器安装：**

```bash
# macOS (Homebrew)
brew install croc

# Linux (apt)
sudo apt install croc

# Windows (Scoop)
scoop install croc
```

**使用示例：**

1. 发送端执行命令并复制生成的短码（codephrase）：
```bash
croc send /path/to/your-file.pdf
```
输出类似：`Code is: 5-panther-dolphin`

2. 接收端在另一台计算机上执行命令并输入相同的短码：
```bash
croc 5-panther-dolphin
```

系统会自动建立加密通道并开始传输文件。如果文件较大，可以添加 `-r` 参数启用压缩：
```bash
croc send --compress /path/to/large-folder
```

## 适用场景

- **个人设备间数据同步**：在办公室电脑和家庭笔记本之间快速传输文档、照片或代码仓库，无需依赖 U 盘或云盘。
- **远程团队协作**：向远程工作的同事分享大型设计文件、日志或测试数据，传输过程自带加密，避免敏感信息泄露。
- **服务器与本地环境交互**：从云服务器快速下载日志文件或备份数据到本地，即使服务器没有公网 IP 也能实现。
- **临时分享场景**：在公共场所或临时网络环境中与他人交换文件，无需连接同一个局域网或注册任何服务。

## 项目亮点

与同类文件传输工具（如 `nc`、`scp`、`magic-wormhole` 等）相比，`croc` 具备以下差异化优势：

- **零配置体验**：无需任何网络配置、端口转发或第三方服务注册，安装即可使用。相比之下，`scp` 需要双方有 SSH 访问权限，`nc` 需要手动指定端口和 IP。
- **真正的跨平台性**：预编译二进制文件覆盖所有主流操作系统，包管理器支持完善。`magic-wormhole` 虽功能类似，但依赖 Python 运行时环境，Windows 上的安装相对复杂。
- **断点续传功能**：大型文件传输中断后无需从头开始，这在网络不稳定的环境下尤其实用。许多命令行传输工具（如 `nc`）不具备此能力。
- **兼顾速度与安全**：PAKE 协议提供了强身份验证，同时中继模式保证了高成功率。与其他使用纯 HTTP 或未加密通道的工具相比，安全性和可靠性更高。
- **活跃的社区维护**：项目持续更新，近期仍有频繁的版本发布和问题修复。超过 37,000 颗星标也反映了其在开发者社区中的认可度。
