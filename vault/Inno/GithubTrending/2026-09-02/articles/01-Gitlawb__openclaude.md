## 项目概述

OpenClaude 是一款开源的编码代理命令行工具（CLI），旨在为开发者提供一个统一、终端优先的交互界面，以连接和调用各类大型语言模型（LLM）。它的核心定位是“runs anywhere, uses anything”——无论你偏好哪种云端模型服务商，还是希望完全本地运行模型，OpenClaude 都能作为你的统一入口。

该项目解决了当前 AI 编程工具碎片化的问题：开发者往往需要在不同 IDE 插件、不同厂商的专用 CLI、不同 API 服务之间切换，学习成本高且工作流难以统一。OpenClaude 将这一过程抽象为单一终端工作流，将提示词管理、工具调用、代理（Agent）逻辑、MCP（模型上下文协议）支持、斜杠命令以及流式输出整合在一起，从而让开发者专注于编码任务本身，而非底层模型接口的差异。

OpenClaude 的目标用户是重度依赖命令行工作流的中高级开发者、技术团队以及 AI 应用研究者，他们需要在一个可控、可脚本化且供应商无关的环境中使用最新的 LLM 能力。凭借超过 3 万颗 GitHub Star，该项目已获得社区广泛认可，成为该领域最活跃的解决方案之一。

## 核心功能

- **多后端模型支持**：无缝对接 OpenAI 兼容 API、Google Gemini、GitHub Models、Codex OAuth、Ollama（本地模型）以及 Atomic Chat 等，用户可自由切换无需重构上下文。
- **统一的终端优先工作流**：将提示词工程、文件上下文、工具调用和流式输出整合在一个 TUI（终端界面）中，保持开发状态的持久性和可追溯性。
- **强大的代理（Agent）与工具调用**：内置支持自主代理循环，允许模型调用外部工具（如代码解释器、Shell 命令执行）以完成复杂编码任务。
- **MCP（模型上下文协议）集成**：原生支持 MCP 标准，方便连接外部数据源和工具生态，扩展编码场景边际。
- **灵活的交互方式**：支持斜杠命令（Slash Commands）快速执行预设操作，同时提供可配置的提示词模板，提升日常操作的效率。
- **流式输出与体验优化**：以流式方式渲染模型生成内容，降低等待焦虑，并提供文本高亮、差异对比等增强显示的细节。

## 技术架构

OpenClaude 使用 TypeScript 语言开发，选择了 Node.js 运行时环境，这为其跨平台能力（Windows/macOS/Linux）奠定了坚实基础。项目在设计上遵循了高度的模块化与协议抽象原则。

其核心架构包括以下层面：

1.  **传输层抽象**：项目定义了一套统一的传输适配器接口，针对 OpenAI、Ollama、Gemini 等不同后端，都有对应的适配器模块，负责将各自的 API 请求/响应格式转换为内部标准格式。
2.  **代理执行引擎**：这是控制“思考-行动-观察”循环的核心引擎。它管理对话历史、工具注册表以及任务队列，决定何时调用用户定义的本地工具或 MCP 工具。
3.  **工具注册与执行环境**：支持动态注册自定义工具（基于 JSON Schema 定义参数），并在沙箱化（或用户指定）的本地环境中执行命令与代码，捕获输出再反馈给模型。
4.  **可持久化会话状态**：针对长会话进行状态缓存和历史快照，确保在模型切换或重启进程后，能够恢复上下文（如通过 Codex OAuth 集成实现云同步与回放）。
5.  **用户界面层（TUI）**：底层使用 Ink（基于 React）或类似的终端渲染库，实现组件化的交互布局，支持鼠标事件、快捷键绑定与异步刷新。

这种架构的显著优势是“前端统一，后端解耦”。用户既可以利用云端强大模型进行架构设计，也可切换到本地 Ollama 模型解决隐私敏感代码的处理，整个过程仅需一条命令或一个配置键，极大降低了环境切换的认知负担。

## 安装与使用

由于项目基于 Node.js 生态，推荐使用 npm 或 pnpm 进行全局安装：

```bash
# 使用 npm 全局安装
npm install -g openclaude

# 或使用 pnpm
pnpm add -g openclaude
```

**最小可用示例**

安装完成后，OpenClaude 需要至少配置一个模型后端。你可以通过环境变量指定 API 密钥，或者使用 `openclaude auth` 命令进行 OAuth 授权（如 Codex、Gemini）。

```bash
# 设置环境变量（以 OpenAI 兼容 API 为例）
export OPENAI_API_KEY="你的密钥"
export OPENAI_BASE_URL="https://api.openai.com/v1"

# 或者直接设置 Ollama（自动检测本地模型）
# export OLLAMA_HOST="http://localhost:11434"

# 启动交互式会话
openclaude
```

在交互界面中，你可以直接通过自然语言下达指令，或使用内置斜杠命令：

```text
> /model gpt-4o          # 切换当前上下文使用的模型
> 帮我介绍一下 src/ 目录结构
> /tools                  # 查看当前可用的工具列表
> /mcp connect <name>     # 连接 MCP 服务器
```

对于一次性任务，也可使用非交互式管道模式（如果版本支持）：

```bash
echo "修复 src/index.ts 中的类型错误" | openclaude --print
```

## 适用场景

- **跨模型快速对比实验**：在同一个代码任务上，开发者可以快速切换 GPT、Gemini 和本地 Llama 3 模型，从多个角度审视解决方案的优劣。
- **隐私敏感的本地开发环境**：涉及内部商业逻辑或未公开算法时，可完全连接至 Ollama 本地服务，确保代码不出内网，同时保留同样的代理工具工作流。
- **基于 MCP 的复合工具链开发**：将编码代理接入公司的内部 API 网关、知识库或 CI 日志系统，实现“故障日志分析 → 代码修复 → 提交 MR”的闭环自动化。
- **自动化脚本与 CI/CD 集成**：使用非交互模式将 OpenClaude 嵌入到 CI 流程中，作为代码审查助手或自动化文档生成器。

## 项目亮点

与市面上其他 CLI AI 工具（如 GitHub Copilot CLI）相比，OpenClaude 具备显著的差异化优势：

- **极致的供应商中立性**：项目旨在成为“唯一的终端入口”，背后连接的是整个开放生态，而非单一厂商。这规避了供应商锁定风险，并支持灰度迁移。
- **企业级 OAuth 流程**：对 Codex OAuth 的支持意味着企业可以通过标准的身份提供商（IdP）进行单点登录验证，便于在团队内审计与合规管理。
- **深度的代理能力扩展**：它不仅仅是简单的聊天补全，而是根据任务复杂度自动规划与执行工具序列，真正朝着“数字同事”的方向演进。标准化的 MCP 支持也意味着新工具的接入成本被显著压低。
- **透明的执行日志**：由于以终端为核心，所有工具调用、命令执行与输出流转均被文本化记录，便于事后回溯、调试和优化提示词。
