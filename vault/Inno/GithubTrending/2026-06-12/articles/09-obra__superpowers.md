## 项目概述

Superpowers 是一套专为编码代理设计的完整软件开发方法论，它建立在可组合的技能集合之上，并通过初始指令确保代理正确使用这些技能。该项目解决了当前 AI 编码代理在软件开发中缺乏系统性方法的问题——许多代理在收到指令后直接开始写代码，导致设计缺失、计划混乱、代码质量难以保证。目标用户包括使用 Claude Code、Codex CLI、Codex App、Cursor、GitHub Copilot CLI 等编码代理工具的开发者、团队和 AI 辅助编程实践者。

## 核心功能

- **需求澄清引擎**：代理启动后不会立即编码，而是先通过对话明确用户真正的需求，将模糊想法转化为可读的设计规格
- **分步设计审查**：将设计规格拆解为短小可读的模块，用户能够逐块阅读、消化并确认，确保方向正确性
- **实现计划生成**：基于已确认的设计，生成清晰的实现计划，遵循红/绿 TDD（测试驱动开发）、YAGNI（你不会需要它）和 DRY（不要重复自己）原则
- **子代理驱动开发**：用户批准计划后，启动子代理协同工作流程，代理们逐项处理工程任务，相互检查并审查工作成果
- **自主工作能力**：经过良好设定的代理（如 Claude）能够连续数小时自主工作，而不偏离共同制定的计划
- **多工具兼容**：支持 Claude Code、Codex CLI、Codex App、Factory Droid、Gemini CLI、OpenCode、Cursor、GitHub Copilot CLI 等主流编码代理工具

## 技术架构

Superpowers 采用分层架构设计，底层是一组可组合的「技能」（skills），这些技能定义了代理在软件开发各阶段的行为规则和工具使用方式。上层是初始指令集（initial instructions），负责在代理启动时将其引导至正确的工作流程。整个方法强调从需求 → 设计 → 计划 → 实现 → 审查的完整流水线，每个阶段都有明确的输入输出和检查点。其中子代理驱动开发模式是该架构的核心创新，通过将大型任务分解为可独立完成的小任务，并让代理之间互相监督，有效降低了单一代理认知偏差带来的风险。项目遵守 MIT 许可证，采用 Shell 语言实现其引导逻辑。

## 安装与使用

1. **克隆仓库**：
   ```bash
   git clone https://github.com/obra/superpowers.git
   ```
2. **选择目标代理工具**：根据使用的编码代理工具（如 Claude Code、Cursor 等），查阅仓库中的对应配置文件
3. **配置代理**：将 Superpowers 的指令集导入到代理工具的配置中，具体步骤因工具而异（详见仓库文档）
4. **启动开发流程**：运行编码代理，从描述软件需求开始，按 Superpowers 引导的步骤逐步完成设计、计划和实现

**最小可用示例**（以 Claude Code 为例）：
- 在 Claude Code 配置中引入 Superpowers 指令
- 启动后描述需求：例如「我想创建一个待办事项 API」
- 代理将询问具体功能、用户角色等细节
- 确认设计后，代理生成计划并启动子代理开发

## 适用场景

- **新项目启动**：从零开始构建软件时，确保设计先行、计划周详，避免早期决策错误
- **复杂功能实现**：处理需要多步骤、多模块协作的复杂功能，子代理模式可并行完成不同组件
- **代码重构与质量提升**：TDD 和代码审查环节强制保证代码质量，适合对现有项目进行系统化改进
- **团队协作标准**：为团队内的 AI 辅助编程制定统一的工作流标准，消除不同代理行为的不一致性

## 项目亮点

与同类项目相比，Superpowers 的核心差异在于其**完整的方法论而非单纯的工具**。许多 AI 编码增强工具只提供预置提示或快捷命令，但 Superpowers 定义了一套完整的从需求到交付的软件工程流程。它不依赖单一代理品牌，而是设计成可插入多种主流代理工具。子代理驱动开发模式是其特色，通过让代理之间相互审查工作，显著降低了单一代理可能产生的设计缺陷或代码错误。另外，它强调 YAGNI 和 TDD 等经典软件工程原则，确保 AI 辅助开发不会陷入过度设计或缺乏测试的陷阱。目前该项目在 GitHub 上已获得超过 22.5 万星标，且热度仍在快速增长，反映了社区对其价值的高度认可。
