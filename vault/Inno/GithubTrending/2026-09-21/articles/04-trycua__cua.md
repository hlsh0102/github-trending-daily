## 项目概述

Cua（读作 "kua"）是一个面向计算机使用代理（Computer-Use Agents）的开源基础设施项目。它的核心目标是让人工智能代理能够像人类一样操作计算机——通过观察屏幕、移动鼠标、点击按钮、输入文字来完成任务，而不是仅仅依赖 API 调用。

随着大语言模型和多模态模型的能力提升，让 AI 直接操控图形界面成为一个重要的研究方向。然而开发者在这一过程中面临几个现实障碍：缺少稳定可靠的桌面自动化底层驱动，难以在云端批量创建和管理隔离的桌面环境，以及缺乏标准化基准来评估代理的实际表现。Cua 正是针对这些问题提供了一套完整的解决方案，涵盖从底层驱动到上层评测的多个环节。

项目的目标用户包括：从事计算机使用代理研究的学术团队和实验室、需要构建 GUI 自动化产品的工程团队，以及希望在不同操作系统上批量部署和测试代理的开发者。

## 核心功能

- **开源桌面自动化驱动**：提供跨平台的计算机控制能力，包括屏幕截图、鼠标操作、键盘输入等基础原语，使代理能够与任意图形界面交互。
- **隔离云桌面（Fleets）**：支持在云端批量创建和管理隔离的虚拟桌面实例，每个代理拥有独立的操作环境，适用于大规模并行任务。
- **本地 macOS 虚拟机**：允许在本地 macOS 环境中运行虚拟化桌面，便于开发和调试，无需依赖远程云资源。
- **专用决策模型**：提供针对计算机使用场景优化的决策模型，辅助代理更准确地理解界面状态并选择下一步操作。
- **基准测试套件**：内置评测基准，用于衡量代理在真实桌面任务中的表现，支持训练、评估和数据生成三种用途。
- **跨操作系统支持**：覆盖 macOS、Linux 和 Windows 等主流平台，使代理能力不局限于单一系统。

## 技术架构

Cua 采用分层设计，将底层驱动、运行时环境和上层工具链解耦，以便各部分独立演进和替换。

最底层是自动化驱动层，直接与操作系统交互，负责屏幕捕获、输入事件模拟和窗口管理。这一层屏蔽了不同操作系统之间的差异，向上提供统一的接口。在虚拟机层面，Cua 利用虚拟化技术在隔离环境中运行完整的桌面系统，既保证了安全性，也使得多个代理实例可以并行工作而互不干扰。

云端 Fleet 部分负责编排和调度大量桌面实例，支持按需创建、销毁和监控。决策模型层则作为可选的智能组件，可以与任意代理框架集成，为界面理解和动作选择提供模型支持。基准测试模块定义了标准化的任务集合和评分规则，使得不同代理之间的比较具有可重复性。

项目主体使用 HTML 及相关 Web 技术构建部分文档和界面，同时结合系统级编程实现对桌面的底层控制。MIT 许可证使得代码可以自由用于商业和非商业用途。

## 安装与使用

由于项目涉及桌面虚拟化和系统级操作，安装过程因平台而异。一般步骤如下：

1. 克隆仓库并进入项目目录：
   ```
   git clone https://github.com/trycua/cua.git
   cd cua
   ```

2. 根据官方文档安装对应平台的依赖。macOS 用户通常需要安装虚拟化相关组件，Linux 用户需要确保内核支持 KVM 等虚拟化功能。

3. 参照文档配置环境变量，例如云桌面 API 密钥或本地虚拟机路径。

4. 启动一个最小示例：创建一个桌面实例，截取屏幕，并执行一次点击操作。具体代码示例请参考 `cua.ai/docs` 中的快速入门指南。

项目同时提供了托管服务入口（run.cua.ai），如果不想自行搭建基础设施，可以直接在云端体验 Fleet 功能。

## 适用场景

- **学术研究与论文复现**：研究人员可以使用标准基准测试评估自研代理，并与已有方法进行公平比较。
- **GUI 自动化产品开发**：工程团队可以基于 Cua 的驱动和云桌面构建 RPA 类应用，覆盖传统 API 无法触及的遗留系统。
- **代理训练数据生成**：通过在大量隔离桌面中运行代理并记录操作轨迹，可以批量生成用于模型微调的训练数据。
- **跨平台兼容性测试**：需要在多种操作系统上验证软件行为时，可以利用 Cua 的跨 OS 能力批量执行测试脚本。

## 项目亮点

与同类项目相比，Cua 的差异化主要体现在三个方面。首先，它同时覆盖了驱动层、虚拟化层和评测层，提供了端到端的能力，而多数项目只解决其中某一环节。其次，跨操作系统支持和云桌面编排使其适合规模化部署，而非仅限于单机实验。最后，内置的基准测试和专用决策模型降低了从零搭建评估体系的成本，使研究者可以把精力集中在代理策略本身。项目采用 MIT 许可证，配合活跃的社区和较为完善的文档，上手门槛相对可控。
