## 项目概述

`cloudflare/security-audit-skill` 是一个面向编码智能体（coding agent）的安全审计技能包。它的核心目标是把通用编码智能体转化为具备结构化审计能力的安全审计员：不是让单个模型一次性通读代码库并给出模糊结论，而是通过多个相互隔离的智能体分阶段协作，产出可被机器读取、且经过独立复核的安全发现。

它解决的问题主要有三个。第一，传统“让模型看代码找漏洞”的方式缺乏覆盖度控制，容易遗漏输入面或信任边界。第二，模型给出的漏洞结论往往没有独立验证，误报率高。第三，审计结果通常是非结构化的自然语言，难以进入自动化流水线或与其他工具对接。该项目通过分阶段编排、候选验证和记录级独立复核来应对这些问题。

目标用户包括安全工程师、负责代码审计的应用安全团队，以及希望把自动化安全审计接入内部流程的研发团队。该项目也是 Cloudflare 漏洞挖掘框架的雏形，仓库本身是单仓起点版本。

## 核心功能

- **六阶段结构化审计流程**：依次执行侦察、覆盖度驱动的漏洞搜寻、候选验证、结构化输出、独立记录复核和目标无关的报告生成。
- **侦察与覆盖度台账**：在 `architecture.md` 中记录架构、信任边界、输入面与既有证据，并在 `coverage-ledger.json` 中维护确定性的覆盖清单。
- **覆盖度驱动的搜寻与批评机制**：从台账单元分配相互隔离的搜寻智能体，记录其检查项，并通过“覆盖度批评者”识别未被覆盖的缺口。
- **候选验证与反驳**：每一个唯一候选发现都会交给全新的验证智能体，其任务是尝试证伪该发现，而非确认它。
- **结构化发现输出**：将 `confirmed`、`needs_validation`、`rejected` 三类记录写入 `findings.json`，并依据 `report-schema.json` 进行校验。
- **目标无关的报告生成**：从已复核的记录与覆盖数据中派生 `REPORT.md`、`FINDINGS-DETAIL.md` 与 `NEEDS-VALIDATION.md`。

## 技术架构

项目以 JavaScript 实现，主体是一套面向智能体的技能定义与编排逻辑。其设计思路可归纳为三点。

一是**角色隔离**。搜寻者、验证者、覆盖度批评者与记录复核者是彼此独立的智能体实例，避免同一上下文中的自我确认偏差。候选发现不会由提出者自己验证。

二是**以覆盖度台账为中枢**。审计过程并非线性遍历文件，而是先建立可枚举的覆盖单元，再据此分配工作并度量缺口。这使得“是否审计完整”成为一个可检查的问题，而非主观判断。

三是**记录级可验证性**。所有结论最终落到结构化记录上，并通过 schema 校验；最终报告的源声明还会由全新智能体再次独立复核，出现实质性替换时需引入另一个独立验证者。这种“验证的验证”是本项目区别于普通提示词集合的关键。

## 安装与使用

该仓库以技能形式分发，通常的接入方式是将其放置到支持技能加载的编码智能体的技能目录中，或按仓库说明将技能注册到对应运行时。基本步骤可概述为：

1. 克隆仓库：`git clone https://github.com/cloudflare/security-audit-skill`
2. 按 README 指引将技能安装或链接到你的智能体运行环境的技能路径。
3. 在目标代码仓库中触发安全审计流程，智能体会按六阶段依次执行。

最小可用示例（概念性）：

```
# 在目标仓库根目录启动编码智能体，并调用该技能
audit this repository
```

执行过程中会生成 `architecture.md`、`coverage-ledger.json`、`findings.json` 等中间产物，最终输出 `REPORT.md` 等报告文件。首次使用时建议先在小规模仓库上运行，确认智能体能够正确读写上述文件，并检查 `findings.json` 是否通过 `report-schema.json` 校验。具体命令与运行参数请以仓库 README 为准。

## 适用场景

- **内部代码库的定期安全巡检**：借助覆盖度台账，对多模块仓库进行可追踪的周期性审计。
- **上线前的安全门禁**：将结构化 `findings.json` 接入 CI，依据 `confirmed` 记录阻断高风险变更。
- **漏洞挖掘框架的原型验证**：作为单仓版本，用于在自建漏洞挖掘流水线中验证分阶段编排与独立复核机制。
- **安全团队的能力扩展**：在人力有限时，用智能体承担初步筛查与候选发现生成，再由人工复核 `needs_validation` 项。

## 项目亮点

与常见的“提示词式安全审计”方案相比，该项目的差异点在流程而非单次调用。它将审计拆分为可独立观察的阶段，使覆盖度成为显式度量对象；用证伪导向的验证者替代确认导向的自检；并通过记录级二次复核与 schema 校验保证输出可被下游系统消费。此外，该项目源自 Cloudflare 实际使用的漏洞挖掘框架，具有真实工程背景，而非纯演示性样本。
