## 项目概述

ECC 是一个面向 AI 编程代理（agent harness）的性能优化系统，定位为“代理框架操作系统”。随着 Claude Code、Codex、Opencode、Cursor 等编码代理工具在日常开发中承担越来越多任务，其运行效率、上下文利用率以及行为可靠性成为关键瓶颈。ECC 通过技能（Skills）、本能（Instincts）、记忆（Memory）、安全（Security）与“研究优先”开发范式（research-first development）五个维度的机制，对这些代理框架进行统一的能力封装与调度优化。

项目要解决的问题主要包括：代理在不同工具之间缺乏一致的技能与记忆层、重复劳动导致 token 与时间浪费、缺乏跨会话的行为积累，以及对研究资料与外部知识的利用不足。目标用户是长期使用多种编码代理的开发者、希望为团队统一代理行为的工程团队，以及需要把代理纳入 CI/自动化流程的构建者。

## 核心功能

- **Skills（技能）**：将可复用的工作流、命令与操作模式封装为可移植的技能单元，供不同代理框架调用，减少重复提示与手工配置。
- **Instincts（本能）**：提供预置的行为规则与触发条件，让代理在特定场景下自动采取更合理的默认动作，而不依赖每次显式指令。
- **Memory（记忆）**：跨会话保存上下文、决策与偏好，使代理在后续任务中复用已有信息，降低重复解释成本。
- **Security（安全）**：在代理执行命令、访问文件与调用外部服务时施加约束与审计，降低自动化操作带来的风险。
- **Research-first development（研究优先开发）**：在动手修改代码之前，引导代理先检索、阅读与验证资料，形成依据后再执行变更。

## 技术架构

项目以 JavaScript 为主要实现语言，采用模块化设计，将技能、本能、记忆与安全策略抽象为可独立配置与组合的组件。各组件通过统一的接口与代理框架适配层对接，因此可以在 Claude Code、Codex、Opencode、Cursor 等不同 harness 之间共享同一套配置与状态。

架构上强调“配置与执行分离”：技能和本能以声明式方式定义，记忆层负责持久化状态，安全层则作为执行前后的拦截与校验环节。这种设计使同一套代理行为可以在不同工具中保持一致，同时允许针对具体框架做适配扩展。项目同时提供了多语言 README（包括简体中文、日文、韩文、德文、西班牙文等），表明其希望覆盖跨语言、跨区域的开发者群体。

## 安装与使用

ECC 通常以 Node.js 生态的方式引入。基本步骤如下：

1. 确认本地已安装 Node.js（建议使用 LTS 版本）。
2. 克隆仓库：`git clone https://github.com/affaan-m/ECC.git`。
3. 进入目录并安装依赖：`cd ECC && npm install`。
4. 根据目标代理框架（如 Claude Code、Cursor），在对应配置目录中引入 ECC 的技能与本能定义。
5. 按需设置记忆存储路径与安全策略选项。

最小可用示例：在项目根目录创建或编辑代理配置文件，声明启用一个技能与一条本能规则，然后启动代理执行任务。由于 ECC 面向多个 harness，具体接入方式需参考仓库中对应框架的文档说明。

## 适用场景

- **多代理工具并行使用**：开发者在 Claude Code、Cursor、Codex 等多个工具间切换时，希望共享同一套技能与记忆。
- **团队统一代理行为**：团队需要把编码规范、命令习惯与安全约束以可版本化的形式固化，避免每位成员各自配置。
- **长期项目的上下文延续**：在跨越多个会话与多天的工作中，依赖记忆层保持决策一致性。
- **自动化流程中的代理执行**：在 CI 或脚本中调用代理时，通过安全层限制可执行操作并保留审计信息。

## 项目亮点

与单一工具内置的提示词或插件机制相比，ECC 的差异在于跨框架的一致性与分层设计：它不绑定某一个代理产品，而是把技能、本能、记忆与安全抽象为可复用组件。研究优先的开发范式也区别于“直接生成代码”的做法，更强调依据与验证。MIT 许可与多语言文档进一步降低了采用门槛，使个人与团队都能按需裁剪。
