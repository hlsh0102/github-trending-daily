## 项目概述

Hallmark 是一个专为 Claude Code、Cursor 和 Codex 等 AI 编码助手设计的 CSS 技能包，其核心目标是让 AI 生成的界面摆脱千篇一律的“AI 味”。项目由 Together AI 开发，解决了当前大语言模型在生成 UI 时普遍存在的模板化问题——所有输出看起来都像是同一套模板的不同颜色变体。Hallmark 的目标用户包括前端开发者、设计系统工程师，以及任何希望借助 AI 快速生成独特、自然、不显得 AI 生成的界面的人。

## 核心功能

- **二十种主题**：提供二十种不同的设计主题，每种主题都有独特的视觉指纹，避免重复。
- **四项动词指令**：支持 `hallmark`（默认构建新 UI）、`hallmark audit`（审计现有代码）、`hallmark redesign`（重构设计）、`hallmark study`（提取设计 DNA）四种模式。
- **57 项“废话检测”门控**：在设计生成过程中，执行 57 项规则检查，过滤掉典型的 AI 生成模式。
- **生成前自我批评**：在输出最终结果前，系统会进行自我评估，进一步排除常见的 AI 设计倾向。
- **设计 DNA 提取**：通过 `hallmark study` 命令，可以从截图或 URL 中提取设计的宏观结构、字体配对和颜色锚点，生成可移植的 `design.md` 文件。
- **快捷键切换主题**：按 `T` 键即可循环切换不同主题，方便快速预览。

## 技术架构

Hallmark 采用 CSS 作为主要载体，设计为可注入 AI 编码助手的技能包。其技术架构包含三个核心层：

1. **宏观结构选择器**：根据用户提供的设计简报，自动匹配最合适的页面布局和结构模式，而非使用固定模板。
2. **主题引擎**：内置二十组预定义的 CSS 变量集和样式规则，涵盖颜色、间距、字体、阴影等视觉属性的组合，形成不同的“设计指纹”。
3. **废话检测管道**：包含 57 个规则级门控，用于识别并拒绝 LLM 默认输出模式（如过度使用渐变、特定卡片布局、固定边距模式等）。在生成前还会执行一次自我批评环节，进一步过滤可疑模式。

整个设计强调“每一对简报与输出都是独一无二的”，而非简单的颜色替换。项目采用 MIT 开源协议，代码结构清晰，可以直接嵌入到 AI 编码助手的工作流中。

## 安装与使用

### 安装

Hallmark 的安装方式取决于使用的 AI 编码助手：

**对于 Claude Code：**
1. 克隆仓库：`git clone https://github.com/Nutlope/hallmark.git`
2. 将 `hallmark` 目录放置在 Claude Code 的技能路径中。
3. 重启 Claude Code 以加载技能。

**对于 Cursor 和 Codex：**
1. 下载仓库中的 CSS 文件。
2. 在项目中引用该 CSS 文件或通过插件系统加载。

### 最小可用示例

1. 安装完成后，在 AI 编码助手的对话中输入一个设计简报，例如：“为一个个人博客首页设计一个干净、阅读优先的界面”。
2. 等待 Hallmark 自动选择合适的宏观结构和主题。
3. 按 `T` 键循环切换主题，找到满意的视觉风格。
4. 如需审计现有代码，使用：`hallmark audit ./src/components`
5. 如想从喜欢的网站提取设计 DNA，使用：`hallmark study https://example.com`

## 适用场景

- **快速原型设计**：在项目早期阶段，需要快速生成不同风格的 UI 原型供团队评审，避免人工重复劳动。
- **设计系统探索**：当需要尝试多种视觉表达方式，但又不希望被 AI 的默认模式束缚时，Hallmark 提供了可控的多样性。
- **代码重构与美化**：现有项目界面缺乏独特性，使用 `hallmark redesign` 或 `hallmark audit` 可以识别并替换掉 AI 生成的常见模式。
- **跨工具设计搬运**：通过 `hallmark study` 将优秀设计的 DNA 提取为 `design.md` 文件，在不同 AI 工具间共享设计语言。

## 项目亮点

与其他 AI 设计工具相比，Hallmark 的核心差异化优势在于其**反套路设计哲学**。大多数工具追求让 AI 输出“好看”的界面，而 Hallmark 的目标是让 AI 输出“不像 AI 生成的”界面。它通过多项独创机制实现这一点：57 项废话检测门控确保了输出避开 LLM 的默认偏好；生成前自我批评环节强制 AI 反思自身的设计选择；宏观结构选择器而非固定模板保证了每对简报-输出的唯一性。此外，四项动词指令覆盖了从新建、审计、重构到学习的设计全流程，提供了比简单样式生成更完整的工具链。
