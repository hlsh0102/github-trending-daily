## 项目概述

llmfit 是一个用 Rust 编写的命令行工具，用于判断本地硬件能够运行哪些开源大语言模型。随着开源模型数量快速增长、参数规模与量化方式各不相同，开发者往往需要在动辄数百个模型中反复查阅显存需求、上下文长度和推理框架兼容性，才能确定某个模型是否能在自己的机器上跑起来。llmfit 将这一判断过程压缩为一条命令：它读取本机硬件信息，结合内置的模型与提供商目录，直接输出可运行的模型列表及推荐配置。

项目的目标用户包括：希望在本地部署开源模型的个人开发者、需要为团队选择合适推理模型的工程师、在边缘设备或受限硬件上评估模型可行性的运维人员，以及想要快速对比不同量化方案显存占用的研究人员。

## 核心功能

- **硬件自动探测**：识别本机 GPU 型号与显存容量、CPU 核心数、系统内存等关键指标，作为模型匹配的输入。
- **模型与提供商目录**：内置数百个开源模型的信息，覆盖主流参数规模、量化格式及多家推理提供商，无需手动维护清单。
- **适配性匹配**：根据硬件能力与模型资源需求进行比对，给出哪些模型可以运行、哪些存在风险或不可运行。
- **命令行输出**：以结构化文本形式呈现结果，便于在终端中快速浏览，也方便通过管道接入其他脚本。
- **多语言文档**：提供英文、中文、日文 README，降低非英语用户的使用门槛。
- **跨平台支持**：作为 Rust 二进制程序，可在主流桌面操作系统上编译与运行，并通过 CI 与签名流程保证发布产物可信。

## 技术架构

项目以 Rust 实现，编译为单一可执行文件，运行时无需额外的解释器或运行时依赖，这是其能够快速启动并分发的原因之一。架构上大致分为三层：硬件探测层负责采集 GPU、CPU 与内存信息；数据层维护模型与提供商目录，记录参数量、量化方式、显存占用估算等元数据；匹配层将前两者结合，依据预设的资源约束规则输出结论。

这种分层设计使得模型目录可以独立更新，而不必改动硬件探测逻辑。Rust 的类型系统与错误处理机制也让硬件探测这类易受环境影响的代码更容易保持稳定。项目通过 GitHub Actions 执行持续集成，发布产物经 SignPath 签名，Crates.io 上提供 crate 分发，说明其在工程化与供应链安全方面有一定投入。

## 安装与使用

由于项目以 Rust 编写并发布在 Crates.io，最直接的安装方式是通过 Cargo：

```bash
cargo install llmfit
```

也可以从 GitHub Releases 下载对应平台的预编译二进制文件，或克隆仓库后本地构建：

```bash
git clone https://github.com/AlexsJones/llmfit
cd llmfit
cargo build --release
```

安装完成后，在终端中运行命令即可查看本机可运行的模型：

```bash
llmfit
```

具体子命令与参数（例如筛选特定提供商、指定量化精度或输出格式）请以仓库 README 和 `--help` 输出为准。

## 适用场景

- **本地部署选型**：在购买或升级硬件前，评估现有设备能承载哪些模型，避免盲目下载数十 GB 权重后才发现显存不足。
- **团队硬件规划**：为团队统一采购推理服务器时，对照模型需求清单确定显存与内存下限。
- **量化方案对比**：在同一硬件条件下比较不同量化版本的可行性，权衡精度与资源占用。
- **边缘与受限环境**：在嵌入式设备或低功耗主机上快速判断是否存在可运行的小参数量模型。

## 项目亮点

与依赖在线服务或手动查阅模型卡片的做法相比，llmfit 的核心差异在于把硬件探测与模型目录放在同一个本地工具中完成，不需要联网查询，也不依赖特定推理框架。覆盖数百个模型与多家提供商的目录规模，使其在广度上优于多数同类脚本；Rust 带来的单文件分发与启动速度，使其适合作为日常命令行工作流中的一环。此外，项目采用 MIT 许可，发布产物经过签名，并提供多语言文档，在开放性与可信度之间取得了平衡。从社区反馈看，该项目在短期内获得了较高的关注度，反映出本地模型选型这一需求具有普遍性。
