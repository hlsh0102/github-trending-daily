## 项目概述

`i-have-adhd` 是一个面向 AI 编码助手（coding agent）的输出风格插件/技能（skill）。它要解决的问题很具体：当前主流编码助手在回答问题时，往往把真正的结论埋在一大段铺垫、复述和客套话之后，用户需要读完一大段文字才能找到可以执行的那一行命令或那一处代码修改。该项目的目标是把输出结构改为「先给答案，再给细节」：动作在最前、步骤编号、去掉“希望这对你有帮助”这类无信息量的客套话。

目标用户是日常使用 Claude Code、Cursor、Codex 等编码助手进行开发的工程师，尤其是需要在终端里快速扫读、频繁切换上下文的用户。项目名称中的 “ADHD” 是一种比喻式表达，README 明确说明「No ADHD diagnosis needed」，即任何希望减少阅读负担的人都可以使用，并不针对某一特定人群。

## 核心功能

- **答案前置**：把可执行的动作、命令或代码修改放在回复的最开头，读者第一眼就能看到该做什么，而不是先读背景说明。
- **步骤编号化**：多步操作以有序列表呈现，每步只做一件事，避免用大段散文描述流程。
- **去除填充语**：删掉“好问题！”“让我想想”“希望这对你有帮助”等对决策没有贡献的语句，缩短单次回复长度。
- **技能/插件形态集成**：以 skill 的形式接入现有编码助手，不改变模型本身，只约束输出格式。
- **多语言 README**：仓库提供简体中文、葡萄牙语、日语、越南语、韩语、泰语等多语言说明文档，降低非英语用户的理解成本。
- **安装指令自举**：README 给出的安装方式本身就是一段可以直接粘贴给助手执行的提示词，由助手读取仓库中的 `AGENTS.md` 完成安装。

## 技术架构

项目以 Python 为主要实现语言，但其核心并不是一个运行时框架，而是一组写给模型看的指令文本与配套的安装说明。从仓库结构看，`AGENTS.md` 承担了「代理可读说明书」的角色：它既是安装步骤的来源，也是运行时期望助手遵循的输出规范。这种做法的特点是把提示词工程从用户手里转移到仓库中，通过版本控制来维护风格规则，而不是让每个用户各自手写 system prompt。

由于以 skill/plugin 形式接入，项目不依赖特定模型的私有 API，理论上可移植到任何支持自定义技能或规则文件的编码助手。输出风格的判定是软约束——依赖模型对指令的遵循，而非后处理脚本，因此实现简单、无额外部署成本，但效果取决于宿主助手对规则的遵守程度。

## 安装与使用

最简安装方式是把 README 中给出的提示词直接粘贴到编码助手的命令行会话中，由助手自动完成拉取与配置：

```text
Install the i-have-adhd skill/plugin from https://github.com/ayghri/i-have-adhd, refer to the repo's AGENTS.md for instructions.
```

若需要手动安装，可参考仓库中的 `INSTALL.md`，按其说明将技能文件放到宿主助手约定的技能目录下。安装完成后无需额外调用，助手在后续回复中即会按新格式输出。

使用前后的差别可以概括为：安装前，助手可能先复述问题、解释背景、再给出修改建议；安装后，回复通常以「改哪一行、执行哪条命令」开头，其余解释退居其后。仓库 README 用 Before/After 对照表展示了这一差异。

## 适用场景

- 在终端中与编码助手结对编程，需要快速拿到命令或补丁，而不想通读解释。
- 排查报错时，希望助手直接给出下一步动作与检查点，而不是先分析所有可能原因。
- 长时间密集开发、上下文切换频繁，需要降低每次回复的阅读成本。
- 团队统一助手输出风格，把「答案前置」作为协作规范固定下来。

## 项目亮点

与常见的提示词合集相比，该项目的差异在于把风格约束做成可安装、可版本化的技能包，而不是让用户每次手动粘贴 prompt。名称本身带有传播性，README 中明确区分比喻与实际医学诊断，避免了误导。此外，项目提供多语言文档与自举式安装指令，降低了上手门槛。从数据上看，仓库在短时间内获得了较高的关注度，说明「减少助手输出冗余」是一个被广泛感知的痛点。

需要注意的是，该项目不改变模型能力，只约束表达方式；它无法保证回答本身正确，也无法在所有宿主助手中获得完全一致的格式效果。
