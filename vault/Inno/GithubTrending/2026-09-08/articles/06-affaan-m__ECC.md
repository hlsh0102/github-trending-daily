## 项目概述

ECC（Enhanced Claude Code）是一个面向 AI 编程代理（Agent）的性能优化与增强系统。它并非一个独立的 AI 模型或 IDE，而是一套为 Claude Code、Codex、Opencode、Cursor 等流行 Agent 化开发工具提供“操作系统”级能力补充的 JavaScript 框架。该项目旨在解决当前 AI 编程代理在复杂项目协作中暴露出的共性问题，例如长期记忆缺失、工具调用纪律性差、安全边界模糊以及上下文窗口利用率低下等。其目标用户是重度依赖 AI 编程助手进行生产级代码开发、并希望将这些工具从“代码补全器”升级为“可靠智能体”的开发者与技术团队。

## 核心功能

- **技能（Skills）体系**：允许开发者将特定的工作流程（如重构、代码审查、测试生成）封装为可复用的指令集，使 Agent 能够按照既定规范和最佳实践执行任务，而非每次从零推理。
- **本能（Instincts）机制**：通过预定义的行为准则与策略模板，塑造 Agent 的基础反应模式。例如，在处理数据库迁移或修改核心模块时可以自动触发安全检查，减少人工提示成本。
- **持久记忆（Memory）管理**：提供了跨会话的结构化记忆存储能力，使得 Agent 能够记住项目架构决策、用户代码偏好及历史问题的解决方案，避免在每次对话中重复沟通。
- **安全与权限控制**：内置了细粒度的允许/拒绝规则和敏感操作提示机制，防止 Agent 在无人监督时执行风险命令（如删除分支、强制推送或生产环境操作）。
- **多平台兼容层**：针对 Claude Code、Codex、OpenCode 与 Cursor 等不同 Agent 的 API 差异进行了抽象，实现了策略与技能配置的“一次编写，多处运行”。
- **研究优先开发模式（Research-First）**：提供特定的脚手架与工具链，鼓励 Agent 在执行大量代码修改前，先进行源码分析、日志查阅与架构搜索，从源头降低代码变更的破坏性。

## 技术架构

ECC 构建于 Node.js 环境之上，采用插件化与事件驱动的核心架构。其核心不直接监听模型输出，而是在 Agent 的工具调用链路之间插入一个“中间层”。该中间层能够拦截并解析来自模型端的指令流，将其与用户定义的配置进行匹配。

从数据流角度看，其设计遵循“策略与执行分离”原则。**策略层**由用户通过 JSON 或 Markdown 文件定义，包含技能、本能与安全规则。**执行引擎**负责解析这些策略，并在运行时动态注入上下文提示词或对底层 Agent API 进行包装。此外，记忆功能通过异步持久化存储实现，拥有独立的索引机制，能够将当前对话查询快速转化为记忆检索，并将重要的交互信息压缩后回写到长期存储中。

该项目的架构设计考虑到了性能开销，尽可能采用轻量级的字符串转译与映射函数，避免在关键路径上进行复杂的计算。同时，通过为不同编码工具提供适配器（Adapter），形成了松散耦合的架构，使得支持新的 Agent 工具只需编写新的适配器即可，而不必修改核心逻辑。

## 安装与使用

ECC 通常作为 npm 全局包或项目开发依赖进行安装。安装过程相对直接，假设项目已存在 `package.json`：

```bash
# 全局安装（推荐）
npm install -g @affaan-m/ecc

# 或作为项目依赖安装
npm install --save-dev @affaan-m/ecc
```

安装完成后，需要初始化配置文件以启用核心功能。运行以下命令会在项目根目录生成 `.ecc/` 配置文件目录：

```bash
ecc init
```

基础使用方式是在您的 Agent 工具（如 Claude Code）的启动流程中，先加载 ECC 的适配器。例如，在对应工具的命令行工具中，通过 Node.js 调用：

```javascript
// example-runner.js
const { createSession } = require('@affaan-m/ecc/claude');
const session = await createSession({
  cwd: process.cwd(),
  memory: { enabled: true },
  instincts: 'team-standard'
});
session.send('请重构这个模块，并处理废弃函数');
```

随后，Agent 的交互响应会自动经过 ECC 的调度。对于常规使用，您也可以在终端直接使用 `ecc run “您的指令”` 命令来快速启动一个受管制的编码会话。

## 适用场景

- **大型存量代码库的维护**：当 Agent 面对架构复杂、历史包袱重的项目时，ECC 的持久记忆与强制研究模式能确保它在修改前查阅上下文，而非盲目“猜测”代码意图。
- **团队协作与标准化治理**：技术管理者可以通过集中管理“技能”和“禁止命令”列表，统一团队成员使用 AI Agent 的编码风格与安全边界，实现团队级别的质量门禁。
- **高复杂度任务自动化**：例如涉及多文件跨模块的接口迁移、升级或大型重构，利用 ECC 的本能系统，Agent 可以按照预设的步骤分解任务，大大减少人工盯防成本。
- **受到严格监管的代码环境**：对于金融或军工行业的项目，ECC 的安全层提供了审计日志与操作阻断能力，将 Agent 的行为约束在合规的范围内。

## 项目亮点

ECC 的差异化优势首先体现在其**横向兼容性**上。相较于仅针对单一工具（如仅支持 Claude）的优化插件，ECC 构建了一个抽象层，使开发者的知识与管理策略跨越了不同 Agent 工具之间的体验割裂。

其次，其**“研究先行”的动态提示工程**优于传统的静态系统提示词。它并非简单地为每条指令附加冗长的规则文本，而是根据任务类型分阶段注入提示，保证模型在处理复杂逻辑时不丢失核心约束，从而有效降低“幻觉”出现的频率。

最后，项目在**工程治理**方面的深度，使其区别于一般的提示词集合。它提供了完整的 Node.js API 与生命周期钩子，允许开发者在事件流程中插入自定义逻辑，这种高度的可编程性满足了高级用户对深度定制的需求。
