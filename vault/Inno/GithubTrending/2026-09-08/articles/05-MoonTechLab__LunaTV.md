## 项目概述

MoonTV（在 GitHub 上以 LunaTV 仓库名发布）是一个开箱即用的跨平台影视聚合播放器，基于现代前端技术栈构建。它解决的核心问题是：用户需要在多个影视资源站点之间反复切换、搜索和播放的痛点。通过一次搜索聚合多个数据源的结果，MoonTV 将分散的影视内容统一到一个优雅的播放界面中。

该项目面向自托管爱好者、影视内容消费者以及希望拥有私人影视库但又不想依赖单一商业平台的技术用户。MoonTV 设计为一个“空壳”应用，本身不内置任何播放源或直播源，用户需要自行配置数据源，这既保证了项目的合法性边界，也赋予了使用者极大的自由度。

## 核心功能

- **多源聚合搜索**：一次搜索即可同时查询多个配置的影视数据源，并聚合返回所有结果，免去逐站查找的麻烦。
- **丰富信息详情页**：展示影片的完整元数据，包括剧集列表、演员阵容、上映年份、剧情简介等，提供接近商业流媒体平台的浏览体验。
- **流畅在线播放**：集成 HLS.js 与 ArtPlayer 播放器内核，支持常见的流媒体协议，确保播放体验的流畅性与可控性。
- **收藏与跨端进度同步**：支持将收藏列表和观看进度存储到 Kvrocks、Redis 或 Upstash（云端 Redis），实现多设备间的进度无缝续播。
- **PWA 支持**：作为渐进式 Web 应用，支持离线缓存、添加到桌面/主屏幕，在移动设备上提供接近原生应用的体验。
- **响应式界面布局**：桌面端采用侧边栏导航，移动端切换为底部标签导航，在不同尺寸的屏幕上均能提供良好的操作体验。
- **智能去广告**：内置实验性功能，可尝试自动跳过视频流中插入的切片广告，提升观看连贯性。

## 技术架构

MoonTV 的技术选型体现了现代全栈应用的设计思路。前端框架采用 **Next.js 14**，利用其 App Router 架构和服务器端渲染能力，保证了页面加载速度与搜索引擎可见性。样式方案选用 **Tailwind CSS**，配合原子化类名快速构建出高度定制化的响应式界面。整个项目以 **TypeScript** 编写，提供了强类型约束，显著提升了代码的可维护性与协作效率。

在后端与数据层面，应用没有绑定特定的 SQL 或 NoSQL 数据库，而是通过抽象层支持 **Kvrocks**（推荐）、**Redis** 或 **Upstash**。这种设计允许用户在自托管时选用轻量级的本地存储方案，或是在 Serverless 环境中使用托管服务，兼顾了性能与弹性。播放核心上，HLS.js 负责处理 HTTP Live Streaming 协议的解码与播放，而 ArtPlayer 则提供了统一、可定制且体验优秀的播放器 UI 与交互控制。

视图层采用了组件化与服务端组件（Server Components）相结合的方式，将数据获取逻辑尽量下沉到服务端，减少客户端 JavaScript 负载。项目的配置体系也考虑到了易用性，支持通过环境变量或配置文件（如 `config.js`）定义搜索数据源的 API 模板。订阅功能允许用户通过 URL 导入或更新数据源集合，使得资源管理更为动态化，配合自动更新机制，数据源可以在无需手动干预的情况下保持活跃。

## 安装与使用

MoonTV 提供了灵活的部署选项，以下是基于 Docker 的常见部署流程（使用 Kvrocks 用于数据存储）：

1.  **获取项目代码**：将仓库克隆至本地服务器。
2.  **配置文件调整**：在项目根目录的 `config.js` 或通过环境变量设定你的搜索数据源（API 地址）。这是项目运行的关键，无有效数据源则无法搜索和播放。
3.  **定义环境变量**：设置 `KVROCKS_URL`（或其他对应存储类型的链接）、`API_SECRET`（用于保护搜索 API 请求的密钥）等必要变量。
4.  **启动 Docker 容器**：执行 `docker-compose up -d` 指令，构建并启动前后端及依赖的存储服务。
5.  **访问与使用**：应用启动后，通过浏览器访问分配的端口（默认 3000）。你可以直接搜索影片，点击结果查看详情并加入播放队列或收藏夹。

最小可用示例（伪代码）：

```typescript
// 在配置中声明你的数据源 API（示例）
export const configs = {
    sources: [
        {
            name: "my-source",
            api: "https://your-source-api.com/search?wd={keyword}",
            // ... 解析规则
        },
    ],
};
```

部署完成后，你可以通过 PWA 功能将应用安装到手机桌面，享受类似于原生客户端的多渠道搜索与播放体验。

## 适用场景

- **个人影视站自托管**：适合希望拥有独立、无广告、可自定义资源来源的影视播放网站的个人或小团体。配合群晖（NAS）或 VPS 使用，可构建家庭影音中心。
- **聚合搜索需求**：用户不再需要在多个影视网站间辗转，一次搜索即可获取全网（接入源范围内）的播放结果，高效的检索体验是其核心价值。
- **多设备观看与进度同步**：得益于 PWA 与 Redis 存储设计，用户可以在客厅的电视（浏览器）上看到一半，回到卧室用手机继续播放同一集，进度无缝衔接。
- **离线部署与内网使用**：项目完全开源且可私有化部署，不依赖外部的中心化服务器（除了订阅的数据源），适合有数据隐私顾虑或需要在隔离网络环境中使用的用户。

## 项目亮点

MoonTV 的差异化特性非常鲜明。首先，它不是一个对特定网站爬虫的硬编码实现，而是一个具备订阅机制的聚合框架，用户可以通过订阅链接动态获取社区维护的、高效的解析接口，这使得其生命周期和资源扩展性远远强于普通静态爬虫项目。

其次，项目坚持非商业化的开源精神，采用 **CC BY-NC-SA** 协议，明确禁止商业化使用，这不仅保证了项目的纯粹性，也让其生态更多由技术爱好者而非商业利益驱动。

在技术体验上，**10k+ 的 Stars** 数量印证了社区的认可度。项目在 UI 打磨（响应式导航、丰富的详情页）与硬核功能（PWA 离线、去广告、跨端同步）之间取得了良好平衡。与同类项目相比，MoonTV 更像是一个开箱即用的“播放器壳”，将复杂性留给了数据源的整合，而将绝佳的用户体验留给了最终使用者。
