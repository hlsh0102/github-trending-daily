## 项目概述

**How-To-Secure-A-Linux-Server** 是一份持续更新的 Linux 服务器安全加固指南。该项目由 imthenachoman 创建并维护，旨在帮助系统管理员、运维人员以及任何需要运行 Linux 服务器的用户，系统地掌握服务器安全防护的实践方法。

该指南不仅提供一个逐步执行的安全配置清单，更重要的是它还解释每个安全措施背后的原理和威胁模型，帮助读者建立正确的安全思维。无论你是在托管的 VPS、云服务器还是本地物理机上运行 Linux，这份指南都能为你提供切实可行的安全建议。

## 核心功能

- **完整的安全加固步骤**：从 SSH 服务配置、防火墙规则到内核参数优化，覆盖服务器安全的关键领域。
- **原理与操作并重**：每个配置项都附有详细的说明，解释为什么这样做能提升安全性，以及潜在的攻击向量。
- **Ansible 自动化支持**：提供 Ansible Playbook 示例，允许用户将手动操作转化为可重复执行的自动化脚本。
- **清晰的章节结构**：按主题划分，从基础到进阶，便于读者按需查阅和分步执行。
- **版本控制与持续更新**：作为 GitHub 仓库维护，社区可贡献，安全实践随威胁演变不断改进。
- **多发行版兼容建议**：在 Ubuntu、Debian、CentOS 等主流发行版的配置差异上给出提示。

## 技术架构

该指南采用“手册式”架构，以 Markdown 文件组织内容。核心思路是：

1. **模块化设计**：每个安全领域（如 SSH、防火墙、用户管理）独立成章，读者可以按需选择要加固的部分。
2. **可操作性强**：所有配置命令和示例都基于实际服务器环境，经过验证可执行。
3. **文档与代码结合**：指南中穿插实际的配置文件修改指令，并在章末提供 Ansible 自动化配置的参考链接。
4. **渐进式学习路径**：从最基础的原则（如最小权限、纵深防御）开始，然后逐步深入到具体的配置细节。

在技术选型上，该指南不绑定特定工具，而是使用 Linux 操作系统原生工具（如 iptables/nftables、sshd、sudo 等），降低了额外依赖带来的风险。同时，它鼓励用户使用风险分级的策略，例如先在一个阶段性服务器上测试，确认无误后再应用于生产环境。

## 安装与使用

该指南不需要安装任何软件，直接在浏览器中访问 GitHub 仓库即可阅读。如果想在本地阅读或离线使用，可以克隆仓库：

```bash
git clone https://github.com/imthenachoman/How-To-Secure-A-Linux-Server.git
cd How-To-Secure-A-Linux-Server
```

**最小可用示例**（步骤摘录：加强 SSH 安全）

1. 阅读“The SSH Server”章节，理解 SSH 公钥/私钥的工作方式。
2. 使用 `ssh-keygen` 生成本地密钥对，并通过 `ssh-copy-id` 上传公钥到服务器。
3. 按照指南修改 `/etc/ssh/sshd_config`，例如：
   - 设置 `PasswordAuthentication no` 禁止密码登录
   - 设置 `PermitRootLogin prohibit-password` 禁止 root 密码登录
   - 设置 `AllowGroups ssh-users` 限制允许 SSH 登录的用户组
4. 重启 SSH 服务：`sudo systemctl restart sshd`
5. 在另一个终端窗口测试 SSH 连接确认无误后，再关闭当前连接。

## 适用场景

- **云服务器安全初始配置**：当你在 AWS、阿里云、DigitalOcean 等平台新购买一台 Linux 服务器后，可以使用该指南进行全面的初次加固。
- **自建服务的安全运维**：运维人员需要定期检查并加固现有的服务器，该指南可作为安全基线检查清单。
- **安全培训与自学**：刚入门的运维工程师或学生可以通过该教程系统学习 Linux 安全实践，理解为什么需要做这些配置。
- **合规审计准备**：在企业进行安全合规评估前，可以参照该指南逐项检查服务器配置，补充缺失的安全措施。
