## 项目概述

Code-Graph-RAG 是一个专为大型单体仓库（monorepo）设计的检索增强生成（RAG）引擎。它解决了传统 RAG 系统在处理多语言、大规模代码库时面临的上下文缺失、跨文件依赖断裂和语义理解不足等核心问题。该项目由 vitali87 发起并维护，目前已在 GitHub 上获得超过 3800 颗星，并呈现出快速增长的势头。

该项目的核心价值在于将代码库的结构化知识——包括函数定义、类声明、模块依赖、函数调用关系——显式编码为知识图谱，并在 RAG 检索过程中充分利用这一图结构。这使其不仅仅是简单地“搜索并粘贴”代码片段，而是能够理解代码间的逻辑关联，从而为开发者提供具备全局视野的代码理解。目标用户包括大型软件团队的工程师、技术负责人、AI 辅助编程工具的开发者和开源项目维护者。

## 核心功能

- **多语言代码解析**：支持 Python、TypeScript、Java、Go、Rust 等主流编程语言的语法解析，自动构建符号索引。
- **知识图谱构建**：提取代码中的函数、类、接口、模块及其调用、继承、导入等关系，生成可查询的图结构数据。
- **语义感知检索**：在检索时不仅匹配文本相似度，还利用图结构中的路径信息，优先返回与查询上下文相关的关联代码。
- **跨文件查询支持**：能够理解一个问题可能涉及多个文件中的协同变化，直接检索出跨越文件边界的完整代码上下文。
- **增量索引更新**：对仓库的改动进行增量处理，无需每次全量重建图，适合持续演进的代码库。
- **交互式代码编辑辅助**：基于检索到的结构化上下文，生成高准确率的代码修改建议，而不仅仅是代码片段。

## 技术架构

Code-Graph-RAG 采用分层架构，主要由三层组成：

**底层是代码分析层**，利用树形解析（如 Tree-sitter 或 ANTLR）对源代码进行语法分析，提取出精确的符号和引用关系。这一层屏蔽了不同语言之间的语法差异，为上层提供了统一的结构化代码中间表示。

**中间层是知识图谱存储层**，将代码分析输出的符号和关系持久化到图数据库中（目前支持 Neo4j 等兼容接口）。图中的节点代表函数、类、模块等实体，边代表调用、继承、包含和导入关系。这种显式建模方式使得复杂查询如“哪些函数调用了 `foo()` 且其中包含错误处理逻辑”成为可能。

**上层是 RAG 推理层**，接收用户的自然语言或代码查询后，先通过嵌入模型将查询向量化，同时在知识图谱上执行结构检索。系统融合两种检索结果，将图路径上的相关代码片段、关系说明和上下文一并构造为提示词，交给大语言模型（LLM）生成最终回答。图检索路径的设计过滤了无关的文本噪音，显著提升了生成内容的准确性和针对性。

架构中还包含一个独立的索引服务，负责监控仓库变更事件并触发增量重分析，从而保证图数据与真实代码的同步。

## 安装与使用

项目以 Python 包形式发布在 PyPI 上，支持 Python 3.9 及以上版本。安装过程相对简单：

```bash
pip install code-graph-rag
```

安装后，首先需要初始化配置并启动索引进程：

```bash
code-graph-rag init
code-graph-rag index --repo-path /path/to/your/monorepo
```

对于集成到现有 Python 应用中，可以使用其编程式 API：

```python
from code_graph_rag import CodeGraphRAG

engine = CodeGraphRAG(
    repo_path="./my_monorepo",
    neo4j_uri="bolt://localhost:7687",
    embedding_model="text-embedding-3-small"
)

# 索引整个仓库
engine.index()

# 执行查询
answer = engine.query("如何修改用户认证模块中的密码重置逻辑？")
print(answer)
```

对于企业或团队使用，项目提供了完整的服务端部署方案，支持 Docker 容器化部署，并可以通过 REST API 或命令行界面访问所有功能。

## 适用场景

- **大型微服务架构的跨服务代码审查**：当修改一个服务中的接口时，快速找到所有调用该接口的客户端代码，评估变更影响范围。
- **遗留系统现代化改造**：面对缺乏文档的旧项目，利用知识图谱理解系统各模块间的真实依赖关系，辅助重构决策。
- **AI 驱动的代码审查与缺陷检测**：结合 RAG 检索到的模式，让 AI 更精准地识别出跨文件的潜在缺陷，如死锁、资源泄漏等。
- **新成员快速入职学习**：新工程师通过自然语言提问“订单模块是如何实现分布式事务的”，获得包含具体实现和调用链的综合解答。

## 项目亮点

区别于其他代码 RAG 工具，Code-Graph-RAG 有几个显著优势。

首先是**真正的多语言支持**，它并非简单拼接不同语言的解析器，而是提供了统一的关系模型，使得跨语言代码的关联（如 TypeScript 前端调用 Go 后端 API）也能被有效捕获。

其次是**对图结构的深度利用**，多数 RAG 方案仅将检索结果作为纯文本拼接，而本项目在提示词构造中保留了代码的调用路径和依赖关系描述，这让模型更容易理解代码的上下文角色。

第三，**增量索引能力**非常实用，对于持续开发的大型仓库，它避免了全量重复计算的开销，降低了实际使用中的维护成本。

最后，项目在工程化上表现出色，拥有完整的 CI/CD 管线、高测试覆盖率（Codecov 跟踪）和 SonarQube 代码质量门禁，这表明其具备企业级软件应有的可靠性。
