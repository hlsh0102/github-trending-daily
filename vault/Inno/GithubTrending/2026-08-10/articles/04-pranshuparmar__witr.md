## 项目概述

witr 是一个开源的进程溯源命令行工具，回答一个看似简单却常常令人困惑的问题：“为什么这个进程在运行？”它能够将任意进程、端口、容器或文件追溯到启动它的完整链路，并支持 CLI 输出、JSON 格式导出以及交互式 TUI 界面。该项目使用 Go 语言编写，采用 Apache-2.0 许可证发布，目前已在 GitHub 上获得超过 2 万星标。

对于系统管理员、DevOps 工程师和开发者而言，witr 解决了排查服务器上“神秘进程”的痛点——无需逐个检查 systemd 单元、cron 任务或手动追踪进程树，一条命令即可还原完整的启动链条，并判断该进程的来源是否可信、是否应当保留。

## 核心功能

- **进程溯源**：输入 PID 或进程名，输出从 systemd、init、supervisor、PM2 等进程管理器到目标进程的完整链式关系，并标注每一步的父进程 ID 与启动参数。
- **端口反查**：指定一个监听端口，witr 会自动定位占用该端口的进程，并向上回溯该进程的启动来源，帮助识别意外暴露的服务。
- **容器追踪**：对于运行在 Docker 或其他容器运行时中的进程，witr 能够穿透容器边界，展示容器内进程与宿主机上容器管理进程（如 dockerd、containerd）之间的关联。
- **文件关联**：通过可执行文件路径或 PID 关联的打开文件，逆向定位启动该文件的进程链，适合排查可疑二进制或遗留守护进程。
- **交互式 TUI**：提供全屏的终端 UI，支持键盘导航逐层展开进程树、搜索过滤节点，并高亮异常或已知恶意进程的线索。
- **机器可读输出**：所有查询结果均支持 `--json` 标志输出为结构化 JSON，方便集成到监控脚本或自动化审计流程中。

## 技术架构

witr 采用 Go 编写，利用 Go 语言跨平台编译的特性，支持 Linux、macOS 与 Windows 等主流操作系统，并对各平台的原生进程信息接口进行了适配。在 Linux 上，它主要通过解析 `/proc` 文件系统获取进程状态、父进程 ID、命令行参数及环境变量，同时结合进程管理器（如 systemd 的 cgroup 信息）推断启动路径；在 macOS 上则使用 `sysctl` 与 `libproc` 接口，Windows 平台通过 Windows API 完成类似信息采集。

设计上，witr 将“数据采集层”与“链路推理层”分离：采集层负责从操作系统读取原始进程信息，推理层则基于进程父子关系、会话 ID 与进程管理器特性，构建出符合人类认知习惯的启动图谱。TUI 部分基于终端 UI 库开发，采用事件驱动模型，确保在低性能远端服务器上也能流畅交互。此外，项目内置了一个用于浏览器演示的 WebAssembly 版本，可模拟 Linux 环境进行完整的功能体验，这一设计也使得 witr 的推理引擎具备良好的可移植性。

## 安装与使用

witr 提供了多种安装方式。最直接的方式是从 GitHub Releases 页面下载对应平台的二进制文件，并放置到 `PATH` 目录中。也可以使用包管理器安装，例如在 macOS 上通过 Homebrew：

```bash
brew install witr
```

在 Linux 上，可以使用预编译的 `.deb` 或 `.rpm` 包，或者通过 `go install` 从源码构建：

```bash
go install github.com/pranshuparmar/witr@latest
```

安装完成后，最基本的用法是查询某个进程的启动来源：

```bash
# 查询 PID 为 1234 的进程
witr 1234

# 查询监听 8080 端口的进程来源
witr port 8080

# 查询容器 ID 为 abc123 的容器内进程链
witr container abc123

# 输出为 JSON 格式
witr 1234 --json
```

插入交互式 TUI 模式：

```bash
witr tui
```

在 TUI 界面中，可以使用方向键浏览进程树，按 `/` 搜索进程名或 PID，按 `Enter` 展开节点查看详细信息。

## 适用场景

- **服务器异常排查**：当发现服务器 CPU 或内存占用异常时，使用 witr 定位占用资源最高的进程 PID，并追踪其启动来源，快速区分是合法业务进程还是被入侵植入的后门程序。
- **端口冲突与安全审计**：面对“端口被占用”问题，用 `witr port` 直接查看占用该端口的进程及其父进程链，判断是否是残留的服务或恶意监听，从而决定 kill 或保留。
- **容器环境治理**：在宿主机上运行大量容器时，通过 `witr container` 追踪每个容器内部进程与宿主机容器运行时之间的关系，理清容器生命周期管理逻辑，辅助清理孤儿容器或排查容器逃逸风险。
- **配置漂移检测**：定期扫描核心服务进程的启动链，对比基线配置，及时发现因系统重启、手工修改或自动化脚本导致的服务启动方式变化。

## 项目亮点

相较于 `pstree`、`htop` 或 `lsof` 等传统工具，witr 的差异化优势体现在三个层面：第一，它提供了**完整的启动链推理**，而非仅仅展示父子进程关系，能够识别并标注 systemd、supervisor、Docker 等管理器的介入层次，直接回答“谁拉起了谁”；第二，**统一入口覆盖多类查询对象**，进程、端口、容器、文件四类查询在同一命令体系下工作，省去组合多种工具的时间；第三，**友好的输出形态**，JSON 输出适合自动化，TUI 适合人工交互，浏览器演示环境则降低了学习门槛，这些设计使得 witr 既可作为日常运维的瑞士军刀，也能融入复杂的 CI/CD 审计流程。
