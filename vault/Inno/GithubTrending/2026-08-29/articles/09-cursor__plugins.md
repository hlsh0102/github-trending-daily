## 项目概述

Cursor Plugins 是 Cursor 官方维护的插件仓库，用于承载面向开发者工具、框架和 SaaS 产品的官方插件生态。每个插件在仓库根目录下以独立目录形式存在，并包含自己的 `.cursor-plugin/plugin.json` 清单文件。该项目解决了 Cursor 编辑器在特定开发工作流中缺乏标准化、可复用扩展能力的问题，为开发者提供了从教学辅助、持续学习到代码评审、团队协作等一系列即插即用的能力扩展。目标用户是使用 Cursor 进行日常开发的软件工程师、技术团队负责人以及关注 AI 辅助编程效率的开发者。

## 核心功能

- **教学辅助**：提供技能映射、练习计划和复盘机制，帮助开发者系统化提升编程能力。
- **持续学习**：基于增量对话记录，自动更新 `AGENTS.md` 文件，只保留高信号要点，实现记忆的渐进式增强。
- **团队协作**：内置 CI、代码评审、发布、本地自动化与验证等内部团队工作流，可作为团队工程实践的标准化参考。
- **深度代码审查**：支持对分支进行“热核级”审查，涵盖安全性与正确性审计、严格的代码质量评分、并行子代理以及可选的合并就绪 PR 流程。
- **插件脚手架**：提供创建和验证新代理插件的工具，降低插件开发门槛，保证插件结构的规范性。
- **自反式 AI 循环**：实现迭代式自引用 AI 循环机制，适用于需要多轮自我反思与优化的场景。

## 技术架构

该项目基于 TypeScript 构建，采用“单仓库多插件”的目录结构设计。每个插件均为独立目录，拥有自己的 `plugin.json` 清单文件，这一设计使得插件之间相互隔离、易于独立版本控制和分发。插件清单文件定义了插件的元数据、入口和依赖关系，Cursor 编辑器可以通过统一机制读取和加载这些清单，从而实现功能的动态扩展。仓库还包含 CLI 工具用于支持插件的兼容性验证，确保插件在不同环境下行为一致。整体架构遵循“约定优于配置”原则，通过标准化的清单格式和目录布局，降低了插件开发和集成的复杂度。

## 安装与使用

要使用这些插件，首先确保你已安装最新版本的 Cursor 编辑器。然后，将本仓库克隆到本地：

```bash
git clone https://github.com/cursor/plugins.git
```

将所需的插件目录（例如 `teaching/`）复制到你的 Cursor 插件目录中，或直接在 Cursor 设置中指定插件路径。以 `create-plugin` 为例，你可以通过 CLI 快速生成一个新插件的骨架：

```bash
# 进入 create-plugin 目录
cd create-plugin
# 根据 CLI 提示运行脚手架命令（具体命令参考插件内 README）
npm run scaffold my-plugin
```

这也是一种直接体验插件开发流程的方式。生成的插件会自动包含合法的 `plugin.json` 清单文件，可立即被 Cursor 加载。

## 适用场景

- **个人技能提升**：开发者可以借助 `teaching` 插件制定阶段性学习计划，并通过复盘功能追踪学习效果，适合自我驱动的技能进阶。
- **团队工程规范落地**：`cursor-team-kit` 提供的 CI 与代码评审工作流模板，适合中小型技术团队快速建立标准化开发流程，减少重复配置成本。
- **高价值代码审查**：在合并关键分支或处理安全敏感代码时，`thermos` 插件可进行深度审查，通过并行子代理从多维度分析代码，提升代码质量保障能力。
- **Agent 行为持久化**：对于依赖 AI 助手进行长期开发的场景，`continual-learning` 能够将对话中的高价值信息沉淀到 `AGENTS.md`，实现知识库的动态演进。

## 项目亮点

与一般的插件集合不同，该仓库由 Cursor 官方维护，质量和兼容性有较高保证。其“单目录一插件”的结构使得插件可以独立演进、独立发布，降低维护成本。插件不仅覆盖常见的效率工具，还深入 AI 编程的独特领域，如自反循环和基于对话记录的持续学习机制，这是许多同类项目所不具备的。此外，`create-plugin` 脚手架的存在使得该仓库不仅是插件市场，更是一个可扩展的插件开发框架，有助于吸引社区开发者贡献新插件，形成良性生态。
