## 项目概述

Superpowers 是一套专为编码代理设计的完整软件开发方法论，它构建在一组可组合的技能之上，并辅以初始指令，确保您的代理能够正确使用这些技能。该项目旨在解决当前 AI 编码助手普遍存在的问题：代理在缺乏系统方法论指导的情况下，往往直接跳入代码编写，导致设计混乱、测试缺失、代码质量低下。Superpowers 的目标用户是所有使用 AI 编码代理的开发者，包括但不限于使用 Claude Code、Cursor、GitHub Copilot CLI 等工具的团队和个人，帮助他们将代理从“代码自动补全工具”升级为“真正的开发伙伴”。

## 核心功能

- **需求澄清与规格制定**：代理启动后不会立即写代码，而是主动与用户对话，挖掘真正的需求，并生成可读的规格文档。
- **渐进式设计审查**：将设计文档拆分为简短易读的片段，让用户在实际阅读和确认后再推进开发，避免信息过载。
- **结构化实施计划**：生成清晰的实现步骤，以“热情但缺乏判断力的初级工程师”为假设目标，确保计划简单可执行。
- **强制 TDD（测试驱动开发）**：强调真正的红/绿 TDD 流程，确保测试先行，代码实现后通过测试验证。
- **YAGNI 与 DRY 原则**：自动遵循“你不会需要它”和“不要重复自己”原则，避免过度工程化和代码冗余。
- **多代理平台兼容**：支持 Claude Code、Cursor、GitHub Copilot CLI、Gemini CLI、Codex App/CLI 等主流编码代理工具。

## 技术架构

Superpowers 采用分层架构设计。底层是一组可组合的“技能”（Skills），每个技能封装了特定的开发子任务（如编写测试、设计数据库、重构代码等）。上层是一套初始指令（Initial Instructions），这些指令指导代理在启动时加载技能集，并按照预定义的开发流程执行。项目使用 Shell 语言作为主要实现，依赖标准化的提示工程和指令编排，确保代理的行为可控且可预测。

架构的核心设计思路是“方法论先行”，即先定义工作流和原则，再通过技能实现细节。这种方法论驱动的设计使得 Superpowers 可以轻松适配不同代理平台，而无需修改核心逻辑。代理的行为由外部配置的指令集驱动，用户只需将 Superpowers 的配置注入到各自代理的启动设置中即可。

## 安装与使用

Superpowers 的使用非常简洁，无需复杂的安装过程。您只需在您选择的编码代理中设置初始指令即可。以下是几种常见代理的快速设置方法：

**对于 Claude Code**：
1. 打开或创建一个项目目录。
2. 在项目根目录放置 Superpowers 提供的指令文件。
3. 启动 Claude Code 并引用该文件。

**对于 Cursor**：
1. 打开 Cursor 设置。
2. 在“Custom Instructions”中粘贴 Superpowers 提供的指令内容。
3. 重新启动 Cursor，代理将自动采用 Superpowers 方法论。

**通用步骤**：
```
# 克隆项目（可选，用于查看详细文档）
git clone https://github.com/obra/superpowers.git

# 阅读具体代理的设置指南（位于 README 中对应的章节）
```

设置完成后，启动您的编码代理并开始一个新任务。代理会首先询问您的需求，而不是直接编写代码，表明 Superpowers 已成功激活。

## 适用场景

- **从零开始的软件开发项目**：当您需要一个 AI 代理为全新项目规划架构、编写测试和实现功能时，Superpowers 确保整个过程有条不紊。
- **代码重构与优化**：代理遵循 YAGNI 和 DRY 原则，能有效识别和消除冗余代码，同时通过 TDD 保证重构后的代码行为不变。
- **团队协作中的 AI 辅助开发**：多个开发者使用同一项目时，Superpowers 提供的结构化流程能确保代理的行为保持一致，减少协作混乱。
- **学习和实践 TDD**：对于希望掌握测试驱动开发的团队或个人，Superpowers 可作为一个自动化的教学工具，强制实施优秀的开发实践。

## 项目亮点

Superpowers 的核心差异化优势在于它将真正的软件开发方法论——而不仅仅是提示词模板——系统化地融入编码代理的工作流中。与大多数仅提供“代码生成”或“测试生成”功能的代理工具不同，Superpowers 从根本上改变了代理的工作方式：从需求分析到设计审查，再到测试驱动的实现，每一步都包含人类决策点，确保人机协作而非全盘自动化。

此外，Superpowers 的跨平台兼容性是其另一大亮点。它支持 Claude Code、Cursor、GitHub Copilot CLI、Gemini CLI 等多种主流代理工具，用户无需更换工具即可获得统一的方法论支持。这种“代理无关”的设计使得团队可以灵活切换底层工具，而开发流程保持不变。

最后，该项目强调“可读性”和“渐进式”的设计审查，解决了传统 AI 辅助开发中“生成内容过多、人类难以审查”的痛点，真正让用户从“阅读大量无用输出”中解放出来。
