## 项目概述

Superpowers 是一套为编码代理（coding agents）打造的完整软件开发方法论，构建于一组可组合的技能（skills）和初始指令之上。该项目解决了当前 AI 编程工具常见的问题：代理往往直接跳入代码编写，缺乏整体规划，导致输出质量不稳定、偏离用户意图。Superpowers 的目标用户是使用各种 AI 编码代理的开发者，包括但不限于 Claude Code、Codex CLI、Cursor 等工具的深度用户，他们希望通过结构化的流程提升 AI 代理的可控性和产出质量。

## 核心功能

- **结构化需求分析**：代理在开始编码前，会主动引导用户明确真正要解决的问题，并通过对话逐步提炼出规格说明。规格以可消化的小块形式呈现，方便用户逐段审阅。
- **可审查的设计文档**：在用户确认规格后，代理生成清晰的设计文档，包含足够的信息供用户签署批准。
- **可执行的实施计划**：设计通过后，代理制定详细的实施计划，该计划像为“热情的初级工程师”编写，强调真正的红/绿 TDD（测试驱动开发）、YAGNI（你不会需要它）和 DRY（不要重复自己）原则。
- **子代理驱动开发（Subagent-Driven Development）**：用户批准计划后，代理启动子代理进程，逐步完成每个工程任务，过程中自动检查与审查工作成果，并能持续自主工作数小时而不偏离计划。
- **多平台兼容**：支持多种主流 AI 编码代理，包括 Claude Code、Codex CLI、Codex App、Factory Droid、Gemini CLI、OpenCode、Cursor、GitHub Copilot CLI 等。

## 技术架构

Superpowers 基于 Shell 脚本实现，核心设计思路是“声明式的技能组合”。项目不依赖特定 AI 模型或服务，而是通过一套标准化的指令和工作流，在代理启动瞬间注入行为模式。其技术架构特点包括：

- **可组合技能**：将常见开发行为（如需求澄清、设计生成、测试编写）封装为独立“技能”，代理可像搭积木一样组合使用。
- **指令即代码**：方法论的核心是一组精确的指令文本，代理在初始化时读取并遵循，无需修改代理本身的代码。
- **子代理循环**：通过递归调用代理自身或利用目标代理的子进程功能，实现任务拆分与并行执行，降低单次上下文窗口压力。
- **代理无关性**：通过适配层支持不同代理平台，用户只需根据所使用的代理选择对应的启动方式。

## 安装与使用

安装 Superpowers 非常简便，基本流程如下：

1. **克隆仓库**：
   ```bash
   git clone https://github.com/obra/superpowers.git
   ```

2. **根据使用的代理执行对应脚本**：
   - 对于 Claude Code：运行 `claude` 脚本
   - 对于 Cursor：运行 `cursor` 脚本
   - 其他支持的代理同样有对应的入口脚本

3. **开始对话**：启动代理后，它不会立刻写代码，而是会询问你正在构建什么，逐步引导你完成需求定义、设计确认和计划制定。

**最小可用示例**：
```bash
# 在项目目录中
cd your-project
# 启动带有 Superpowers 的 Claude Code
/path/to/superpowers/claude
# 代理将自动开始询问你的需求
```

## 适用场景

- **复杂软件项目开发**：涉及多个功能模块、需要严格测试和审查的项目，Superpowers 的流程控制能有效减少返工。
- **团队协作中的 AI 辅助**：当开发者需要确保 AI 代理的产出符合团队标准（如 TDD、代码审查规范）时，该方法论提供统一的行为框架。
- **长时间自主开发任务**：需要代理持续数小时工作的场景，如重构、批量代码生成、集成测试编写等，子代理机制可保持任务一致性。
- **AI 编程新手引导**：对 AI 代理能力不熟悉的用户，通过规范流程可降低误用风险，逐步建立高效协作习惯。

## 项目亮点

- **专注方法论而非工具**：不绑定特定 AI 模型或平台，而是提供可复用的开发流程，适应性强。
- **人类参与的关键环节**：在需求定义和设计审批阶段强制人类参与，避免“黑箱开发”带来的失控风险。
- **子代理架构创新**：通过任务分解和子代理审查，解决了单个代理在长任务中容易偏离方向的问题。
- **开源且社区友好**：基于 MIT 许可证，鼓励用户贡献和定制，已有超过 22 万 Stars 验证其价值。
- **零依赖部署**：仅需 Shell 环境，对现有开发工作流侵入性极低。
