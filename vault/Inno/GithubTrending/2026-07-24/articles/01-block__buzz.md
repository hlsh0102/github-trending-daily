## 项目概述

Buzz 是一个开源的群体思维通信平台（hive mind communication platform），由 block 团队用 Rust 语言开发。它本质上是一个可自托管的工作空间，让人类和 AI 智能体能够在同一个“房间”里协同工作。

Buzz 解决的核心问题在于：传统的团队协作工具往往将人类和 AI 工具割裂对待，要么将 AI 作为外部插件接入，要么缺乏统一的身份和审计模型。Buzz 基于 Nostr 协议构建，将所有交互——无论是消息、反应、工作流步骤、审核批准还是 Git 事件——都视为同一种签名事件。这意味着人类和智能体在同一个日志、同一个身份模型、同一个审计轨迹下共存。

目标用户包括：需要私有化协作平台的技术团队、探索人机协作的开发组织、对去中心化协议感兴趣的社区运营者，以及希望深度掌控工作空间数据的管理者。

## 核心功能

- **统一工作空间**：通过一个 URL 进入完整的工作区，包含频道、线程、成员管理等功能，人类和智能体共享相同的交互界面。
- **原生 AI 智能体支持**：智能体以和工作空间成员相同的身份参与对话、执行任务、触发工作流，所有行为都记录在同一个事件日志中。
- **Nostr 协议驱动**：所有数据交互都基于 Nostr 签名事件，确保身份可信、消息不可篡改、审计可追溯。
- **事件日志架构**：每个消息、审批、代码审查、CI/CD 事件都作为结构化的日志条目存储，形成完整的工作流历史。
- **可自托管**：用户可以自主部署和控制自己的中继（relay），无需依赖第三方服务，数据主权完全掌握在用户手中。
- **多社区支持**：托管运营者可以通过多个域名或子域名服务多个社区，通过 URL 隔离不同工作空间的可见状态。

## 技术架构

Buzz 的技术核心建立在 Nostr 协议之上。Nostr 是一个简单的去中心化消息协议，每条消息都是一个带有签名的结构化事件。Buzz 采用了“单中继（single-relay）”架构——在一台服务器上运行一个 Nostr 中继，该中继负责处理某个特定工作空间的所有事件。

关键设计思路包括：

1. **事件溯源（Event Sourcing）**：工作空间的状态完全由事件日志决定。从频道创建到消息发送，从审批通过到代码部署，所有变更都作为不可变事件记录。这不仅提供了完美的审计能力，还支持状态重放、回滚和时间旅行调试。

2. **统一身份模型**：无论是人类账户还是智能体账户，都采用相同的 Nostr 密钥对进行身份认证和事件签名。这使得系统无需特殊对待智能体，它们只是拥有密钥对的另一个参与者。

3. **使用 Rust 实现**：Rust 语言提供了内存安全、高性能和无 GC 的运行环境，非常适合构建需要处理实时事件流和并发通信的中继服务。性能开销可控，便于在生产环境中长期运行。

4. **URL 即社区标识**：用户通过特定 URL 访问的 Buzz 实例即对应唯一的工作空间。托管运营者可以基于域名路由到不同中继，但客户端视角是统一的——URL 就是工作空间的权威标识。

## 安装与使用

Buzz 作为一个自托管应用，部署相对直接。以下是一般步骤：

1. **运行中继**：在服务器上执行 Buzz 中继二进制文件，指定配置参数（如端口、域名等）。Buzz 默认采用单中继模式，启动后即可接受客户端连接。

2. **访问工作空间**：通过浏览器打开中继的 URL，即可进入对应的工作空间。首次访问通常需要创建或导入 Nostr 密钥对。

3. **创建频道与邀请成员**：在工作空间中创建频道（如 `general`、`dev` 等），通过分享密钥或邀请链接添加人类和智能体成员。

4. **与智能体协作**：在频道中可以直接 @ 智能体，智能体会像普通成员一样响应消息、执行指令或触发自动化工作流。所有交互实时可见。

5. **集成外部事件**：通过 API 或 Webhook 将 Git 事件、CI/CD 通知等外部事件推送到特定频道，事件同样以签名形式存储。

最小示例：`buzz start --community my-team` 启动一个名为 `my-team` 的工作空间，成员通过 `https://your-server/my-team` 访问。

## 适用场景

1. **技术团队协作**：开发团队可以将 Buzz 作为日常沟通、代码审查、部署通知的聚合平台，所有事件天然形成可追溯的工作流记录。

2. **AI 辅助开发**：团队可以部署 AI 编码助手、自动审查机器人、构建代理等智能体，它们与人类共享同样的沟通渠道，不需要额外学习工具。

3. **去中心化社区运营**：开源项目或 DAO 社区可以使用 Buzz 构建私有或公开的工作空间，成员通过自持密钥参与协作，无需信任中心化服务器。

4. **监控与警报聚合**：运维团队可以将服务器告警、指标异常事件推送到 Buzz 频道，同时让自动化响应智能体在同一中进行处理。

## 项目亮点

- **真正的平等协作**：不是“工具”或“插件”，而是人类和智能体作为对等参与者共享同一个事件驱动的工作空间。这重构了人机协作的基本概念。
- **事件日志即工作流**：所有工作流状态都从事件日志中派生，不存在额外的数据库状态。这让审计、回滚和状态重建变得异常简单。
- **Nostr 原生兼容**：基于开放标准 Nostr 协议构建，理论上可以与任何 Nostr 客户端或工具互操作。这不是另一个封闭的专有平台。
- **轻量自托管**：Rust 实现带来的性能优势和单中继架构的简洁性，使得个人或小团队也能轻松部署自己的协作中继。
- **Apache 2.0 开源**：采用宽松的开源许可证，允许商业使用、修改和再分发。企业可以放心基于 Buzz 构建私有内部工具。
