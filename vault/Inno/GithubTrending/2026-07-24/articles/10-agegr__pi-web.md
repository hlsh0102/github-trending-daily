## 项目概述

Pi Web 是一个为 [pi coding agent](https://github.com/badlogic/pi-mono) 提供的本地 Web 用户界面。pi 是一个基于命令行的智能编码助手，而 Pi Web 则为其赋予了图形化操作能力。用户可以直接读取本地的 pi 会话文件，在浏览器中完成会话浏览、实时聊天、模型配置、技能管理和项目文件预览等操作，无需离开浏览器窗口。

该项目解决了纯命令行环境下交互体验不够直观的问题，尤其适合需要频繁查阅历史会话、切换模型参数或管理多个编码助手的用户。目标用户包括使用 pi 作为日常编码助手的开发者、希望从 CLI 迁移到更友好界面的新手，以及需要在团队中共享会话记录和配置的协作者。

Pi Web 与 pi CLI 共享同一套会话文件，这意味着用户在终端中启动的会话可以立即在 Web 界面中看到，反之亦然——两者完全同步，数据不割裂。

## 核心功能

- **会话浏览与管理**：自动读取本地的 pi 会话文件，以结构化列表展示所有历史会话。可快速检索、重命名、删除或导出会话，支持按时间、项目或模型标签筛选。
- **实时聊天**：在浏览器中与 pi 进行实时对话，支持 Markdown 渲染。工具调用（tool calls）会以清晰的结构化格式展示，而非原始 JSON，大幅提升可读性。
- **模型配置**：无需编辑配置文件或命令行参数，直接在 Web 界面中调整当前会话的模型参数（如温度、top-p、最大 token 数、系统提示词等），并可保存为多个预设。
- **技能管理**：为 pi 添加或管理自定义技能（skills），支持从本地文件导入、在线 SDK 或直接编写代码。技能可以按会话或全局启用。
- **项目文件预览**：在浏览器中直接查看项目源代码、文档和配置文件（支持语法高亮），无需切换到单独的编辑器中。
- **HTTP 代理支持**：通过标准的环境变量 `HTTP_PROXY` 等配置，让服务器端模型和 API 请求通过代理访问，适应企业网络或需要科学上网的场景。

## 技术架构

Pi Web 使用 **TypeScript** 作为主要开发语言，基于 Node.js 构建。其架构以本地文件系统和 HTTP 服务器为核心：

- **后端**：一个轻量级的 Express 或类似框架的 HTTP 服务器，运行在用户本地（默认端口 30141）。它负责读取/写入 `~/.pi`（或用户指定的路径）中的会话数据库、管理配置文件和技能资源，并通过 REST API 暴露能力。
- **前端**：基于现代 Web 技术（如 React/Vue 或纯 TypeScript 构建的单页应用），通过浏览器直接与后端通信。前端负责渲染聊天界面、文件树、配置面板等 UI 组件。
- **数据同步**：前端与后端间采用基于文件系统的事件通知（如 `fs.watch`）或轮询机制，确保当 pi CLI 在终端中写入新消息时，Web 界面能即时更新。
- **安全性**：默认只绑定到 `127.0.0.1`（`hostname` 选项），避免暴露到外部网络。所有数据都在本地处理，不经过任何远程服务器。

设计上坚持“本地优先”：所有会话、配置和技能数据都存储在用户本机的文件中，无需注册账号、无需云同步，保护隐私的同时也消除了网络依赖。

## 安装与使用

**无需安装，直接运行：**

```bash
npx @agegr/pi-web@latest
```

该命令会自动下载最新版本并启动 Web 服务器，然后尝试在浏览器中打开 `http://localhost:30141`。

**或全局安装：**

```bash
npm install -g @agegr/pi-web
pi-web
```

**常用选项：**

```bash
pi-web --port 8080              # 自定义端口（默认30141）
pi-web --hostname 127.0.0.1     # 仅允许本地访问
pi-web -p 8080 -H 127.0.0.1     # 组合选项
pi-web --no-open                # 不自动打开浏览器
```

环境变量同样有效（适合作为后台服务运行）：

```bash
PORT=8080 pi-web                # 设置端口
PI_WEB_NO_OPEN=1 pi-web         # 不自动打开浏览器
```

**启动后**，如果本地已有 pi 的会话文件，Web 界面会自动加载并展示。如果没有，可以立即在 Web 界面中创建一个新会话开始与 pi 对话。

**使用代理：**

```bash
HTTP_PROXY=http://127.0.0.1:7890 \
HTTPS_PROXY=http://127.0.0.1:7890 \
NO_PROXY=localhost,127.0.0.1 \
npx @agegr/pi-web@latest
```

## 适用场景

- **日常编码辅助**：开发者在使用 pi 进行代码生成、重构或调试时，通过 Web 界面查看结构化的对话记录、代码片段和工具调用结果，比终端输出更易阅读和管理。
- **团队协作与复盘**：一个项目组使用 pi 完成任务时，可将 Web 界面展示在大屏幕上或分享给同事，共同检视 AI 的推理过程和代码输出。历史会话可作为知识留存。
- **模型调参与实验**：AI 开发者或爱好者可以通过 Web 界面快速切换不同模型（如从 GPT-4 切换到 Claude-3）、调整参数，并观察同一问题在不同模型下的表现差异，无需在终端不断输入参数。
- **学习与教学**：学习如何使用 coding agent 或教授他人时，Web UI 的可视化操作降低了上手门槛。学生可以直观理解工具调用的过程和 AI 的思考链条。

## 项目亮点

- **零配置即可使用**：只需一个 `npx` 命令，无需安装、无需注册、无需配置数据库。自动读取本地现有 pi 会话，即开即用。
- **与 pi CLI 完全同步**：Web 界面与终端中运行的 pi 共享同一份会话数据。在 CLI 中发出的问题，立即可以在浏览器中查看；在 Web 上调整的模型参数，也会在后续的 CLI 交互中生效。不存在数据孤岛。
- **结构化工具调用可视化**：普通的聊天界面往往将工具调用（如执行命令、读写文件）以 JSON 形式展示，晦涩难懂。Pi Web 将其渲染为可折叠的卡片，清晰展示输入参数和返回结果，提升了可读性。
- **本地优先，保护隐私**：所有数据存储在用户本地文件系统，不经过任何外部服务器。用户完全掌控自己的数据，适合对数据安全有高要求的团队或个人。
- **支持代理环境**：通过标准的环境变量即可配置 HTTP 代理，适配公司内网或受限网络环境，无需修改代码或配置文件。
