## 项目概述

ECC（Enhanced Claude Code）是一个面向 AI 编程代理（Agent）的性能优化系统，定位为“代理操作系统的拓展层”。它主要解决当前主流 AI 编程工具（如 Claude Code、Codex、Opencode、Cursor 等）在长期运行中暴露出的核心痛点：上下文窗口有限导致的“失忆”、工具调用不够精准、安全边界模糊、以及缺乏个性化行为记忆。该项目通过为这些代理注入“技能（Skills）、本能（Instincts）、记忆（Memory）和安全（Security）”四大模块，使 AI 代理在复杂项目中表现得更像一位经验丰富、且了解你偏好的资深开发者。

该项目主要面向深度使用 AI 编程助手的开发者、技术团队负责人以及希望通过自动化提升研发效率的工程师。无论是个人项目的长期维护，还是团队协作中的代码审查与重构，ECC 都旨在成为 AI 代理的“中枢神经系统”，让工具更智能地适应你的工作流。

## 核心功能

- **技能（Skills）系统**：允许用户为代理定义高度定制化的工具调用链。不同于简单的自然语言指令，技能模块可以将多步骤的复杂操作（如“从 Issue 创建分支并生成 MR”）封装为可复用的原子命令，极大提升指令的置信度和执行效率。
- **内置与自定义本能（Instincts）**：提供一系列预设的行为“反射”，例如自动识别代码风格冲突、检测多余的 import、在提交前自动执行格式化等。同时支持用户编写自定义本能规则，让代理在无明确指令时也能采取最合理的默认行动。
- **持久化记忆（Memory）**：超越单一的会话上下文。系统会分类存储项目架构决策、用户编码偏好、易错点提醒等关键信息，并在后续对话中自动检索注入，有效解决多会话项目开发中的“冷启动”问题。
- **深度安全守护（Security）**：在文件读写、命令执行前设置额外的策略层。能够基于路径、命令风险等级或权限规则进行动态阻断与人工确认，防止代理在无意识状态下执行危险操作（如删除生产数据库或安装恶意依赖）。
- **多平台适配**：统一了 Cluade Code、Codex、Opencode、Cursor 等主流代理的配置抽象。一套规则文件即可在多款工具间迁移，无需针对各平台重复编写 Prompt 或 MCP 配置。
- **研究优先的开发模式**：内置“反思”循环机制，鼓励代理在执行代码变更前先搜索代码库、查阅最佳实践文档，并将“研究”环节的结论记录在案，从而减少盲目试错。

## 技术架构

从技术栈来看，ECC 以 JavaScript/TypeScript 为基础，构建了一套轻量级的规则引擎与状态存储适配层。其核心设计并不与特定 IDE 或 CLI 工具强绑定，而是利用各代理原生支持的指令注入、Hook 事件和配置扩展点（如 CLaude Code 的 hooks、Slash Commands）作为“底层驱动”。

架构上主要有三个关键特点：

1.  **分层配置化**：ECC 将“技能”定义为数据驱动的 Schema（包含触发条件、前置检查、执行步骤、后置验证），而“本能”定义为基于正则或语义匹配的监听规则。这种设计让非深度开发者也能通过 YAML/JSON 形式维护复杂的指令编排，而非硬编码逻辑。
2.  **上下文压缩与检索**：针对代理上下文窗口的限制，ECC 实现了记忆的存储与按需加载。通过相似度计算，仅将当前任务最可能需要的“记忆碎片”加载进 Prompt，既节省 Token，又避免无关信息对模型的干扰。
3.  **安全沙箱预检**：在执行危险操作前，会经过一个独立的验证层。该层读取用户定义的策略路由，返回“允许/拒绝/需交互确认”三种决策。该过程独立于模型推理，确保了安全策略的绝对执行和不可绕过性。

## 安装与使用

**前提条件**：已安装 Node.js (v18+)，并确保你的终端环境已初始化对应的 AI 编程工具（例如 Claude Code 已登录）。

**安装步骤**：

1. 通过 Git 克隆仓库或直接下载源码包。
   ```bash
   git clone https://github.com/affaan-m/ECC.git
   ```
2. 进入目录并安装依赖。
   ```bash
   cd ECC && npm install
   ```
3. 运行初始化脚本，根据提示选择你当前使用的代理平台（例如 `claude` 或 `codex`）。
   ```bash
   npm run init
   ```

**最小可用示例**：

在完成初始化后，系统会自动生成一个 `ecc.config.yaml` 配置文件。你可以定义一个简单的“技能”来尝试效果：

```yaml
skills:
  - name: concise_diff   # 让代理解释代码改动
    trigger: "explain change"
    steps:
      - run: "git diff HEAD~1"
      - action: "ask_model: 用三点总结上面的diff内容，要求口语化"
```

之后，在你的 AI 编程工具中直接输入“explain change”，代理便会自动提取 git diff，并按照系统预设的模板为你生成格式化总结。

## 适用场景

- **大型仓储重构**：面对超大型代码库，代理容易在重构中迷失方向。ECC 的记忆与技能系统能够锁定模块边界，确保重构操作仅影响指定范围，同时提供精准的航线指引。
- **长期非同步开发**：例如间隔数月的手工/自动维护任务。通过持久化记忆，代理能够回忆起项目特有的目录结构和命名约定，无需每次手动解释。
- **多人协作环境下的安全控制**：团队管理者可以通过策略文件统一代理解锁的安全等级，禁止任何成员激活代理的“自动提交代码至主分支”等高风险权限。
- **个人自动化工作流搭建**：将 ECC 作为个人研发的“脚本中枢”，将常规的每日站会报告、周报生成、例行测试触发均封装为代理技能。

## 项目亮点

与市面上常见的单款工具配置调优方案相比，ECC 的最大差异化在于**“平台中立”与“规则即资产”**。它不是某一个 IDE 的附属补丁，而是独立的一层大脑。这带来几个显著好处：首先，你的所有优化策略均沉淀在可版本控制（能加入 Git 仓库）的配置文件中，不再是分散在各软件设置里难以维护的人生经验；其次，它拥有 25 万 + Star 的社区基础，拥有极其丰富的内置规则库可供直接借鉴，而这通常意味着它经历了大量真实场景的检验。最后，其“记忆”功能真正解决了跨工具迁移的痛点——换一个编码工具时，你的个人偏好也能一并“搬家”。
