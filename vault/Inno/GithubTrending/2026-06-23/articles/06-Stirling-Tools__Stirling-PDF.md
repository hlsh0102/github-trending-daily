## 项目概述

Stirling PDF 是一款功能强大的开源 PDF 编辑平台，由社区维护并在 GitHub 上获得了超过 8.3 万颗星标，成为 GitHub 上排名第一的 PDF 应用程序。该项目解决了用户在日常工作中处理 PDF 文件时面临的共性问题：需要依赖外部在线服务或商业软件，导致文档隐私泄露风险高、功能受限且无法跨平台使用。Stirling PDF 允许用户通过桌面客户端、浏览器界面或自托管服务器三种方式运行，所有操作均在本地或自建服务器上完成，无需将敏感文档上传至第三方服务。目标用户包括需要日常编辑 PDF 的个人用户、关注数据安全的企业团队、以及希望通过 API 实现 PDF 处理自动化的开发者。

## 核心功能

- **50 多种 PDF 工具**：涵盖合并、拆分、签名、盖章、编辑、OCR 识别、压缩、转换等常用功能，满足绝大多数 PDF 处理需求。
- **多平台运行**：支持桌面客户端、浏览器 UI 和自托管服务器三种模式，用户可根据场景自由选择。
- **自动化与工作流**：提供无需编码的流程设计器，用户可在界面中直接创建自动化流水线；同时提供完整的 API 接口，便于程序化集成。
- **数据隐私保护**：所有处理均在本地或自建服务器完成，文档内容不会离开用户控制的环境。
- **私人 API**：自托管实例可启用私有 API 接口，支持与其他系统集成，实现自动化的 PDF 处理任务。
- **跨设备访问**：通过浏览器或桌面客户端，可在任何设备上随时随地使用相同的功能集。

## 技术架构

Stirling PDF 采用前后端分离的架构设计。前端基于 TypeScript 构建，提供现代化的用户界面和跨平台桌面客户端支持。后端核心基于 Java 开发，利用成熟的开源 PDF 处理库（如 iText、Apache PDFBox 等）实现底层 PDF 操作。项目整体以 Docker 容器化作为主要部署方式，用户可通过 Docker Compose 或 Kubernetes 等工具快速部署，同时也支持裸机安装。设计上强调模块化和可扩展性，新增工具或功能无需改动核心框架。数据存储方面，默认使用本地文件系统，用户可配置使用外部存储。安全性方面，自托管实例支持 HTTPS、认证机制和可选的私有 API 密钥，确保文档在传输和存储过程中的安全性。

## 安装与使用

### 快速启动（Docker 方式）

这是最推荐的部署方式，只需一个命令即可在本地运行：

```bash
docker run -d -p 8080:8080 stirlingtools/stirling-pdf
```

启动后，在浏览器中访问 `http://localhost:8080` 即可进入主界面。

### 其他安装方式

- **桌面客户端**：从 GitHub Releases 下载对应操作系统（Windows、macOS、Linux）的安装包，安装后即可使用。
- **裸机安装**：请参考项目文档中的手动安装指南，需安装 Java 17+ 及相应依赖。

### 最小可用示例

1. 打开浏览器，访问 Stirling PDF 实例地址。
2. 在首页工具列表中找到“合并 PDF”功能。
3. 点击“选择文件”上传 2 个 PDF 文件。
4. 调整文件顺序后，点击“合并”按钮。
5. 下载合并后的 PDF 文件。

## 适用场景

- **个人文档处理**：日常需要合并报告、拆分 PDF 页面、为扫描件添加 OCR 文字的普通用户。
- **企业文档管理**：需要内部处理合同、发票、报表等敏感 PDF 文件，但不愿将数据暴露给第三方在线服务的团队。
- **开发与自动化集成**：需要通过 REST API 将 PDF 处理功能集成到现有系统中，例如自动生成报表、批量处理电子签名等。
- **教育与科研**：需要与其他协作工具结合，处理 PDF 格式的论文、课件、实验报告等材料。

## 项目亮点

与同类 PDF 工具相比，Stirling PDF 的核心差异化优势在于：**完全开源且数据本地化**。大多数免费在线 PDF 工具要求上传文档到云端，存在隐私和安全风险；而商业软件通常价格昂贵且功能受限。Stirling PDF 在保持功能全面的同时，让用户完全掌控数据流向。其多平台支持（桌面、浏览器、服务器）和 API 接口设计，打破了传统 PDF 编辑器的使用边界。此外，社区驱动的更新机制保证了功能持续增长，目前已有 50 多种工具并持续增加。项目维护活跃，提供详细的文档、Discord 社区支持和 Docker 镜像，降低了部署和使用门槛。
