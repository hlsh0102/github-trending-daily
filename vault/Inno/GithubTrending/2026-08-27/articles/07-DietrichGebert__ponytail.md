## 项目概述

Ponytail 是一个面向 AI 代理的 JavaScript 工具库，它的核心哲学是“最优秀的代码是你从未写过的代码”。这个项目试图改变 AI 编程助手过度生成代码的现状，让它们像一位经验丰富但“懒惰”的资深开发者一样思考——在动手写代码之前，先考虑是否真的需要写这些代码。项目名称和 Logo 都刻意营造出一种“手插口袋、靠墙站着、只说一句话”的资深工程师形象，这位工程师从不炫耀技术，但总能以最少的代码解决问题。

Ponytail 的目标用户是使用 Cursor、Copilot、Claude Code 等 AI 编程工具的开发者，以及所有对 AI 生成代码质量有更高要求的人群。它解决了 AI 编程中一个普遍存在的痛点：AI 倾向于输出大量“看起来合理但实际冗余”的代码，增加了维护负担和出错概率。Ponytail 通过注入新的推理规则，让 AI 代理在编码前先进行“必要性思考”，从而显著减少生成代码量，提升代码质量。

## 核心功能

- **最小化代码生成**：Ponytail 的核心指令促使 AI 代理在响应编码请求时，优先考虑“不写代码”的选项，只有在确实需要时才生成最小化的实现方案。
- **多代理兼容**：项目宣称支持 20 多种主流 AI 代理和编程助手，包括 Cursor、Claude Code、Copilot、Windsurf 等，并提供统一的集成方式。
- **轻量级注入**：通过简单的指令或配置注入即可启用，无需修改现有工作流或训练新模型。
- **推理前置机制**：内置“思考优先”的提示框架，引导 AI 在生成任何代码之前先分析问题本质，评估是否已有现成解决方案。
- **风格定制接口**：允许开发者调整“懒惰程度”和代码风格偏好，从温和精简到极端极简，满足不同团队的文化需求。
- **无需后端服务**：所有逻辑通过提示词工程实现，不依赖外部 API 或基础设施，保证隐私和数据安全。

## 技术架构

Ponytail 本身是一个纯 JavaScript 实现的工具包，其核心机制围绕精心设计的提示词（prompt）体系构建。项目不修改 AI 模型的底层权重，而是通过系统提示词（system prompt）和上下文注入来影响代理的决策过程。这种设计借鉴了“少样本学习”和“思维链”等提示工程技巧，将资深开发者的决策模型编码为结构化的推理步骤。

架构上包含三个层次：底层是一组高度凝练的原则性指令，定义了“写过时最小修改”“删除多于添加”等核心行为准则；中间层为可选的引导性提示词，面对不同任务类型（如重构、修 bug、添加功能）提供针对性思考框架；最上层则是与各 AI 代理的适配层，负责将这些提示词以兼容的格式注入到不同代理的上下文中。

这种架构的巧妙之处在于零侵入性：它不要求在本地运行任何守护进程，也不拦截 API 调用，只是改变了发送给模型的“上下文配方”。每个适配器控制在几百行代码以内，因此维护成本极低。项目还提供了 CLI 工具，用于快速将规则注入到支持文件配置的代理（如 Claude Code 的 `.claude.md`）中。

## 安装与使用

安装 Ponytail 非常简单，它支持 npm 全局安装和直接复制配置两种方式。

```bash
# 使用 npm 全局安装
npm install -g @dietrichgebert/ponytail

# 推荐使用代理配置注入方式
bunx ponytail install cursor      # 注入到 Cursor
bunx ponytail install claude      # 注入到 Claude Code
bunx ponytail install copilot     # 注入到 GitHub Copilot
```

对于支持项目级配置文件的代理，可以直接将 Ponytail 的规则链接到项目根目录：

```
# .claude.md
@ponytail/lazy-rules
```

最小可用示例，以 Claude Code 为例：

1. 在项目根目录创建 `.claude.md` 文件；
2. 添加一行 `import Ponytail from '@dietrichgebert/ponytail'` 或直接粘贴安装时生成的规则文本；
3. 重新启动 Claude Code 会话，之后收到的任何编码请求都会先经过 Ponytail 的“必要性评估”。

对于不支持配置文件的代理，可以通过在对话开头粘贴一小段规则文本来手动启用。项目仓库中提供了适用于各类场景的模板文本，拷贝即用。

## 适用场景

**代码审查与重构**：当 AI 被要求审查一段代码时，Ponytail 会让它只标注真正需要修改的地方，而不是重写整个函数。它能精准指出“这 3 行可以删掉”或“这个函数其实没人调用”，帮助团队保持代码库整洁。

**新功能开发**：面对一个新需求，Ponytail 驱动的代理会先探索代码库中是否已有类似工具函数，或者是否有更简单的架构方案。例如，在实现一个日期格式化功能时，它可能直接建议使用 `Intl.DateTimeFormat` 而不新增任何代码。

**快速原型和脚手架**：在需要快速产出验证性原型时，Ponytail 依然会保持克制，生成最小可运行的代码骨架，避免一次引入过度设计，让开发者能迅速聚焦核心逻辑进行迭代。

**教学与代码库健康维护**：团队可以用它训练 AI 助手遵循“够用就好”的原则，避免新手开发者被 AI 生成的过度复杂代码带偏，长期维护代码库的可读性和简洁性。

## 项目亮点

Ponytail 在众多 AI 编程工具中显得特立独行。市面上多数工具的目标是生成更多代码、更快完成功能，而 Ponytail 反其道而行之，将“不写代码”视为最高效的解决方案。这种逆向思维恰好契合了资深工程师的真实工作方式——在动手前先问“是否真的需要改”。

与其他提示词优化工具相比，Ponytail 采用模块化设计，适配层独立，可轻松扩展支持新出现的代理工具。其规则文本经过反复迭代，能在保持“懒惰”的同时不牺牲功能正确性，避免了简单粗暴“少写代码”可能带来的功能缺失风险。

项目的核心优势在于它不只是一个提示词片段，而是一套可移植的“工程思维模型”。它将资深开发者几十年的经验浓缩成几条清晰规则，并让任何 AI 代理都能即时“穿上”这套思维。此外，项目还提供了可视化网站（ponytail.dev）用于交互式体验和规则定制，降低了上手门槛。
