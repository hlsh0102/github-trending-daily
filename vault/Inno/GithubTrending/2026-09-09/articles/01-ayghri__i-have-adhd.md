## 项目概述

`i-have-adhd` 是一个面向编码助手（Coding Agent）的 Skill/Plugin 项目，旨在改变 AI 编程助手回复信息的方式，使其输出更加简洁、直接、易于消化。项目的核心口号是“ADHD-friendly outputs. No ADHD diagnosis needed!”，即无论你是否真的被诊断为 ADHD，都能从中受益。

该项目解决的核心问题是：许多 AI 编码助手在回答用户问题时，倾向于长篇大论地解释背景、列出多个可能的方案、或者在结论前铺垫大量上下文。对于注意力容易分散或希望快速拿到答案的开发者来说，这种回复方式效率极低。`i-have-adhd` 通过注入特定的指令规则，强制编码助手遵循“行动优先、步骤编号、不废话”的输出风格，确保用户能第一时间看到问题的答案或解决方案。

目标用户是所有使用 AI 编程助手的开发者，尤其是那些希望减少阅读负担、快速获取关键信息的用户。项目本身不需要任何诊断，任何感到 AI 回复“太啰嗦”的人都可以直接使用。

## 核心功能

- **行动优先输出**：强制编码助手在回复的第一时间直接给出解决方案或答案，而不是先进行冗长的解释或思考过程。
- **步骤编号清晰**：将复杂操作分解为编号步骤，便于用户逐步执行，避免信息堆砌带来的混乱。
- **消除无效礼貌语**：禁止输出“Hope this helps!”、“Great question!”等客套话，减少视觉噪音。
- **简洁结论前置**：在需要解释时，先将最终结论或核心要点放在开头，再补充必要的细节。
- **示例对比说明**：项目仓库中通过“Before/After”对比展示了启用该 Skill 后 AI 回复风格的变化，让用户清晰理解改进效果。
- **多语言支持**：提供英文、简体中文、日文、韩文等全球多语言版本的说明文档，方便国际用户使用。

## 技术架构

该项目的技术实现基于编码助手（如 Claude、Cursor 等）的 Skill 或 Plugin 机制。其核心是一个包含指令规则的 `AGENTS.md` 文件或专用的 Skill 配置，当用户安装此 Skill 后，编码助手在生成回复时会自动加载并遵守其中的输出约束。

从设计理念上看，`i-have-adhd` 本质上是一种“提示词约束工程”。它并不修改编码助手底层的 AI 模型，而是通过在上下文中注入一套明确的、结构化的行为准则，利用当前大语言模型对指令的高度遵循性，来改变输出的风格与结构。这种方式的优点在于：

1. **通用性强**：可以适配不同厂商、不同架构的编码助手，只要它们支持自定义 Skill/Plugin。
2. **即时生效**：无需重新训练模型，安装后即对后续所有对话产生约束。
3. **易于维护**：项目以代码仓库形式管理，用户可自行 fork 修改规则，定制属于自己的输出偏好。
4. **轻量级**：没有复杂的运行时依赖或重型框架，仅依赖文本规则文件。

整个项目结构清晰，包含安装说明（`INSTALL.md`）、不同语言的 README 以及作为 Skill 核心的规则文件。为了让规则不流于形式，项目还通过示例对比（即 README 中的 Before/After 表格）来“校准”AI 对规则的理解，以确保实际输出风格符合预期。

## 安装与使用

安装 `i-have-adhd` 非常简单，提供了两种方式：

**方式一：通过提示词注入**

复制以下命令，粘贴到你的编码助手对话窗口中，并发送：

```text
Install the i-have-adhd skill/plugin from https://github.com/ayghri/i-have-adhd, refer to the repo's AGENTS.md for instructions.
```

**方式二：手动安装**

访问项目的 [安装指南](INSTALL.md)，按照其中针对你使用的编码助手类型的说明进行配置。

**最小可用示例**：

假设你需要编码助手帮助你修复一段 Python 代码中的 bug。未安装 Skill 时，AI 可能会回复：

> 好的，我看到你代码中有个潜在问题。首先，函数 `validate_user` 接收参数 `token`，而这里的逻辑……（此处省略 500 字背景分析）……因此，我建议你检查一下 token 是否过期。

安装 `i-have-adhd` 后，AI 的回复将变为：

1. 问题：`validate_user` 中令牌校验逻辑错误。
2. 修复：将 `if not token.is_valid()` 改为 `if token.expired()`。
3. 原因：原逻辑未处理过期状态。

## 适用场景

- **日常开发调试**：当你向 AI 咨询报错信息、逻辑 bug 或代码变更建议时，希望立刻获得可执行的具体操作，而不是被大段解释分心。
- **技术方案评审**：当你想快速了解一个复杂库或 API 用法的要点时，需要 AI 直接给出推荐做法的编号步骤，用于快速筛选可用方案。
- **学习和技术速查**：当你在代码中碰到不熟悉的函数或框架时，需要 AI 提供精炼的说明而不过度展开，以保持学习专注力。
- **多任务并行**：当同时进行多项开发任务，频繁切换上下文时，通过该 Skill 收到一键式指令，能减少理解成本，提高多任务处理效率。

## 项目亮点

与通用型编码助手或普通提示词工程相比，`i-have-adhd` 具有显著的差异化优势：

- **专门解决“回复冗长”痛点**：市面上多数优化目标是代码正确率，而该项目聚焦于沟通效率，直击 AI 对话中信息密度低的痛点。
- **行为改变可感知**：通过 README 中的前后对比，用户可以直观地看到输出风格的剧变，真正做到“所见即所得”。
- **设计极具同理心**：“No ADHD diagnosis needed!”的标语传递了包容性，将针对特定人群的优化泛化为提升所有人体验的举措。
- **实现零成本、易维护**：不同于需要复杂 API 接入或模型微调的项目，它只是一个 Skill 文件，用户可以轻松审查、修改与分享，形成社区化的最佳实践沉淀。
- **多语言支持与社区基础**：项目拥有高达 31,678 的 star 数且保持高速增长，多语言 README 展现出国际化社区的活力，证明该需求具有充分的普适性。
