## 项目概述

ECC（Enhanced Claude Code）是一个面向 AI 代理运行时的性能优化与能力增强系统。它并非某一个特定 AI 工具的插件，而是一套通用的“代理驯服框架”，旨在为 Claude Code、Codex、Opencode、Cursor 等主流 AI 编程助手注入技能（Skills）、本能（Instincts）、记忆（Memory）、安全机制（Security）以及以研究优先的开发范式。该项目将原本分散、脆弱的 AI 编码体验，整合为一个具有操作系统级控制能力的统一环境，解决了 AI 代理在复杂项目协作中普遍存在的“失忆”、“越权”与“低效”问题。

## 核心功能

- **技能系统（Skills）**：支持定义和加载可复用的专业技能包，使 AI 代理在特定任务（如代码审查、性能剖析、漏洞扫描）中表现出专家级行为，而非通用聊天式回应。
- **本能机制（Instincts）**：内置一套行为基线规则，约束 AI 在编码过程中的默认动作，例如偏好使用安全函数、强制类型检查或遵循项目特定的日志规范。
- **持久化记忆（Memory）**：为代理提供跨会话的上下文存储能力。代理可以记住你的项目决策历史、代码风格偏好以及已解决的问题模式，避免每次对话都从零开始。
- **安全围栏（Security）**：在代理执行新命令、访问文件系统或调用外部 API 时，增加可控的权限过滤与提示确认机制，显著降低 AI 误操作带来的破坏风险。
- **研究优先的开发流程（Research-first Development）**：引导代理在修改代码前先进行全面的仓库搜索与影响分析，输出结构化的研究摘要后再进行编辑，极大减少盲目修改导致的回归错误。
- **多代理前端适配**：不仅支持 Anthropic 的 Claude Code，同时兼容 OpenAI 的 Codex、通用终端代理 Opencode 与编辑器内嵌的 Cursor，实现了行为配置的“一次编写、多处运行”。

## 技术架构

ECC 采用 JavaScript 构建，其核心设计遵循“配置即代码”与“拦截器模式”。从架构上看，它分为三层：

1. **适配层**：负责对接不同的代理前端。由于各工具的 Hook 或事件流机制不同，ECC 通过统一的接口适配器将内部指令翻译为特定代理能理解的系统提示或工具调用格式。
2. **决策引擎层**：这是 ECC 的中枢，负责解释技能文件（如 Markdown 或 JSON 格式定义）、执行本能规则排序、管理记忆的读改写策略，并调用安全策略模块进行授权评估。该引擎的设计灵感来源于操作系统的调度器，对代理的每一次“工具调用意图”进行裁决。
3. **持久化存储层**：使用本地文件系统或轻量级嵌入式数据库（如 SQLite）来存储代理记忆、使用统计与安全审计日志。这种分层架构使得 ECC 在面对不同模型版本升级时，也能保持策略的稳定性。

从架构特点来看，ECC 强调轻量级侵入——它不需要修改底层大模型的权重，只运行于代理与命令行/IDE 之间的“代理运行时”地位，因此安装与卸载均较为干净，不会污染用户的代码仓库。

## 安装与使用

安装 ECC 通常需要 Node.js v18 及以上环境。在大多数情况下，你可以通过 npm 直接进行全局安装：

```bash
npm install -g @affaan-m/ecc
```

安装完成后，对于 Claude Code 用户，在项目根目录初始化：

```bash
ecc init
```

该命令会生成 `ecc.config.json` 配置文件，并激活默认的本能与技能包。以下是一个最小化的配置示例：

```json
{
  "adapter": "claude",
  "security": {
    "shell": "ask",
    "fileWrite": "allow"
  },
  "memory": {
    "enabled": true,
    "storagePath": ".ecc/memory"
  }
}
```

完成配置后，正常启动 Claude Code。ECC 会自动注入其运行时上下文。例如，当你要求代理“帮我优化数据库查询”时，ECC 会先触发记忆检索（查找之前是否讨论过类似表结构），再激活 SQL 优化技能，并依据本能检查 SQL 注入风险，最后输出带有修改建议的研究摘要。

## 适用场景

- **大型遗留代码库维护**：当代理需要理解跨越数年、涉及众多框架的老项目时，ECC 的记忆功能与仓库扫描本能可以帮助其快速定位关键业务逻辑，避免因信息过载而产生的无效输出。
- **企业级安全合规开发**：在严格监管的行业中，ECC 的安全围栏能强制代理遵循固定的操作白名单，生成符合审计要求的操作日志，从而将 AI 编程纳入合规体系。
- **多代理协同办公**：团队中同时使用 Cursor 进行日常编辑、使用 Codex CLI 进行批量重构时，ECC 通过共享同一套“记忆库”与行为规范，确保不同代理能衔接彼此的工作上下文，保持编码风格统一。
- **本地化研究驱动的二次开发**：面向开源软件进行深度定制时，ECC 引导代理优先阅读相关 Issue、决策记录（ADR）与测试代码，确保二次开发方向与上游主线不产生冲突。

## 项目亮点

与市面上琐碎的提示词管理工具或单一平台的插件相比，ECC 的差异化优势集中在三方面：

1. **跨工具一致性**：大多数优化工具绑定单一环境（如仅限 Claude Code），而 ECC 提供的控制能力与记忆格式完全抽象化，团队迁移或混合使用不同工具时，学习成本为零。
2. **行为可观测性**：ECC 不仅仅是给代理添加提示，它使得代理的决策过程（如为何调用此命令、为何略过某文件）能以“研究日志”的形式输出，使 AI 的编码过程透明、可复盘，这在同类项目中较为少见。
3. **面向未来的架构**：其技能包使用简单的 Markdown 定义，这意味着 AI 本身可以编写新的技能包来优化自己。ECC 将此称为“自治性优化循环”，为未来的代理自我升级预留了结构性空间。
