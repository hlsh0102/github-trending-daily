## 项目概述

多卡人工智能团队的 `andrej-karpathy-skills` 项目，是一个旨在直接改善 Claude Code 行为模式的轻量级开源项目。它的核心交付物，仅是一份精心编写的 `CLAUDE.md` 文件。该文件的内容源自 Andrej Karpathy 在社交媒体上对大型语言模型（LLM）在编程任务中常见缺陷的深刻观察。

该项目不依赖于复杂的插件系统或庞大的代码库，而是通过一份结构化的指令文件，为 AI 编程助手注入四条核心原则，从而解决模型在编写代码时表现出的系统性弱点。目标用户包括所有使用 Claude Code 进行日常开发的软件工程师、技术负责人，以及对 AI 辅助编程工具行为模式感兴趣的研究者。它解决的核心问题是：如何引导大模型从"盲目执行"转向"审慎协作"，从"过度设计"回归"简洁务实"。

## 核心功能

- **Think Before Coding** — 强制模型在生成代码前进行显式思考，列出可能存在的假设、混淆点，并主动向用户提问以澄清需求，而非默默执行。这一原则直接针对模型"基于错误假设直接运行"的顽疾。
- **Simplicity First** — 引导模型始终以最简方案为起点，禁止引入不必要的抽象、过度设计 API 或编写超过实际需求的行数。鼓励模型主动建议移除死代码，并在代码审查中优先考虑"删除而非添加"。
- **Surgical Changes** — 要求模型执行最小范围的代码修改，严格限制任务触及的文件和函数，避免由于"顺手清理"或"误理解"而改变与当前任务无直接关联的注释或代码逻辑，确保变更的可追溯性与安全性。
- **Goal-Driven Execution** — 确保模型理解每个任务的最终业务目标而非仅仅关注语法层面，在编写代码时主动验证其对现有代码库的认知，避免基于幻觉的假设进行编程。同时，在处理复杂的多步骤任务时，能记住高层次目标，而不迷失于局部实现细节。

## 技术架构

该项目在技术架构上体现了"以简驭繁"的设计哲学。它并未依赖特殊框架或外部依赖库，而是巧妙的利用了 Claude Code 对 `CLAUDE.md` 文件的原生支持机制。该文件作为项目级的指令集，在 Claude Code 每次会话开启时被自动加载，相当于为模型提供了一个"行为指南"或"提示词前缀"。

其设计思路在于将 Andrej Karpathy 的抽象观察（如过度复杂化、错误假设、连带修改）转化为可操作的、结构化的指令语句。这种基于**上下文注入**的架构，具备零侵入性、普适性和易于测试的特点。开发者不需要学习新的配置语言，也不需要构建复杂的工具链，只需将文件放入项目根目录即可生效。整个项目的"代码"是纯文本的，但逻辑针对性与语言模型的提示敏感性进行了高度适配，通过清晰的排版和条目式内容，使得模型能够高效地解析并遵守这些规则。

## 安装与使用

要使用这一指南，你只需完成一次文件复制操作，然后即可体验其带来的行为变化。

**安装步骤**

1.  克隆项目到本地 (或直接拷贝文件)。
2.  将 `CLAUDE.md` 文件从仓库中复制到你的目标项目根目录。
3.  确保你使用的 `claude-code` 命令行工具已正确安装和登录。

```bash
# 假设你的项目名为 my-awesome-app
curl https://raw.githubusercontent.com/multica-ai/andrej-karpathy-skills/main/CLAUDE.md -o CLAUDE.md
```

**最小可用示例**

将文件放入项目后，启动 Claude Code 并交给它一个复杂任务，例如"重构此项目中负责用户登录的模块，提高其可读性"。

启用规则前：模型可能直接开始重写整个文件，引入新的类结构和设计模式，并可能删除一些注释，不考虑全局影响。

启用规则后：模型会在开始前输出类似以下的响应："我注意到现有登录模块中 `login()` 函数包含了过多的逻辑，但我需要先确认几点：1. 是否部分异常处理逻辑在其他地方也有使用？2. 根据 Simplicity First 原则，我将主要整理条件判断顺序，不做大规模抽象。我计划只修改 `auth.py` 文件中的两处函数，不触碰测试代码注释，这是否符合您的预期？"

## 适用场景

- **大型项目维护与重构**：当代码库庞大且脆弱时，`Surgical Changes` 原则能有效减少模型在修改代码时引入的非预期副作用，保证重构的安全边界。
- **团队协作开发**：当一个团队多人使用 AI 辅助编程时，统一的 `CLAUDE.md` 文件能确保所有模型输出保持一致的质量标准，减少相互间的代码风格冲突和逻辑误解。
- **自动化代码审查与 Bug 修复**：在需要 AI 独立解决深层 Bug 的场景，`Think Before Coding` 和 `Goal-Driven Execution` 能够帮助模型识别问题的真正根源，而不是停留在表面现象的修补，提升修复成功率。
- **作为新项目初始化的即时引导**：在项目第一天就加入此文件，能够从源头遏制"AI 垃圾代码"的累积，避免项目在演进过程中陷入技术债务。

## 项目亮点

- **极致的轻量化与简洁性**：与那些动辄数十个文件、依赖复杂依赖关系的大型 Agent 框架相比，这个项目仅由一个文件构成，透明度极高，维护成本趋近于零——任何人都可以快速审查并调整其中的规则。
- **源自前沿的实践洞察**：该项目的价值并不仅在于代码，更在于其知识浓缩过程。它直接提炼自全球顶尖 AI 研究者 Andrej Karpathy 的一手观察，确保了规则的针对性和有效性，解决了该领域中被广泛讨论但尚未被系统性解决的核心痛点。
- **广泛的适用性与可迁移性**：虽然目标指向 Claude Code，但其原则（如最小惊讶、最小变更）与通用软件工程理念高度一致。用户可以轻松借鉴此文件中的自我设问逻辑，将其内化为自己的工作习惯或用于配置其他 AI 编程工具。
