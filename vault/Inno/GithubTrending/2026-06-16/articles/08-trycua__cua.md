## 项目概述

Cua 是一个面向计算机操作型（Computer-Use）AI 代理的开源基础设施项目。该项目致力于提供一套完整的工具链——包括沙箱环境、SDK 和基准测试框架——来帮助开发者训练和评估能够像人类一样控制完整桌面环境（macOS、Linux、Windows）的 AI 代理。Cua 的目标用户包括 AI 研究员、机器学习工程师、自动化工具开发者，以及任何希望在真实操作系统层面上构建或测试自主代理能力的团队。通过开放源代码和标准化基础设施，Cua 降低了进入计算机操作型 AI 领域的门槛，使得从研究原型到生产部署的过渡更加顺畅。

## 核心功能

- **多桌面沙箱环境**：提供隔离的虚拟桌面环境，支持 macOS、Linux 和 Windows 三大操作系统，允许 AI 代理在安全可控的沙箱中执行任意桌面操作，包括点击、拖拽、键盘输入和文件管理等。
- **跨平台客户端与 SDK**：提供统一的 Python SDK 和 CLI 工具，开发者可以用少量代码启动一个计算机使用代理，并将其连接到目标桌面环境。SDK 封装了底层视窗系统交互和输入设备模拟的复杂性。
- **内置基准测试套件**：项目附带一套标准化基准测试场景和评估指标，用于衡量代理在真实桌面任务（如安装软件、填写表单、爬取信息）上的表现，支持结果复现和对比。
- **桌面遥测与行为记录**：在代理运行期间，自动记录鼠标移动、点击屏幕截图、键盘事件等全流程行为数据，便于调试、回放和分析代理决策过程。
- **多代理协作支持**：允许多个代理在同一个桌面环境中并行工作或分工配合，模拟团队协作场景，适用于复杂的自动化流程编排。
- **可插拔模型后端**：支持接入 OpenAI、Anthropic、本地开源模型等多种 LLM（大型语言模型）后端，开发者可以选择或自行训练最适合特定任务的行为策略模型。

## 技术架构

Cua 采用分层架构设计，将桌面控制、AI 推理层和用户接口清晰分离。底层是桌面交互引擎（Cua Desktop Engine），它通过操作系统的 Accessibility API（macOS 的辅助功能接口）、X11/Wayland 协议或 Windows UIA 来获取屏幕元素结构并模拟用户输入。该引擎运行在轻量级虚拟机或容器内，确保代理操作不影响宿主系统，同时提供硬件级输入和显示捕获性能。

中间层是 Cua SDK，它封装了桌面引擎的所有原始操作，并提供高级抽象，例如“点击按钮”、“输入文本”、“等待元素出现”等语义化动作。SDK 内部维护一个实时更新的 DOM 树（桌面元素结构树），并将截图和 DOM 信息以结构化格式传递给上层的 AI 推理模块。

上层是 AI 代理运行时，负责接收用户任务指令，将任务拆解为一系列原子操作，调用下层 SDK 执行并观察结果。运行时支持热替换策略模型，通过规划-执行-观察（Plan-Execute-Observe）循环实现自适应行为。所有运行数据（截图、动作序列、反馈结果）都会被序列化并存入可选的本地或远程存储后端，用于后续分析和训练模型微调。

项目整体采用模块化设计，核心组件之间通过 gRPC 或 WebSocket 通信，因此可以轻松地将桌面引擎部署在远程服务器上，而 AI 推理部分在本地或云端运行，适应不同的部署规模和隐私要求。

## 安装与使用

**前提条件**：确保系统中已安装 Python 3.10 或更高版本，并且已安装 Docker（用于沙箱桌面环境）。

**步骤一：安装 Cua SDK**
```bash
pip install cua
```
或者从源代码安装：
```bash
git clone https://github.com/trycua/cua.git
cd cua
pip install -e .
```

**步骤二：启动沙箱桌面环境**
```bash
cua desktop create --os ubuntu:22.04
```
该命令会在 Docker 容器中启动一个功能完备的 Linux 桌面，并自动映射端口供 SDK 连接。

**步骤三：编写一个最小代理示例**
```python
from cua import ComputerAgent

# 连接到本地沙箱桌面
agent = ComputerAgent(desktop="local:5900")

# 给代理分配一个任务
agent.run("打开 Firefox 浏览器，访问 google.com，在搜索框中输入 'cua ai' 并按下回车")

# 查看执行回放
agent.replay_last_session()
```

上述代码中，`ComputerAgent` 会自动调用背后配置的 LLM（默认为 openai/gpt-4o，你需要通过环境变量 `OPENAI_API_KEY` 提供密钥），规划并执行一系列桌面操作。执行完毕后可以通过 `replay_last_session()` 以视频或截图序列的形式查看代理的每一步操作。

## 适用场景

- **自动化测试与质量保证**：QA 团队可以利用 Cua 构建能自动完成软件安装、配置、GUI 交互测试的代理，覆盖多种操作系统，显著提高回归测试效率。
- **研究型 AI 代理开发**：研究机构可以使用项目的基准测试套件和沙箱环境，快速迭代和评估新的计算机操作型模型，并在统一标准下对比不同策略的性能。
- **业务流程自动化（RPA 升级版）**：企业可以将 Cua 与内部系统集成，部署能够处理传统 RPA 难以应对的、需要视觉理解和灵活决策的桌面流程，例如不明结构的旧式 ERP 系统操作。
- **教育与培训**：在教学场景中，Cua 的可记录回放功能可以被用来展示 AI 如何决策，或者让学生观察不同模型在同样任务上的行为差异，加深对 AI 代理原理的理解。

## 项目亮点

与同类项目（如传统的 RPA 工具或简单的 GUI 测试框架）相比，Cua 的差异化优势在于其面向 AI 原生设计。传统工具通常要求开发者硬编码操作流程，而非通过自然语言指令驱动；而 Cua 从底层开始就假设后端的操作策略是一个可训练、可替换的 AI 模型，因此提供了标准化的训练数据采集和回放机制。此外，Cua 是开源且跨平台的，避免了供应商锁定和单一操作系统的限制；其沙箱环境的设计也让用户可以在不污染真实工作机的前提下进行风险试验。项目活跃的社区（Discord 和 Twitter）和快速增长的趋势也侧面印证了其技术方案的受欢迎程度。
