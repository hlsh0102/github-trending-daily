## 项目概述

Buzz 🐝 是一个基于 Nostr 协议的自托管协作平台，核心理念是“让人类与 AI 代理在同一个工作空间中共同构建”。它解决了传统团队协作工具中人与自动化流程割裂的问题——在 Buzz 中，人类成员和 AI 代理共享同一批频道、消息和事件流，彼此之间没有身份或权限上的本质差异。

该项目使用 Rust 编写，以 Nostr relay 为核心架构，将所有团队活动（消息、反应、工作流步骤、审批、Git 事件）统一表示为签名事件。目标用户包括：需要私有化部署协作平台的技术团队、希望在协作流程中深度集成 AI 代理的开发者，以及对数据主权有要求的组织。

## 核心功能

- **统一事件日志**：所有交互（消息、审批、工作流触发、代码事件）均为 Nostr 签名事件，形成单一、可审计的日志。
- **人机同室协作**：AI 代理与人类成员拥有相同的事件模型和身份体系，可以自然地参与频道讨论、执行任务、更新状态。
- **URL 即工作区**：每个社区（Community）由 URL 唯一确定，用户通过 URL 直达对应工作区，状态完全隔离。
- **自托管部署**：支持单 relay 部署，用户完全掌握数据与基础设施。
- **项目频道与线程**：针对项目协作优化的频道结构，支持线程化讨论与发布计划协调。
- **签名审计轨迹**：每个事件都有密码学签名，提供完整、不可篡改的协作历史。

## 技术架构

Buzz 的核心是一个 **Nostr relay 服务器**，使用 Rust 实现，强调性能与安全性。架构设计的核心原则是“同一形状、同一身份模型、同一审计轨迹”——无论事件来自人类还是代理，都使用完全相同的协议格式和验证机制。

在单 relay 部署模式下，relay URL 即社区标识，所有租户可见状态均限定在该 URL 之下。这种设计简化了部署模型，同时保留了多社区托管的扩展可能（运营方可通过不同域名映射多个社区）。事件流采用 Nostr 的 `kind` 和 `tag` 机制进行结构化组织，支持频道、线程、工作流状态等复杂业务语义。由于所有状态都通过签名事件表达，系统天然具备可恢复性和可验证性。

## 安装与使用

Buzz 提供标准的 Rust 服务部署方式。以下为基本步骤：

1. **获取源码**
   ```bash
   git clone https://github.com/block/buzz.git
   cd buzz
   ```

2. **构建二进制**
   ```bash
   cargo build --release
   ```

3. **配置并启动 relay**
   ```bash
   # 按需编辑配置文件（如端口、域名、存储路径）
   ./target/release/buzz --config buzz.toml
   ```

4. **访问工作区**
   启动后，通过浏览器访问配置的 URL（如 `http://localhost:8080`）即可进入你的 Buzz 社区。在该 URL 下创建频道、邀请成员（包括 AI 代理）并开始协作。

最小可用示例：两个人类成员加一个 AI 代理在同一个项目频道中讨论发布计划，代理通过 API 监听频道事件，自动更新任务状态并回复结果——所有操作都以签名事件形式记录在 relay 日志中。

## 适用场景

- **私有团队协作**：对数据隐私有严格要求的企业内部项目协作，希望完全掌控数据存储与访问。
- **AI 原生研发流程**：团队希望在代码审查、发布管理等流程中嵌入 AI 代理，且要求代理的操作可审计、可回溯。
- **多组织隔离托管**：运营方需要为多个客户或项目组提供独立的、URL 隔离的协作环境。
- **去中心化协作实验**：利用 Nostr 生态，构建跨组织或跨地域的、基于开放协议的协作网络。

## 项目亮点

与 Slack、Discord 等传统团队协作工具相比，Buzz 的差异化优势明显：

- **AI 是一等公民**：代理不是通过“机器人”API 附加的，而是与人类完全对等的协议参与者，这简化了集成并增强了可信度。
- **统一事件溯源**：所有操作（包括人类行为和 AI 行为）都进入同一签名日志，天然支持审计、回放和恢复，而传统工具往往需要额外的审计插件。
- **协议开放**：基于 Nostr 标准，不锁定在私有 API 中，用户保有数据迁移和互操作的自由。
- **Rust 性能与安全**：核心实现使用 Rust，提供内存安全、高并发能力和低资源占用，利于自托管部署。
