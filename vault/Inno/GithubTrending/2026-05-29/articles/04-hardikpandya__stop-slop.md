## 项目概述

Stop Slop 是一个专门用于去除 AI 生成文本中“机器味”的技能文件。它针对 AI 写作中常见的固定短语、结构套路和句式惯习，提供了一套系统性的检测与清除规则。该项目面向所有希望让 AI 输出更自然、更人性化的写作者、编辑和开发者，无论是直接使用 Claude 进行对话式写作，还是通过 API 集成文本生成功能，都能从中受益。

## 核心功能

- **短语过滤**：识别并移除包括“清嗓子式”开场白、强调语气词、商业术语、所有副词、模糊表意句以及原评论性表述在内的多种 AI 典型用语。具体清单见 `references/phrases.md`。
- **结构排除**：检测二进制对比、否定罗列、戏剧化碎片句、修辞设问、虚假主体、旁观者视角叙事以及被动语态等结构陷阱。详细规则保存在 `references/structures.md`。
- **句子级规范**：禁止以 Wh-开头的句子、禁止使用破折号、禁止断续式碎片写作、禁止懒散极端表述，强制使用主动语态。
- **评分系统**：提供 1–10 分的多维度评分体系，涵盖短语、结构、句子三个层面，帮助用户量化文本的自然度。
- **多场景适配**：支持 Claude Code 技能加载、Claude 项目知识库注入、自定义指令粘贴以及 API 系统提示嵌入四种使用方式。
- **零外部依赖**：整个技能以纯文本文件形式存在，无需安装任何额外软件或运行环境。

## 技术架构

项目采用轻量级的技能文件架构，核心目录结构清晰：

- `SKILL.md` 作为总控制文件，定义检查规则、评分维度和操作流程。
- `references/` 目录存放三个支撑文件：
  - `phrases.md`：按类别列出需删除的短语库。
  - `structures.md`：描述应避免的段落和篇章结构模式。
  - `examples.md`：提供改造前后的对比样例，帮助用户理解规则的应用边界。
- 所有规则均以自然语言书写，不依赖任何编程语言或解析器，任何支持文本上下文的 LLM 均可理解并执行。

这种设计本质上是一种“语体约束体系”，通过穷举 AI 常用但读者容易识别的模式来降低文本的机械感。它与常见的提示词优化不同——后者往往更强调“写什么”，而 Stop Slop 更关注“不写什么”。

## 安装与使用

**Claude Code 用户**：将项目文件夹直接添加到 Claude Code 的 skills 目录下。

**Claude Projects 用户**：在项目知识库中上传 `SKILL.md` 以及 `references/` 目录下的三个参考文件。

**自定义指令用户**：从 `SKILL.md` 中复制核心规则（如句子级规范和评分维度）粘贴至自定义指令栏。

**API 用户**：在系统提示中嵌入 `SKILL.md` 的内容。注意：参考文件可按需加载，比如仅在需要详细检查时才引用 `phrases.md`。

最小可用示例（以 API 方式为例）：

```
system: 你要严格遵循以下规则对用户的文本进行改写。
[粘贴 SKILL.md 内容]
user: 请改写这段话：”毫无疑问，在这快速变化的数字时代，我们必须要认识到创新不仅仅是一个选择，更是一种必然。它推动着我们的业务向前发展。“
```

## 适用场景

1. **内容编辑与润色**：对 AI 初稿进行二次处理，去除明显的算法痕迹，使文本更接近人类写作风格。
2. **写作风格训练**：将规则嵌入写作流程中，持续约束 AI 的输出习惯，培养更自然的表达模式。
3. **教育与研究**：作为识别 AI 生成文本的参考框架，帮助初学者理解 AI 写作的模式特征。
4. **企业内容生产**：在不牺牲效率的前提下提升品牌内容的可信度，避免被读者感知为“AI 堆砌”。

## 项目亮点

与同类项目相比，Stop Slop 最大的差异在于其**系统化与可扩展性**。大多数反 AI 化工具只是简单列出“不要用的词汇”，而 Stop Slop 构建了三层检查体系（短语、结构、句子），每层都有独立的参考文件，允许用户按需定制或扩展。例如，你可以向 `phrases.md` 中添加行业特定的禁用短语，而无需修改核心规则。

其次，它**零技术门槛**。不需要安装 Python 包、配置规则引擎或运行预处理脚本。任何能打开 Markdown 文件的人都可以直接使用，这在团队协作中尤其方便。

最后，项目的**社区共建性**也很突出。由于规则以开放文件形式存在，任何人都可以 fork 仓库并提出改进建议，比如添加新的结构模式或删除过时的短语。这种众包式的维护方式让项目的规则库可以随 AI 写作风格的变化而持续进化。

需要注意的是，Stop Slop 并非魔法工具。它的效果取决于你如何执行规则——如果只是机械地删除所有“副词”和“设问句”，文本可能会变得生硬。更合理的使用方式是将其作为检查清单，在保留必要修辞的前提下，尽量减少冗余模式。
