## 项目概述

OpenCodeReview 是阿里巴巴开源的一款代码评审工具，采用「确定性流水线 + LLM Agent」的混合架构，旨在把人工 Code Review 中最常见的重复性检查自动化，同时保留大模型在上下文理解和自然语言解释方面的能力。该项目使用 Go 语言实现，遵循 Apache-2.0 协议，已在阿里内部的大规模研发流程中经过验证。

它主要解决的问题是传统代码评审的效率与一致性问题：纯静态规则引擎误报率高、难以理解语义，而纯 LLM 方案则存在成本高、不确定性强、容易漏检关键缺陷等缺陷。OpenCodeReview 将两者结合，用确定性分析保证关键问题的召回率，用 LLM 补充语义层面的判断，并输出精确到代码行的评论。

目标用户包括：需要保障代码质量的中大型研发团队、希望把安全与规范检查左移到 CI 流程的工程效能团队，以及对 AI 辅助评审工具有定制需求的个人开发者。

## 核心功能

- **混合分析架构**：先由确定性流水线做语法与规则层面的扫描，再由 LLM Agent 在必要时进行语义推理，两者结果合并后输出评审意见。
- **行级精确评论**：评审结果定位到具体的文件与代码行，可直接用于 PR/MR 的评论回写，减少开发者的定位成本。
- **内置多语言规则集**：覆盖空指针（NPE）、线程安全、XSS、SQL 注入等典型缺陷模式，开箱即可对常见风险做检查。
- **多模型兼容**：支持 OpenAI 与 Anthropic 兼容的接口，可对接官方 API 或自建的兼容网关。
- **可扩展的规则与流水线**：确定性规则与 Agent 调度均可配置，便于团队按自身规范增删检查项。
- **多入口形态**：以 Go 实现核心能力，同时提供 npm 包（`@alibaba-group/open-code-review`），方便在前端工具链或 Node 环境中调用。

## 技术架构

项目以 Go 作为核心实现语言，选择 Go 的主要考量在于分发简单（单一二进制）、并发处理能力好、适合在 CI 环境中低开销运行。整体架构可以拆为三层：

第一层是确定性流水线，负责人工编写或内置的规则匹配、AST 分析与模式检测。这一层不依赖模型，结果可复现，是保证关键缺陷召回的底座。

第二层是 LLM Agent 层，负责把代码上下文、变更 diff 与规则命中结果组织成提示，调用模型做进一步判断或生成解释。该层通过抽象接口对接不同厂商，避免与具体供应商耦合。

第三层是输出与集成层，将两路结果归并、去重、按严重程度排序，并以行级评论的形式呈现，便于接入代码托管平台的评审流程。

这种设计的关键思路是把「高确定性、低成本」的检查交给流水线，把「需要语义理解」的问题交给模型，从而在准确率、成本和响应速度之间取得平衡。阿里内部的大规模使用也为其稳定性和工程成熟度提供了背书。

## 安装与使用

仓库提供了多种安装方式，具体以官方 README 与文档为准。常见做法如下：

通过 npm 安装：

```bash
npm install -g @alibaba-group/open-code-review
```

或使用 Go 工具链从源码构建：

```bash
git clone https://github.com/alibaba/open-code-review.git
cd open-code-review
go build ./...
```

配置模型访问信息，通常以环境变量方式提供：

```bash
export OPENAI_API_KEY="your-api-key"
export OPENAI_BASE_URL="https://api.openai.com/v1"
```

最小可用示例（示意）：

```bash
open-code-review review --path ./your-repo --diff main...HEAD
```

该命令会对指定代码库或变更范围执行评审，并输出按文件、按行组织的检查结果。实际参数名与可用子命令请以仓库文档为准。

## 适用场景

- **CI/CD 中的自动化评审**：在合并请求阶段自动运行，拦截空指针、注入类等高危问题，减少人工评审负担。
- **安全左移检查**：把 XSS、SQL 注入等安全检查提前到编码与提交环节，降低修复成本。
- **团队规范落地**：通过自定义规则与 Agent 提示，把团队内部的编码规范固化为可执行的检查项。
- **存量代码巡检**：对历史仓库批量运行，识别潜在的线程安全与资源管理问题。

## 项目亮点

与常见的纯规则扫描器或纯 LLM 评审工具相比，OpenCodeReview 的差异化主要体现在三点：一是混合架构带来的召回率与准确性平衡，确定性流水线兜底关键缺陷，LLM 负责语义补充；二是行级评论的输出粒度，直接适配代码评审平台的工作流，而非输出一份需要人工二次解读的报告；三是经过阿里内部大规模使用验证，并由阿里巴巴开源、采用 Apache-2.0 许可，具备较高的工程可信度与可商用性。
