## 项目概述

`security-audit-skill` 是 Cloudflare 开源的一个编码代理（coding-agent）技能包，用于将通用代码代理转化为具备结构化流程的安全审计员。它要解决的核心问题是：让大语言模型驱动的代理在安全审计中输出**可复现、可被独立验证、机器可读**的漏洞发现，而不是依赖单次提示生成的、无法追溯的文本结论。

传统的“让模型读代码找漏洞”做法存在两个明显缺陷：一是覆盖范围不可控，代理容易在局部代码上反复打转而遗漏其他模块；二是发现结果缺乏独立校验，模型容易产生幻觉或过度推断。本项目通过多阶段编排与隔离代理机制回应了这两点。目标用户是安全工程师、红队成员、企业安全团队，以及希望搭建自有漏洞发现流程的研发组织。

## 核心功能

- **六阶段结构化审计流程**：依次经过侦察、覆盖驱动的漏洞搜索、候选验证、结构化输出、独立记录校验、目标中立报告，每个阶段都有明确的输入与产出物。
- **覆盖率账本（coverage ledger）**：在侦察阶段生成 `architecture.md` 与 `coverage-ledger.json`，把架构、信任边界、输入面和确定性覆盖单元登记在案，作为后续任务分配的依据。
- **隔离代理并行取证**：从账本单元中分配独立的 hunter，各自记录检查过程，再由 coverage critic 查找覆盖缺口，减少单代理的路径依赖。
- **候选验证与反证机制**：每个唯一候选发现都交给新起的 verifier，verifier 的任务是尝试*证伪*它，只有无法被推翻的候选才进入确认集合。
- **机器可读的验证记录**：输出 `findings.json`，区分 `confirmed`、`needs_validation`、`rejected` 三类状态，并依据 `report-schema.json` 做模式校验。
- **目标中立的报告生成**：从已验证记录与覆盖情况派生出 `REPORT.md`、`FINDINGS-DETAIL.md`、`NEEDS-VALIDATION.md`，报告不绑定特定仓库或技术栈。

## 技术架构

项目以 JavaScript 编写，整体是一套技能定义与提示/流程编排的集合，而非独立运行的扫描引擎——它依赖宿主编码代理来执行实际的代码阅读与推理。设计上体现了几个取舍：

首先是**阶段隔离**。每个阶段使用全新的代理实例，避免前一阶段的上下文偏见污染后续判断，尤其是“验证阶段必须由新代理执行”这一约束，直接针对模型自我确认偏差。

其次是**覆盖驱动而非灵感驱动**。任务不是来自代理的“我觉得这里可疑”，而是来自侦察阶段建立的覆盖单元清单，使审计进度可度量、可审计。

第三是**记录优先于叙述**。所有结论先落成结构化记录并通过 schema 校验，人类可读文档由记录派生，保证报告与底层证据一致。独立记录校验阶段还会由新代理复核最终来源声明，对发生实质性替换的记录追加另一名独立验证者。

## 安装与使用

该项目以“技能”形式分发，具体安装方式取决于宿主代理平台对 skill 的加载约定，通常是将仓库克隆或复制到代理的技能目录中：

```bash
git clone https://github.com/cloudflare/security-audit-skill
```

最小可用流程是：在目标代码库上触发该技能，代理会依次生成侦察产物（`architecture.md`、`coverage-ledger.json`）、分派 hunter 与 verifier，最终产出 `findings.json` 及三份 Markdown 报告。使用者应关注 `findings.json` 与 `NEEDS-VALIDATION.md`，前者是模式校验后的权威记录，后者列出尚需人工判断的边界案例。

## 适用场景

- **自建漏洞发现流水线**：作为从单仓库起步的参考实现，用于搭建企业内部的漏洞挖掘 harness。
- **开源项目例行审计**：在发布前对代码库进行覆盖可控、结论可追溯的安全检查。
- **安全团队培训与流程验证**：借助其分阶段产出物评估代理审计的覆盖度与误报率。
- **AI 代理工作流研究**：多代理隔离、反证验证与结构化输出可作为代理编排的样本工程。

## 项目亮点

与常见的“单提示词找漏洞”方案相比，本项目的差异点在于：验证阶段被设计为**主动证伪**而非确认；结论以 **schema 校验的机器可读记录**为唯一权威来源；审计进度由**覆盖率账本**驱动而非模型直觉；且经历了从单仓库技能到 Cloudflare 全组织范围漏洞 harness 的实践演进，具备真实生产环境的方法论背景。MIT 许可也便于直接嵌入既有流程。
