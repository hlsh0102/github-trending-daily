## 项目概述

`i-have-adhd` 是一个面向编码 AI 代理（coding agent）的“技能（skill）”插件，其核心目标是改变代理的输出风格，让回答像给 ADHD（注意力缺陷多动障碍）用户阅读一样简洁直接。它并不诊断或治疗 ADHD，而是借用“ADHD 友好”这一说法来表达一种普遍的沟通诉求：**先给答案，再给解释；先给行动，再给背景**。

在实际使用中，许多编码助手会习惯性地先寒暄、复述问题、铺陈上下文，把真正的解决方案埋在长段落的中后部。对于需要快速获取下一步操作的开发者而言，这种输出方式增加了阅读成本。`i-have-adhd` 通过注入一段输出规范，约束代理改变回答结构：把可执行的结论和步骤放在最前面，省略“希望这对你有帮助”之类的客套话，并尽量使用编号步骤而非大段散文。

项目的目标用户是日常使用 CLI 或 IDE 内编码代理的开发者，尤其是那些已经厌倦了“过度解释型”回复、希望快速拿到 diff、命令或修复步骤的人。项目采用 MIT 许可证，语言标记为 Python，当前在 GitHub 上已积累较高关注度。

## 核心功能

- **答案前置**：强制代理在回复开头给出直接答案或可执行操作，而不是先展开背景分析。
- **步骤编号**：将多步操作改写为有序列表，降低阅读时定位关键信息的难度。
- **去除客套话**：抑制“好问题！”“希望这能帮到你”等无信息量的填充语，让回复更紧凑。
- **代理无关的 skill 形式**：以“技能/插件”的形式接入，不绑定单一代理，可通过安装指令接入支持该机制的工具链。
- **多语言 README**：仓库提供英文、简体中文、葡萄牙语、日语、越南语、韩语、泰语等说明文档，方便不同地区用户理解安装方式。

## 技术架构

从仓库信息看，项目主要是一个**提示词/技能配置型项目**，而非复杂的运行时框架。其实现思路可以概括为：

1. 定义一份输出规范（skill 描述），规定代理在生成回复时应遵循的结构优先级——行动在前、解释在后；
2. 通过安装指令将该规范注入到目标编码代理的技能或插件目录中；
3. 代理在后续会话中读取该规范，并据此调整自然语言输出的组织方式。

仓库中的 `AGENTS.md` 承担了向代理说明安装步骤的职责，这也是当前 AI 代理生态中较为常见的做法：用代理自身可读的说明文件来完成自安装。项目本身以 Python 作为语言标记，可能包含安装脚本或辅助工具，用于将技能文件复制到对应目录。整体设计倾向轻量、无侵入，不修改代理的推理能力，只约束其表达形式。

## 安装与使用

最简单的安装方式是把下面这句话粘贴到你的 CLI 代理提示中：

```text
Install the i-have-adhd skill/plugin from https://github.com/ayghri/i-have-adhd, refer to the repo's AGENTS.md for instructions.
```

代理会读取仓库中的 `AGENTS.md`，按其中的指引完成安装。仓库同时提供了 `INSTALL.md` 作为手动安装参考。若需手动操作，通常的做法是：克隆仓库，将技能定义文件放入代理所识别的 skills/plugins 目录，然后重启或重新加载代理。

安装完成后无需额外调用，代理在后续对话中会按新的输出规范作答。最小可用示例可以理解为一次对比：

- 未启用时，代理可能先复述问题、再分析原因、最后才给出修改建议；
- 启用后，代理会先给出“把 `middleware.ts` 第 42 行的 `token` 改为 `accessToken`”，再附上一句必要说明。

## 适用场景

- **快速排障**：报错当前，需要立刻拿到修复命令或改动位置，而不是阅读完整背景分析。
- **CLI 编码代理日常使用**：在终端里与代理交互时，紧凑输出更利于滚动查阅和复制命令。
- **代码审查与重构建议**：希望代理直接列出待改项，按优先级编号呈现。
- **多任务切换频繁的开发者**：减少在长回复中来回寻找关键信息的时间成本。

## 项目亮点

与通用的“让 AI 简洁一点”提示词相比，`i-have-adhd` 的差异在于它把输出规范做成了**可安装、可复用的技能包**，并配有明确的安装协议（通过 `AGENTS.md` 让代理自安装）。它不依赖特定模型或特定厂商，任何支持 skill/plugin 机制的编码代理都可以接入。此外，项目对“ADHD 友好”的定位并非医学宣称，而是一种清晰的沟通风格标签——先给结论、编号步骤、去掉噪音，这一原则对所有读者都成立，因此适用范围不限于 ADHD 人群。
