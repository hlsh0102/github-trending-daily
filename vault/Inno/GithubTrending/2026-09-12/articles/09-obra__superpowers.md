## 项目概述

Superpowers 是一套面向编码代理（coding agent）的软件开发方法论，由一组可组合的“技能（skills）”和一组初始指令构成。它解决的并非某个具体的编码难题，而是一个更基础的问题：编码代理在接到需求后，往往会直接跳入代码编写阶段，跳过需求澄清、方案设计与计划编排，最终产出与用户真实意图不一致的结果。

Superpowers 通过一套预设的指令与技能体系，强制代理在动手写代码之前先与用户对话、提炼规格、拆分设计并生成实施计划。目标用户是使用 Claude Code、Codex、Cursor、Gemini CLI、GitHub Copilot CLI 等各类编码代理的开发者，希望让代理的输出更贴近预期、过程更可控。项目以 Shell 为主要实现语言，采用 MIT 许可证。

## 核心功能

- **需求澄清优先**：代理在识别到用户正在构建功能时，不会立即写代码，而是先追问用户的真实目标，把模糊需求转化为明确规格。
- **分块式设计确认**：提炼出的规格以较短、易读的片段分批呈现给用户，避免一次性输出大段设计文档导致难以审阅。
- **实施计划生成**：在用户确认设计后，代理会产出结构化的实施计划，作为后续编码的依据。
- **可组合技能体系**：内置多种技能模块，代理可根据任务类型调用相应技能，形成可复用、可扩展的工作流。
- **多代理平台支持**：提供针对 Claude Code、Antigravity、Codex App/CLI、Cursor、Devin CLI、Factory Droid、Gemini CLI、GitHub Copilot CLI、Grok Build CLI、Kimi Code、OpenCode、Pi、Hermes Agent 等多种代理的接入方式。

## 技术架构

项目以 Shell 脚本为核心，通过初始化指令和技能定义注入到不同代理的运行环境中。其设计思路是“方法论先行、工具无关”：不绑定单一代理平台，而是把工作流抽象为一组可被不同代理加载的技能与指令。

整体流程遵循“提问 → 规格 → 分块确认 → 实施计划 → 编码”的顺序，把传统上由开发者承担的需求澄清与计划编排职责显式地前移到代理侧。技能之间保持松耦合，可单独调用，也可组合成完整流程。仓库中同时包含针对各代理平台的安装配置说明，以及关于哲学、贡献、更新与可视化辅助遥测的文档章节。

## 安装与使用

由于项目面向多种代理，安装方式随平台而异。基本流程如下：

1. 克隆仓库：

   ```bash
   git clone https://github.com/obra/superpowers.git
   ```

2. 根据所用代理，参照 README 对应章节（如 Claude Code、Cursor、Codex CLI 等）执行初始化脚本或配置指令，将 Superpowers 的技能与指令注册到代理环境中。

3. 启动编码代理并描述你的构建目标。代理会先提问澄清需求，随后给出分块设计供你确认，最后生成实施计划并开始编码。

最小可用示例即：在未指定任何额外配置的情况下，向代理提出一个功能需求，观察它是否先询问目标、再给出设计片段，而非直接输出代码。

## 适用场景

- **从零开始的功能开发**：需求尚不清晰时，借助代理的提问机制快速理清规格。
- **多代理环境下的统一工作流**：团队中成员使用不同编码代理，希望统一开发方法论。
- **复杂任务的计划编排**：任务涉及多个模块时，先产出实施计划再动手，降低返工概率。
- **代理行为的规范化**：希望约束代理“先思考再编码”，避免其直接生成偏离预期的代码。

## 项目亮点

与常见的提示词集合或单一代理插件相比，Superpowers 的差异在于它是一套完整的方法论而非零散技巧。它将需求澄清、设计确认与计划编排固化为代理的默认行为，并保持平台无关性，可运行在十余种主流编码代理之上。技能的可组合设计也让工作流能够按需裁剪，而非强制走完整流程。项目采用 MIT 许可证，便于自由使用与二次开发。
