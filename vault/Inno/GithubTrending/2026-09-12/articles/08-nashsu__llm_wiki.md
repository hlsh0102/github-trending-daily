## 项目概述

LLM Wiki 是一款跨平台桌面应用，目标是将用户分散的本地文档自动转换为结构化、互相关联的知识库。与传统 RAG（检索增强生成）在每次提问时都从原始文档重新检索、拼接上下文不同，LLM Wiki 让大语言模型以增量方式读取源文件，并持续构建、维护一个持久化的 wiki。换言之，知识不是临时检索出来的，而是被“写入”并长期保留下来。

它面向的典型用户包括：需要长期管理大量技术资料、研究文献或笔记的开发者与研究者；希望把 PDF、Office 文档、网页剪藏统一整理的资料收集者；以及需要一个可检索、可追溯来源的本地知识库，但又不愿依赖云端服务的隐私敏感用户。项目使用 TypeScript 编写，已在 GitHub 上获得接近两万颗星标，并持续有新增关注。

## 核心功能

- **两步式思维链摄取（Two-Step Chain-of-Thought Ingest）**：模型先对文档进行分析，再生成 wiki 页面。每一页都保留来源出处，并支持增量缓存，避免重复处理已摄取的内容。
- **多模态图片摄取**：可从 PDF 中提取内嵌图片，借助视觉大模型生成事实性图注，并将图片纳入搜索结果。结果支持灯箱预览与跳转到源文件位置。
- **多格式文档解析**：支持 PDF、Office 文档、EPUB/MOBI、Org mode、图片、媒体文件、网页剪藏以及批量 URL 的摄取。PDF 处理可选用内置方案、云端服务或本地 MinerU。
- **灵活的模型配置**：可按项目分别配置模型，将对话（Chat）与摄取（Ingest）两条链路独立路由，并支持自定义服务商、请求头与流式输出。
- **持久化知识库**：LLM 持续维护 wiki 结构，使页面之间形成互链，并在新增资料时更新既有条目，而非每次从零开始。

## 技术架构

项目采用 TypeScript 作为主要开发语言，以桌面应用形态交付，可跨平台运行。其核心设计思路与常规 RAG 有本质区别：传统方案把模型视为无状态的“问答器”，每次请求都重新检索；LLM Wiki 则把模型视为知识库的“维护者”，将摄取结果持久化。

架构上大致分为三层。第一层是文档解析与摄取层，负责把多种格式的源文件切分、抽取文字与图片，并交由 LLM 进行分析。第二层是生成与索引层，通过两步式思维链产出带来源标记的 wiki 页面，并维护增量缓存与页面间的链接关系。第三层是查询与展示层，用户可搜索 wiki 内容，结果可关联到图片与原始来源。模型路由被抽象为可配置项，允许对话与摄取使用不同模型，便于在成本与质量之间做权衡。

## 安装与使用

由于项目为桌面应用，通常的安装方式是从仓库的 Releases 页面下载对应操作系统的安装包并直接运行。若需从源码构建，常见步骤如下：

```bash
git clone https://github.com/nashsu/llm_wiki.git
cd llm_wiki
npm install
npm run dev
```

首次使用的最小流程为：在应用内新建一个项目，配置模型服务商与 API 密钥，选择用于摄取与对话的模型；随后导入一份或多份文档（如 PDF 或 Markdown），等待摄取完成；应用会生成对应的 wiki 页面，用户即可浏览、搜索并查看每页的来源引用。具体命令与配置项请以仓库文档为准。

## 适用场景

- **个人研究资料管理**：把长期积累的论文、电子书、技术文档整合为可互链的知识库，便于回顾与交叉引用。
- **多格式文档统一归档**：将 PDF、Office、EPUB、网页剪藏等异构来源集中摄取，形成一致的结构化条目。
- **带来源追溯的问答**：在需要核实信息出处的工作中，通过页面上的来源标记回溯到原始文件与位置。
- **增量更新已有知识库**：当新增资料时，由 LLM 更新既有 wiki，而非重建整个索引。

## 项目亮点

与常见的 RAG 工具相比，LLM Wiki 的差异在于“持久化 wiki”这一取向：知识被写入并维护，而非每次临时检索。功能层面的组合也较少见，例如两步式思维链摄取、图片抽取与视觉图注、来源可追溯以及按项目分流模型，都集成在同一桌面应用内。多格式解析与内置、云端、本地三种 PDF 处理路径，使它在离线与在线环境下都有可用的方案。这些特点使其更适合需要长期积累、而非一次性问答的知识管理需求。
