## 项目概述

Sonarr 是一个面向 Usenet 与 BitTorrent 用户的智能 PVR（Personal Video Recorder，个人视频录制/管理）系统。它并不是下载工具本身，而是位于下载客户端之上的一层自动化管理中枢：通过持续监控用户订阅的剧集，自动从索引器与 RSS 源中检索新发布的剧集资源，并交由下游的下载客户端完成抓取，随后对文件进行整理、重命名与归档。

它解决的核心问题是剧集追更过程中的重复性劳动。传统方式下，用户需要手动浏览站点、比对已下载集数、判断画质、重命名文件并归入媒体库目录，而 Sonarr 将这一整套流程自动化。其目标用户包括自建 NAS 或家庭服务器的媒体爱好者、使用 Plex、Jellyfin、Kodi 等媒体中心的用户，以及希望在不依赖手动操作的前提下维护剧集库的人群。项目以 C# 编写，采用 GPL-3.0 许可证，目前在 GitHub 上拥有约 1.58 万颗星标。

## 核心功能

- **剧集订阅与自动追更**：用户只需添加剧集并指定目标画质，Sonarr 会持续监控 RSS 源并自动检索、抓取新发布的剧集，无需人工干预。
- **媒体库扫描与缺失补全**：可对已有媒体库进行扫描，识别缺失的集数并尝试补全，避免剧集断档。
- **画质自动升级**：当已下载文件的画质低于设定标准时，若出现更高质量的版本（例如从 DVD 升级到 Blu-Ray），系统会自动替换。
- **失败下载处理**：当某个资源下载失败或被判定为无效时，会自动尝试其他候选版本，提高获取成功率。
- **文件整理与重命名**：按照可自定义的命名规范对下载完成的内容进行重命名并移动到媒体库对应目录，保持库结构统一。
- **多平台与多下载客户端支持**：支持 Windows、Linux、macOS、Raspberry Pi 等主流平台，并可对接多种 Usenet 与 BitTorrent 下载客户端。

## 技术架构

Sonarr 使用 C# 开发，属于典型的 .NET 服务端应用。其架构可概括为三层：**索引与检索层**负责对接各类索引器、RSS 源与追踪站点，聚合候选资源；**决策层**依据用户设定的画质配置、语言偏好与优先级规则，对候选资源进行评分与筛选；**执行层**通过下载客户端 API 下发任务，并在完成后执行导入、重命名与升级替换。

这一分层设计使各环节可独立替换，例如更换索引器或下载客户端不会影响整体逻辑。同时，Sonarr 对外提供 REST 风格的 API（官方有独立 API 文档），第三方工具可借此集成或开发客户端。项目采用 servarr 组织下的统一 Wiki 与翻译平台（translate.servarr.com），在社区协作与本地化方面有一定投入。

## 安装与使用

Sonarr 提供面向 Windows、Linux、macOS、Raspberry Pi 等平台的安装包，用户可从官网下载页获取对应版本，也可通过社区维护的软件源或容器镜像部署。典型的使用流程如下：

1. 安装并启动 Sonarr，通过浏览器访问其 Web 管理界面（默认端口通常为 8989）。
2. 在设置中添加下载客户端（如 qBittorrent、SABnzbd 等）与索引器。
3. 配置媒体库根目录与命名规范。
4. 搜索并添加需要追更的剧集，设定目标画质与语言。
5. 之后由系统自动完成检索、下载、整理与升级。

对于进阶用户，还可通过 API 进行自动化配置或与其他媒体管理工具联动。

## 适用场景

- **家庭媒体服务器追更**：配合 NAS 或家庭服务器使用，自动维护剧集库，供 Plex、Jellyfin 等媒体中心播放。
- **大规模剧集库管理**：对已有大量剧集文件的用户，通过扫描与规范化命名统一库结构。
- **多客户端混合下载**：同时使用 Usenet 与 BitTorrent 的用户，可集中管理不同来源的任务。
- **自动化集成开发**：借助官方 API，将 Sonarr 接入自建面板或自动化脚本，构建端到端媒体流水线。

## 项目亮点

与手动追更或单一功能的下载工具相比，Sonarr 的差异化优势主要体现在三个方面。其一，**端到端的自动化闭环**，从检索、筛选、下载到整理与升级均由系统完成，用户介入成本低。其二，**成熟的画质决策机制**，能够基于用户配置对资源进行评分与替换，而不仅是简单抓取。其三，**活跃的社区与生态**，拥有独立 Wiki、论坛、Discord、Reddit 及 IRC 支持渠道，且已衍生出同组织的 Radarr 等同类项目，形成了稳定的媒体自动化工具链。
