## 项目概述

Ever® Gauzy™ 是一个开源的企业业务管理平台，定位为面向协作经济、按需经济与共享经济场景的一体化管理系统。它将企业资源计划（ERP）、客户关系管理（CRM）、人力资源管理（HRM）、招聘跟踪系统（ATS）、工作与项目管理（PM），以及员工时间与生产力追踪等多个业务模块整合在同一个平台中，目标是替代企业通常需要分别采购的多套 SaaS 工具。

该项目解决的核心问题是业务系统的碎片化：销售、人事、招聘、项目、工时等数据通常分散在不同厂商的系统中，导致数据孤岛、集成成本高、权限体系不统一。Gauzy 通过统一的 API 与数据模型，把这些职能模块放到同一平台上，使组织可以在一个后台中完成跨部门的业务操作与统计。

目标用户包括中小企业、外包与人力派遣公司、咨询与代理机构，以及需要按工时或项目计费的团队；同时由于其开源与可自行部署的特性，也适合对数据主权、合规与二次开发有要求的技术团队。

## 核心功能

- **企业资源计划（ERP）**：管理组织架构、财务相关基础数据与业务往来，作为平台的核心数据层。
- **客户关系管理（CRM）**：维护客户、联系人、销售线索与沟通记录，支撑销售流程的跟进与转化。
- **人力资源管理（HRM）**：涵盖员工档案、薪酬、假期与费用报销等日常人事事务。
- **招聘跟踪系统（ATS）**：面向招聘流程，管理职位发布、候选人管道与面试进度。
- **项目与工作管理（PM）**：支持任务、看板、团队协作与项目进度跟踪。
- **时间与生产力追踪**：提供员工工时记录、活动采集与效率统计，可直接服务于按工时计费的业务场景。

## 技术架构

项目以 TypeScript 为主要开发语言，整体属于典型的模块化全栈应用。后端基于 Node.js 与 NestJS 构建，采用模块化依赖注入的设计方式，使 ERP、CRM、HRM 等功能域可以相对独立地演进与裁剪。数据持久化方面同时支持多种关系型数据库（如 PostgreSQL、MySQL/SQLite 等），通过 ORM 抽象层屏蔽底层差异。

前端提供基于 Angular 的管理后台（Web UI），并对外暴露独立的 HTTP API，官方文档地址为 api.gauzy.co/docs。这种前后端分离加无头（headless）API 的设计，使得第三方可以基于同一套接口构建不同的客户端——例如同组织下的 Ever Teams 项目就采用 React（Next.js）与 React Native（Expo）栈接入 Gauzy 的后端 API。

此外，项目提供了 Gitpod 一键开发环境配置，便于贡献者快速启动。整体架构强调可自托管与可扩展，适合在其之上做定制化开发。

## 安装与使用

由于仓库未在 README 摘要中给出完整命令，以下为基于常见做法的概述，实际步骤请以仓库文档为准。

1. 准备运行环境：Node.js、包管理器（Yarn 或 npm）以及受支持的数据库（如 PostgreSQL）。
2. 克隆仓库并安装依赖：
   - `git clone https://github.com/ever-co/ever-gauzy.git`
   - 进入目录后执行依赖安装命令。
3. 配置环境变量：复制示例配置文件（如 `.env.example`），填写数据库连接、端口等参数。
4. 初始化数据库并执行迁移/种子数据脚本。
5. 启动后端 API 服务与前端管理界面，浏览器访问本地端口完成初始账号设置。

若不想本地部署，也可以直接使用官方托管的 API 端点进行联调。对于希望快速体验的开发者，Gitpod 链接可在浏览器中直接拉起已配置好的开发环境。

## 适用场景

- **外包与人力派遣公司**：需要同时管理客户、项目、员工工时并按时间计费，Gauzy 的时间追踪与项目管理可直接对接业务结算。
- **咨询与代理机构**：以项目为单位交付服务，关注人力利用率与生产力统计。
- **中小企业一体化管理**：希望用一套系统替代 CRM、HRM、PM 等多套分散工具，降低集成与订阅成本。
- **自托管与合规需求场景**：对数据存放位置、隐私合规有要求，需要自行部署并二次开发的组织。

## 项目亮点

与多数只覆盖单一领域的开源业务系统相比，Gauzy 的主要差异在于**功能广度**：它把 ERP、CRM、HRM、ATS、PM 与工时追踪放在同一个平台内，共享同一套组织、权限与数据模型，减少了跨系统同步的复杂度。

其次是**无头 API 与前后端分离**的设计，使得同一后端可以服务于不同技术栈的客户端，官方生态中已有基于 React/React Native 的 Ever Teams 作为示例，扩展性较强。

此外，项目采用 AGPL-3.0 许可证，允许自托管与修改，配合 Gitpod 开发环境和较完整的 API 文档，降低了上手与参与贡献的门槛。仓库当前在 GitHub 上拥有约 5400+ 星标，社区活跃度相对可观。
