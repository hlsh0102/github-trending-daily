## 项目概述

Colibrì（意大利语“蜂鸟”）是一个用纯 C 编写的轻量级大模型推理引擎，目标是在用户已有的消费级硬件上运行前沿规模的 MoE（混合专家）模型。它解决的核心问题是：传统推理框架通常要求模型权重完整驻留显存或内存，导致 700B 以上参数的模型难以在个人设备上部署。Colibrì 通过把存储、内存和显存统一视为一个多层推理层级（AI 内存分层），将专家权重按需从磁盘流式加载，从而在有限硬件上运行 744B 到 2.8T 参数的模型。

项目面向希望在本地运行大型 MoE 模型的研究者、开发者和爱好者，也适合作为研究内存分层与稀疏推理的开放平台。引擎本身没有第三方依赖，每个模型家族对应单个 C 文件。

## 核心功能

- **超大 MoE 模型支持**：当前支持 GLM-5.2/5.3（744B）、GLM-5.3-Flash（321B，带视觉）、Inkling（975B）、Kimi K3（2.8T）、DeepSeek V4 Flash（284B）、DeepSeek V4.1 Flash（552B，带视觉）、Qwen3.8-Flash-Next（125B + 51B n-gram）、Qwen3.6（35B-A3B）和 OLMoE（7B）等多个模型家族。
- **AI 内存分层**：将磁盘、RAM 和 VRAM 视为统一层级，专家权重从磁盘按需流式读取，降低对显存容量的硬性要求。
- **零引擎依赖**：整个引擎以纯 C 实现，不引入外部运行时或深度学习框架，便于编译和移植。
- **统一命令行入口**：不同模型共用 `coli chat`、`coli serve`、`coli web` 三种前端交互方式，分别对应终端对话、API 服务和网页界面。
- **异构硬件适配**：支持消费级与异构硬件组合，允许 CPU、GPU 和存储协同参与推理。

## 技术架构

Colibrì 的设计思路是围绕 MoE 模型的稀疏激活特性展开。由于 MoE 每次前向只激活部分专家，大量专家权重在单个 token 生成步骤中并不需要同时驻留高速内存。引擎利用这一点，将专家权重存放在磁盘上，在需要时流式加载，并把 RAM 和 VRAM 作为缓存层进行管理，形成“存储—内存—显存”的推理层级。

实现层面，项目使用纯 C 编写，每个模型家族对应一个 C 文件，模型相关的张量布局、路由逻辑和加载策略在这一层实现，而推理调度、内存分层和前端接口由共享的引擎核心提供。这种结构使新增模型家族的代价相对可控，也便于研究者针对特定模型修改实现。项目采用 Apache-2.0 许可证。

## 安装与使用

Colibrì 以源码形式发布，通常的流程是先获取仓库并编译：

```bash
git clone https://github.com/JustVugg/colibri
cd colibri
make
```

编译完成后，可通过统一入口运行所选模型。以交互式对话为例：

```bash
./coli chat --model <model-name>
```

若需作为本地 API 服务运行，可使用：

```bash
./coli serve --model <model-name>
```

网页界面则通过：

```bash
./coli web --model <model-name>
```

具体可用的模型名称、权重下载方式以及硬件配置建议，请以仓库 README 和发布页面为准。由于模型体积较大，首次运行前需要准备足够的磁盘空间，并确保存储读取带宽满足流式加载需求。

## 适用场景

- **本地运行超大 MoE 模型**：在显存不足以完整容纳 744B 以上模型的设备上，通过磁盘流式加载专家权重进行推理。
- **内存分层与稀疏推理研究**：作为开放研究平台，用于实验不同的缓存策略、专家调度和存储层级组合。
- **隐私敏感或离线环境**：在无外网或数据不便上传的场景下，本地部署模型完成对话或服务。
- **多模型对比与教学演示**：借助统一的 `coli` 前端，在同一套工具链下切换不同模型家族进行测试和展示。

## 项目亮点

与常见的本地推理方案相比，Colibrì 的差异主要体现在三点。第一，它瞄准的是 744B 到 2.8T 参数级别的 MoE 模型，而不是中小规模稠密模型，定位明确。第二，它用纯 C 实现且零引擎依赖，避免了 Python 运行时和框架版本带来的部署负担。第三，它把磁盘纳入推理层级，将“模型必须装进显存”这一约束转化为可调度的流式加载问题，使前沿规模模型在消费级硬件上运行成为可能。
