## 项目概述

Munder Difflin 是一个本地运行的多智能体编排框架（multi-agent harness），灵感来源于经典美剧《Office》中的同名纸业公司。它的核心思路很直接：把你正在使用的终端编码 CLI（如 Claude Code、OpenCode 等）包装成一个个“数字员工”，让它们在你的机器上组成一个“办公室”，由你的“数字分身”负责调度和协调，从而在你离开电脑时持续工作。

项目解决的核心问题是：现有的 AI 编码工具大多是单会话、单任务的，当任务复杂到需要多个模型协作、上下文需要共享、或者需要长时间无人值守运行时，单个 CLI 就显得力不从心。Munder Difflin 通过一个可视化的桌面应用（基于 Electron），把多个模型实例统一管理起来，让它们像同事一样互相发消息、分工协作，而你不必为每个模型单独维护一套工作流。

目标用户是已经拥有各类 AI 编码工具订阅（Claude、Gemini、Codex 等）的开发者，希望在不增加额外 API 费用的前提下，利用已有订阅的每小时额度，搭建一个可离线运行的“数字员工团队”。项目目前处于工作原型阶段（version 0.4.4），开源免费，采用 MIT 许可证。

## 核心功能

- **多模型统一接入**：内置适配层，支持 Claude Code、Antigravity（Gemini）、OpenAI Codex、xAI Grok、Kimi Code、Qwen、OpenCode、Crush、pi.dev 和 GitHub Copilot CLI，同时支持自带 API Key 和本地 LLM（如 Ollama）。
- **智能体通信与路由**：智能体之间可以通过消息系统互相传递任务和结果，路由机制根据任务类型自动分配最合适的模型。
- **数字分身“Michael”**：一个由你配置的“克隆体”作为总协调者，负责分派任务、汇总进展、处理异常，让整个流程无需人工介入。
- **共享记忆**：智能体之间共享上下文和任务历史，避免重复劳动，也支持持久化记忆以便后续会话接续。
- **可视化办公室界面**：基于 Pixi.js 渲染的办公室场景，每个智能体以“工位上的头像”呈现，实时展示工作状态、消息流动和任务进度，让多进程并行工作一目了然。
- **终端级集成**：基于 xterm.js 和 node-pty，直接复用终端 CLI 的完整能力，包括文件读写、命令执行、交互式调试等，而非简单的 API 封装。

## 技术架构

Munder Difflin 的技术栈清晰且务实。前端采用 **Electron + React + TypeScript** 构建跨平台桌面应用（支持 macOS、Windows、Linux）。界面层使用 **Pixi.js** 渲染高性能的 2D 办公室场景，保证多个智能体动画的流畅性。终端交互层则依赖 **xterm.js** 与 **node-pty**，使得每个智能体的会话本质上就是一个真实的 PTY 进程，这意味着所有底层 CLI 的原生功能（如颜色输出、TUI 控件、快捷键）都能完整保留。

架构的核心设计在于“包装而非重写”。项目没有重新实现任何模型的推理逻辑，而是通过适配器模式，将每个 CLI 工具的标准输入输出流转化为标准化的消息协议。这样做有两大好处：一是模型能力随官方 CLI 更新而自动更新，维护成本低；二是用户已有的配置、登录状态、自定义命令都能直接复用。

调度层采用事件驱动架构。每个智能体是一个独立的进程，通过内部消息总线交换 JSON-RPC 风格的消息。协调者（Michael）监听所有智能体的状态广播，根据任务队列和优先级进行动态路由。共享记忆层使用 SQLite 本地存储，记录任务描述、决策日志和产出物路径，便于事后审计和断点恢复。

这样的设计使得系统具备较好的横向扩展性——你可以在同一台机器上运行数十个智能体进程，而性能开销主要取决于 CLI 本身的资源占用。项目当前的定位是“本地优先”，所有通信都在 localhost 内完成，不依赖云端控制面。

## 安装与使用

由于项目处于原型阶段，安装方式建议从源码构建。基本步骤如下：

```bash
# 克隆仓库
git clone https://github.com/chaitanyagiri/munder-difflin.git
cd munder-difflin

# 安装依赖
npm install

# 启动开发模式
npm run dev
```

首次启动后，你需要配置至少一个模型提供方。在配置文件（如 `config.yaml` 或通过界面设置）中指定你已有的 CLI 路径和对应的 API Key。例如，使用 Claude Code 的配置片段：

```yaml
agents:
  - name: "coder-claude"
    provider: "claude-code"
    model: "claude-sonnet-4-5"
    api_key_env: "ANTHROPIC_API_KEY"
    capabilities: ["coding", "terminal"]
```

配置完成后，启动应用，你会看到办公室界面。创建任务时，可以在输入框中描述需求，Michael 会自动拆解并分派给合适的智能体。你可以在“工位视图”中实时观察每个智能体的工作日志和输出。

最小可用示例：让两个智能体协作完成一个“写一个 Python 脚本并测试”的任务——Michael 将编码任务派给 Claude Code 智能体，将测试执行派给 Codex 智能体，两者通过消息交换文件路径和测试结果，最终产出更新的代码文件和测试报告。

## 适用场景

- **夜间批处理开发**：在你睡觉或离开电脑时，让智能体团队按照任务清单完成代码编写、Bug 修复、依赖升级等常规工作，早晨检查结果。
- **多模型交叉验证**：针对同一需求，让不同厂商的模型分别产出方案，再由协调者汇总对比、选优或融合，提升输出质量。
- **本地知识库维护**：将文档更新、代码注释补全、CHANGELOG 生成等琐碎任务交给智能体长期值守，解放人工。
- **离线环境开发辅助**：对于网络受限或数据敏感的环境，使用本地 LLM 接入，实现完全离线且自主可控的多智能体协作。

## 项目亮点

与市面上其他的多智能体框架（如 AutoGen、CrewAI 等）相比，Munder Difflin 的差异化优势非常明显：

1. **零额外 API 成本**：不强制使用某个特定云服务，完全复用你已有的订阅额度，甚至支持本地模型，因此长时间运行也不会产生新的费用。
2. **真实终端能力**：不仅仅是 LLM 调用，每个智能体都拥有完整的终端环境，可以操作真实文件系统、运行测试、启动服务，而不是局限于沙箱内的代码生成。
3. **视觉化管理体验**：用办公室隐喻和实时头像动画来呈现复杂的多进程协作，降低了理解门槛，让监控和干预变得直观。
4. **本地私密性**：所有数据流和通信都留在本地机器上，尤其适合企业环境或对数据出境敏感的场景。
5. **热插拔模型支持**：适配层设计让新增一个 CLI 提供方的工作量很小，社区很容易扩展支持新的工具。
