## 项目概述

gstack 是 Y Combinator 总裁兼 CEO Garry Tan 个人使用的一套 Claude Code 配置，包含 23 个高度定制的工具。该项目旨在复现 Garry Tan 本人“一个人的团队”式开发效率——他在过去 60 天内（兼职全职运营 YC 的情况下）发布了 3 个生产服务、40+ 个功能特性，其逻辑代码变更效率达到 2013 年的 810 倍。项目核心理念源于 Andrej Karpathy 在 2026 年 3 月的观察：他自 12 月以来几乎没有手写过代码，但依然高效交付。gstack 将这些工具打包为 CEO、设计师、工程经理、发布经理、文档工程师和 QA 六大角色，让单一个体借助 AI 工具具备传统团队的组织能力。

gstack 面向希望借助 AI 编码助手实现“一人团队”式开发效率的独立开发者、创业公司早期团队以及技术负责人。它不是一个通用的 AI 工具，而是一套经过验证、高度集成的开发工作流模板。

## 核心功能

- **CEO 角色工具**：提供产品方向决策、优先级排序、战略级代码审查的能力，帮助开发者从执行者转变为决策者。
- **设计师角色工具**：集成了 UI/UX 设计相关的提示和工具链，支持快速原型生成和设计一致性检查。
- **工程经理角色工具**：包含代码分解、任务拆解、依赖管理、进度追踪等项目管理能力，帮助单人项目保持多人团队的结构化开发节奏。
- **发布经理角色工具**：自动化版本号管理、变更日志生成、发布分支创建、依赖兼容性检查，支持持续集成和持续部署流水线。
- **文档工程师角色工具**：根据代码变更自动生成或更新 API 文档、README、变更日志，保持文档与代码同步。
- **QA 角色工具**：自动生成测试用例、边界条件检查、代码质量评估、性能回归检测，并可以按需执行全面的冒烟测试。

## 技术架构

gstack 基于 TypeScript 开发，以 Claude Code 为核心执行引擎，通过一系列高度结构化的提示模板（prompts）和配置脚本来组织工作流。项目的关键架构特点包括：

- **角色化工具封装**：每个工具都对应一个明确的角色（CEO、设计师等），每个角色拥有独立的上下文提示库和约束规则。这种设计避免了单一大型提示的泛化问题，让 AI 在不同阶段切换角色时获得更精确的指令。
- **配置即代码**：所有工具的定义、版本、角色归属均通过声明式配置文件管理，支持按需启用/禁用、自定义扩展，且与项目源代码共存于仓库中。
- **增量执行模型**：gstack 不替代已有开发流程，而是作为“协议层”叠加在 Claude Code 之上。开发者随时可以退回到手动模式，或者只启用特定角色的工具来处理当前任务。
- **逻辑变更度量**：项目特别强调了“逻辑代码变更（logical code change）”而非原始代码行数（LOC）的度量方式，避免 AI 膨胀代码量的常见问题，专注于衡量真正的功能改动量。
- **运行时可插拔**：工具本身可以独立运行、组合使用或替换，例如 QA 角色的测试工具可以在 CI 流水线中独立调用，也可以与发布经理工具联动完成自动化发布。

## 安装与使用

**前提条件**：确保已安装 Node.js（v18+）和 Claude Code CLI（版本 ≥ 0.8.x）。

**安装步骤**：
1. 克隆仓库到本地：
```bash
git clone https://github.com/garrytan/gstack.git
cd gstack
```

2. 安装依赖：
```bash
npm install
```

3. 将 gstack 工具配置链接到 Claude Code：
```bash
npx gstack setup
```

**最小可用示例**：
在项目根目录执行以下命令，让 AI 以“CEO + 工程经理”双角色审查当前代码库：
```bash
npx gstack run --roles ceo,eng_manager --task "Review the entire codebase and suggest improvements for scalability"
```

若需生成发布版本，可组合发布经理和 QA 角色：
```bash
npx gstack run --roles release_manager,qa --task "Prepare a patch release with automated changelog and test suite validation"
```

## 适用场景

- **独立开发者构建复杂产品**：一个开发者需要同时管理产品决策、设计、开发、测试和发布，gstack 的多角色分工可以显著降低上下文切换成本，让 AI 在不同阶段提供针对性协助。
- **创业公司早期快速迭代**：2–5 人的小团队可以用 gstack 模拟 10–20 人组织的开发节奏，角色化工具让每个团队成员都能在需要时获得跨职能支持（例如工程师临时承担设计审查）。
- **开源项目维护**：维护者经常需要同时处理 issue 分类、代码审查、文档更新和版本发布，gstack 的文档工程师和发布经理角色可以自动化大量常规工作，让维护者专注于核心代码。
- **大型项目的碎片化时间开发**：像 Garry Tan 一样工作繁忙的人，可以利用 gstack 提供的“上下文恢复”机制，在零散时段高效地切换不同任务（从审查代码到撰写发布说明），而无需每次都重新向 AI 解释背景。

## 项目亮点

- **源自真实实践**：不是学术性的概念验证，而是 YC CEO 每天亲自使用的生产级工作流。Garriy Tan 在 60 天内交付 3 个生产服务、40+ 特性的数据本身就是最有力的背书。
- **角色化而非功能化**：不同于其他 AI 工具列出一长串孤立功能，gstack 按照软件开发全生命周期中的角色来组织能力，更符合人类的协作心理模型，使用与学习成本更低。
- **逻辑变更优先**：明确区分“逻辑代码变更”和“原始代码行数”，在度量上更接近真正的开发效率，避免了 AI 代码膨胀带来的虚假生产力感知。
- **高度可定制且开源**：MIT 许可证允许任意修改和商用，任何人都可以 fork此仓库 并调整其中的角色工具来匹配自己的开发习惯。
- **与现有工作流兼容**：不强制替代已有工具链，而是作为增强层叠加在 Claude Code 之上，允许开发者按需启用部分角色，逐步过渡。
