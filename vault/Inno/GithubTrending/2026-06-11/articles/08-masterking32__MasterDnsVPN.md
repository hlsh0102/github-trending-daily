## 项目概述

MasterDnsVPN 是一个专注于高级 DNS 隧道技术的开源 VPN 项目，旨在利用 DNS 查询和响应来传输 TCP 流量，从而实现对网络审查的绕过。该项目由 masterking32 开发，采用 Go 语言编写，整体思路与 DNSTT 或 SlipStream 类似，但在实现结构和方式上有根本性差异。

MasterDnsVPN 的核心目标是兼容多种 DNS 解析器行为，并在极端恶劣的网络条件下，依然保持极高的稳定性和数据传输成功率。项目主要面向网络研究者、审查规避开发者和对网络自由有需求的技术用户，提供一种底层优化的 DNS 隧道方案。

## 核心功能

- **超低传输开销**：自定义协议配合 ARQ（自动重传请求）机制，传输头部开销仅为 5–7 字节，相比 DNSTT 约降低 88%，相比 SlipStream 约降低 71%。
- **解析器负载均衡**：内置智能负载均衡算法，能够根据 DNS 解析器的响应质量动态分配流量，减少单一解析器压力堆积。
- **高丢包环境稳定**：针对高丢包率的网络条件进行了专门优化，通过 ARQ 与重传策略确保数据完整交付，减少因丢包导致的连接中断。
- **兼容多种 DNS 解析器**：设计上充分考虑不同解析器的行为差异，能够适应公共 DNS、ISP DNS 乃至私有解析器的不同规则和限制。
- **VPN 模式支持**：除了基本的 DNS 隧道功能，还提供 VPN 模式，允许将整个设备流量通过 DNS 隧道转发，实现完整的网络层代理。
- **自定义协议栈**：完全基于 Go 语言实现自定义传输协议，不依赖 QUIC 或 KCP 等现有协议栈，从而实现对头部大小、重传策略和数据片段化的精细控制。

## 技术架构

MasterDnsVPN 采用客户端-服务器架构。客户端负责将 TCP 数据包封装为 DNS 查询请求发送至目标 DNS 解析器，服务器端（部署在境外）则从这些 DNS 请求中提取并还原原始 TCP 数据，再转发至实际的目标服务器。返回的响应同样通过 DNS 响应包携带回客户端。

项目的技术核心在于自定义传输协议，而非采用现有的 QUIC 或 KCP 套件。该协议基于 ARQ（自动重传请求）机制，能够检测数据包丢失并自动发起重传，同时将传输头部开销压缩到 5–7 字节，远低于 DNSTT 的 59 字节和 SlipStream 的 24 字节。此外，项目内建了解析器负载均衡模块，通过持续监控各 DNS 解析器的延迟、成功率与响应稳定性，动态切换分配请求，避免单一解析器成为瓶颈。整体设计以“稳健优先”为原则，优先保障数据交付的可靠性，而非追求极限吞吐。

## 安装与使用

### 安装步骤

1. 确保系统已安装 Go 1.18 或更高版本。
2. 克隆仓库到本地：
   ```bash
   git clone https://github.com/masterking32/MasterDnsVPN.git
   ```
3. 进入项目目录并编译：
   ```bash
   cd MasterDnsVPN
   go build -o masterdnsvpn
   ```

### 最小可用示例

**启动服务端**：
```bash
./masterdnsvpn server --listen 0.0.0.0:5300 --domain example.com
```

**启动客户端**：
```bash
./masterdnsvpn client --server <server_ip>:5300 --domain example.com --dns 8.8.8.8 --tun tun0
```

客户端会自动创建 TUN 接口并劫持系统 DNS 流量，通过 DNS 隧道将流量转发至服务端。具体参数可通过 `--help` 查看。

## 适用场景

- **网络审查规避**：适用于 DNS 劫持和 IP 封锁严重的地区，利用 DNS 查询这一高频、难以彻底封禁的协议穿透限制。
- **高丢包环境下的通信**：对于卫星网络、山区或信号差区域的用户，ARQ 机制能有效维持连接稳定性，优于传统基于 QUIC 的隧道方案。
- **资源受限的嵌入式设备**：由于传输头部开销极低，MasterDnsVPN 特别适合在内存和带宽受限的物联网或路由设备上运行。
- **DNS 研究**：作为网络研究的实验平台，可帮助研究者理解 DNS 隧道在高丢包、高延迟场景下的行为模式。

## 项目亮点

- **极低传输开销**：5–7 字节的头部开销在整个 DNS 隧道领域处于领先水平，这意味着在同样带宽下，有效载荷占比更高，传输效率更优。
- **全面的鲁棒性设计**：项目明确针对最坏网络条件设计，而非仅优化理想环境。ARQ 机制、解析器负载均衡和多策略重传共同保证了在高丢包与高延迟下的可用性。
- **与同类项目的系统性对比**：项目 README 中提供了与 DNSTT、SlipStream 的量化对比表格，从开销、协议类型、稳定性等多维度展示优势，具备很强的透明度和说服力。
- **独立自主的协议栈**：不依赖 QUIC 或 KCP 等第三方协议库，不仅减少了依赖和攻击面，也使得对协议的调优可以完全自主进行。
