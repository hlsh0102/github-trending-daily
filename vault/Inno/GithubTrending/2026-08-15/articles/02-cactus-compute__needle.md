## 项目概述

Needle 2 是一个面向微型设备的开源基础模型，由 cactus-compute 团队开发。整个模型仅有 45M 参数，打包为一个 14MB 的独立二进制文件，运行完整会话仅需约 28MB 内存。它专为手机、可穿戴设备、智能家居和机器人等资源受限场景设计，提供了工具调用、设备使用和结构化信息提取能力。

项目名称 "Needle" 寓意在数据海洋中精准定位信息。Needle 2 构建在团队此前提出的 Simple Attention Network 研究成果之上，采用 Cactus Quants 量化技术压缩至 CQ2 位精度，并内置了专用推理引擎。在多项基准测试中，Needle 2 与 FunctionGemma 270M、LFM2.5 230M 和 Apple FM 等体积大 5 至 70 倍的模型互有胜负，却仅以其 2 位量化精度运行，对比这些模型的 f16 精度实现了数十倍体量压缩。

## 核心功能

- **完全自包含**：模型权重直接烘焙进单个 14MB 引擎文件，无独立模型文件需要管理，推理过程不依赖任何网络连接。
- **结构化输出契约**：采用简单且严格的输入输出协议——文本进、JSON 出。模型会根据用户定义的工具 schema 编译字节级语法，约束每一个生成的 token 以符合预期格式。
- **置信度门控机制**：每个响应都附带一个从学习头（learned head）生成的校准置信度分数。开发者可以设定阈值：高于阈值则自动执行操作，低于阈值则转交人工处理或升级流程。
- **工具检索能力**：支持声明大型工具目录，内置检索头每轮对话仅渲染最相关的五个工具，并将语法约束限定在该子集内，兼顾性能与精度。
- **有界内存管理**：采用 256 token 的滑动窗口机制，配合工具调用策略，有效控制长任务的上下文占用，使模型能在极小内存环境下稳定运行。

## 技术架构

Needle 2 的架构设计围绕"极简单、极轻量"展开。其底座是团队自研的 Simple Attention Network（SAN），一种比传统 Transformer 更高效的注意力机制变体。SAN 在保持建模能力的同时大幅削减计算量和参数量，为后续压缩奠定了良好基础。

在量化方案上，项目使用自研的 Cactus Quants 技术将权重压缩到 CQ2 位精度。这不仅是单纯的位宽降低，而是结合了模型结构的优化设计，使得量化后的损失相对于传统 2 位量化方案大幅减少。配合 f16 基线对照，Needle 2 在极小体积下仍展现出具有竞争力的模型质量。

推理引擎被内嵌为单一二进制文件，这意味着无需在设备上运行 Python 环境或加载外部依赖。Python 包 `cactus-needle` 仅作为控制层，负责描述工具、发起调用和接收结构化结果。引擎首次使用时从 Hugging Face 获取并缓存，之后完全离线运行，对气隙网络（air-gapped）环境有完善的部署支持。

整个模型的设计哲学是"简单契约 + 强约束"：通过语法层约束和检索层过滤，将模型的自由度限制在可行范围内，既保证输出质量，也降低了推理时的不确定性。

## 安装与使用

安装过程非常简洁，只需通过 pip 安装 Python 包：

```bash
pip install cactus-needle
```

首次使用时，包会自动从 Hugging Face 下载推理引擎并缓存到本地，后续调用无需任何网络请求。最小可用示例如下：

```python
import needle

# 描述你的工具 schema
tools = [
    {
        "name": "get_weather",
        "description": "查询指定城市的天气",
        "parameters": {
            "type": "object",
            "properties": {
                "city": {"type": "string", "description": "城市名称"}
            },
            "required": ["city"]
        }
    }
]

# 初始化模型（自动加载缓存引擎）
client = needle.Client(tools=tools)

# 发起对话并获取结构化工具调用结果
response = client.chat("北京今天天气怎么样？")
# response 为 JSON 格式：
# {"tool": "get_weather", "args": {"city": "北京"}}
```

对于需要离线部署的设备场景，完整的 air-gapped 安装指南可在仓库的 `doc/apis.md` 文件中找到。

## 适用场景

1. **智能家居中心**：在树莓派或智能音箱等本地设备上运行，实现对灯光、温控、安防等设备的声控操作，无需云端参与。

2. **可穿戴设备**：在手表或健康手环上执行语音命令解析、结构化数据提取，如"记录昨晚睡眠质量到日志"等操作，全程本地处理保护隐私。

3. **边缘机器人**：为家用或工业机器人提供本地工具调用能力——控制机械臂、读取传感器数据、执行脚本，摆脱对中央服务器的依赖。

4. **嵌入式语音助理**：在资源有限的 MCU 设备中实现自然语言交互终端，根据用户话语调用预设功能模块，响应速度毫秒级。

## 项目亮点

- **极度轻量化**：14MB 二进制在保持可用性能的同时，体积比同类小模型小 5 至 70 倍，是当前极少数能在 MCU 类设备上跑的 LLM 方案。
- **零网络依赖**：推理过程完全离线，杜绝了数据泄漏风险，同时避免了设备离线时服务不可用的问题。
- **结构化输出保证**：字节级语法约束确保模型输出严格符合 schema，错误率和重新生成率远低于自由文本 + 解析的方案。
- **置信度评分**：内置置信度门控让应用层可以做出更智能的决策——低置信度时自动转人工，大幅提升端到端可靠性。
- **模型即引擎**：不需要单独加载深度学习框架，极简部署路径降低了工程集成成本。
