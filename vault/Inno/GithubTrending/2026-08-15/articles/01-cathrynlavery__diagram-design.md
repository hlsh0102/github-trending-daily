## 项目概述

diagram-design 是一个为 Claude Code、Codex 和 Pi 等 AI 编程助手设计的专业图表生成技能包。它提供了 29 种编辑级图表类型，全部使用独立的 HTML + SVG 实现，无需依赖任何外部库或框架。项目的核心目标是解决 AI 生成图表时常见的"塑料感"问题——那些千篇一律的圆角矩形、刺眼的阴影和混乱的配色，让设计师和工程师都感到头疼。

这个项目特别适合需要在文档、博客、架构说明或产品演示中嵌入高质量图表的开发者、技术写作者和产品经理。它并非简单调用 Mermaid 或 draw.io 的封装，而是一套精心设计的视觉语言体系，让 AI 助手能够生成近乎人工设计水准的图表。

## 核心功能

- **29 种编辑级图表类型**：涵盖流程图、架构图、金字塔、循环图、时间线等多种常见图表形态，每种都经过视觉设计打磨
- **语义化模式系统**：通过"语义模式"描述图表行为，与布局解耦。一个队列、策略追踪或信任边界可以直接套用最接近的现有类型，无需为每种场景新增图表类型
- **纯静态输出默认**：默认生成自包含的 HTML + SVG，无阴影、无外部依赖，可直接嵌入任何网页或文档
- **格式转换能力**：能够将 draw.io 或 Mermaid 源码重绘为指定格式、尺寸和细节层级的图表
- **可选的无障碍动画**：虽然在 2.3 版本引入了可选的 accessible motion（用于有序说明场景），但静态输出始终是默认选择
- **多平台 Agent 支持**：同一套技能文件适用于 Claude Code、Codex 和 Pi，无需重复配置

## 技术架构

项目的技术核心在于"行为与布局分离"的设计理念。语义模式（semantic patterns）定义了图表的逻辑结构，例如数据流方向、节点关系、边界约束等，而具体的视觉呈现则由独立的类型映射完成。这种设计带来了两个直接好处：一是类型数量可控，29 种基础类型可以覆盖绝大多数场景；二是重绘能力极强，任意 Mermaid 或 draw.io 图表都能被解析后映射到最合适的视觉呈现上。

从实现角度看，所有图表均为自包含的 HTML + SVG 文件。SVG 矢量格式保证了在不同分辨率下的清晰度，而自包含意味着没有任何加载时依赖，双击即可在浏览器中查看。设计上刻意避免了阴影、渐变和过度装饰，采用编辑级排版风格——这更像杂志图表而非工程制图。

在 2.0 版本中引入的"Loop"类型值得特别说明：循环图（即飞轮图）使用"共享内存中枢"（shared-memory hub）来表示系统的核心共享状态，虚线则代表写回操作。这种设计在描述具身智能、多智能体协作等复杂系统循环时尤为清晰。

## 安装与使用

安装过程非常直接，只需将仓库克隆到本地，并将相关技能文件配置到你的 AI 编程助手中：

```bash
git clone https://github.com/cathrynlavery/diagram-design.git
cd diagram-design
```

以 Claude Code 为例，将技能文件放入对应的 skills 目录下即可。配置完成后，向 AI 助手发出自然语言指令即可生成图表，例如：

```
"用 diagram-design 画一个飞轮图，描述推荐系统的用户增长循环，使用 Loop 类型，带共享内存中枢。"
```

项目也会默认将 Mermaid 或 draw.io 源码重绘为更高品质的视觉呈现。如果你已有现成的 Mermaid 图表，只需提供源码，AI 助手会自动调用技能完成重绘，并可指定输出的尺寸、格式和细节层级。

## 适用场景

- **技术文档与博客插图**：需要嵌入架构说明、数据流图或概念关系图，但又不想花时间在 draw.io 中手工排版
- **产品演示与汇报材料**：编辑级的视觉质量适合直接用于客户演示或内部高层汇报，无需二次美化
- **AI Agent 开发中的状态可视化**：Loop 类型特别适合描述多智能体系统的记忆共享与写回机制，语义模式也能准确表达信任边界或策略追踪
- **大型项目的维护性文档**：由于语义与布局解耦，当业务逻辑变化时，重构图表只需调整语义描述，而非从头绘制

## 项目亮点

与常见的 Mermaid、PlantUML 或直接要求 AI 生成 SVG 的方案相比，diagram-design 的核心差异在于视觉质量的确定性。Mermaid 输出虽快速，但存在明显的"模板感"——同样的圆角矩形和箭头组合，几乎无法用于对外发布的正式文档。而本项目的编辑级设计规范，使输出结果更接近专业设计师的交付。

另一个差异化优势是语义模式的扩展性。普通方案遇到新场景只能增加新的图表类型，导致维护成本攀升和视觉风格漂移。而语义模式允许通过组合和映射现有类型来应对新需求，类型数量得到有效控制。

此外，项目坚持"无依赖、无阴影"的原则，生成的 HTML 文件可以轻松嵌入到任何技术栈中，不会与现有样式产生冲突，也无需担心依赖过期的维护问题。静态输出的默认选择则保证了可访问性和打印效果，无障碍动画始终是可选项。
