## 项目概述

Superpowers 是一套面向编码代理（coding agents）的完整软件开发方法论，构建于一组可组合的技能（skills）之上，并辅以初始指令，确保你的代理能够真正使用这些技能。简单来说，它并非一个单一的工具或插件，而是一套系统性的工作流程和规范，旨在改变编码代理的工作方式，从“直接写代码”转变为“先思考、再设计、后实现”的工程化流程。

该项目解决的核心问题是：当前编码代理（如 Claude Code、Cursor 等）在面对复杂任务时，往往倾向于跳过需求分析、设计评审和测试，直接生成大量代码，导致产出质量不稳定、与用户真实意图脱节、后期返工成本高昂。Superpowers 为代理注入了一套结构化的、类 SCRUM 的流程，使其能在无人监督的情况下，长时间、高质量地自主完成开发任务。

目标用户是重度依赖 AI 编码助手进行软件开发的开发者、技术负责人以及希望通过 AI 提升研发效能和代码质量的团队。无论你使用哪种主流编码代理，Superpowers 都能提供统一的、可复用的方法论支持。

## 核心功能

- **需求澄清而非直接编码**：当代理检测到你在构建新功能时，不会立即产出代码，而是会主动向你提问，逐步梳理出真实需求，并最终生成一份精炼的设计规格说明（spec）。
- **分段式设计评审**：将完整的设计规格拆分成适合人类阅读的小块，逐段展示给你审阅，确保你在签署设计前充分理解并认可方向，避免“黑箱”式的实现偏差。
- **可执行的实施计划**：生成一份极其清晰的实施计划，其粒度足以让一位“热情但缺乏项目上下文、审美欠缺且厌倦测试的初级工程师”按部就班地执行。该计划强调整合测试驱动的开发（TDD，Test-Driven Development）、YAGNI（You Aren't Gonna Need It，你不会需要它）和 DRY（Don't Repeat Yourself，不要重复自己）原则。
- **子代理驱动开发（Subagent-Driven Development）**：在你批准计划后，Superpowers 会启动多个子代理并行工作。每个子代理负责一项具体的工程任务，并在完成后由另一个代理进行代码审查。这种协作模式支持代理连续自主工作数小时。
- **可组合的技能体系**：核心功能由一系列独立的、可插拔的技能（Skills）构成，你可以根据项目需要启用或组合，形成最适合自己的工作流。
- **跨平台支持**：提供针对多种主流编码代理的接入方式，包括 Claude Code、Cursor、Gemini CLI、GitHub Copilot CLI、OpenCode 等，确保方法论在不同工具间保持一致。

## 技术架构

Superpowers 的架构设计遵循“指令 + 技能”的核心理念。其技术栈以 Shell 脚本为主要载体，这与 Claude Code 等代理的技能机制（Skills）高度兼容。项目结构上，它首先通过一组**初始指令（Initial Instructions）** 在代理启动时即注入行为约束，促使代理主动调用后续的技能。

其核心架构特点在于：

- **流程编排层**：通过定义清晰的阶段（需求分析、设计、规划、实施、审查），将传统的软件开发流程转化为代理可执行的状态机。例如，当代理识别到“构建功能”的任务时，会依据指令自动进入“需求澄清”状态，而非“编码”状态。
- **技能原子化**：每个技能（Skill）对应一个具体的操作或流程，例如“编写文档”、“生成测试”、“执行代码审查”等。这些技能是可组合的，代理可以根据任务动态调用和串联它们，类似于 Unix 哲学中“做一件事并做好”的工具。
- **代理间协作机制**：通过子代理（Subagent）的配置，实现任务的分发与回收。父代理负责规划与监督，子代理负责具体执行，子代理的结果需经父代理或专门的审查子代理验证，以此构建了一个多代理协作的闭环系统。

这种架构使得 Superpowers 不依赖任何特定 IDE 或平台的内部 API，而是通过定义行为规范和技能边界来实现其方法论。

## 安装与使用

安装 Superpowers 通常涉及为你使用的特定编码代理配置其“技能”或“指令”文件。虽然不同代理的安装路径略有差异，但基本模式如下：

1.  **获取项目**：将仓库克隆到本地指定目录。
    ```bash
    git clone https://github.com/obra/superpowers.git
    ```

2.  **接入代理**：以 Claude Code 为例，你需要将项目中的技能链接或复制到 `~/.claude/skills/` 目录，并在 Claude Code 的配置中引入初始指令文件。对于其他代理（如 Cursor、Gemini CLI），操作类似，均遵循其官方技能加载规范。

3.  **最小使用示例**：完成安装后，重新启动你的编码代理。在对话中输入类似以下指令以触发流程：
    ```
    “我想为我的项目添加一个用户登录功能。请使用 superpowers 流程来协助我。”
    ```
    代理此时应该不会直接编写代码，而是会按照 Superpowers 的预设，向你提问关于安全要求、验证方式、会话管理等问题，然后逐步输出设计文档供你确认。

> **注意**：更详细、分步的安装指南请参考仓库 README 中针对不同代理（如 Claude Code、Antigravity、Codex 等）的专门链接。

## 适用场景

- **大型功能开发**：当你需要实现一个涉及多模块、多步骤的复杂功能时，Superpowers 能确保代理先进行充分的系统分析和设计，避免因代码量大而失控。
- **长时间自主编程**：在需求明确且边界清晰的情况下，你可以通过子代理驱动模式，让代理在无人值守的情况下连续工作数小时，完成一整个子系统的开发，并自动进行测试和修正。
- **团队协作与知识管理**：由于 Superpowers 强制要求生成清晰的规格说明和实施计划，这些产出本身就是极佳的文档。团队可以借此审查 AI 的“工作逻辑”，并作为代码评审的辅助材料。
- **快速原型与架构验证**：对于探索性项目，你可以利用其“先设计后编码”的流程，快速生成多个方案的设计草案并进行比对，从而选择最优路径。

## 项目亮点

与市面上其他 AI 编程辅助工具或简单的提示词集合相比，Superpowers 的差异化优势十分明显：

- **工程方法论的系统化落地**：它不仅仅是告诉代理要“做测试”，而是通过完整的、强制性的流程（从需求到审查）确保 TDD、YAGNI、DRY 等原则贯穿整个开发周期。
- **高度的可组合性与可定制性**：它并非一个黑盒解决方案，而是一个开源框架。你可以修改现有的技能，或者新增符合团队规范的技能，实现个性化定制。
- **代理自主性的显著提升**：通过子代理协作和明确的流程节点，Superpowers 将编码代理从“逐行提示”的模式中解放出来，实现了真正意义上的“从规划到审查”的自主开发。
- **广泛的工具兼容性**：项目在开发之初就覆盖了当前主流的多种编码代理，使得团队在切换工具链时，其核心的 AI 开发流程规范可以无缝迁移。
