## 项目概述

Semantica 是一个开源的、图原生的上下文与可问责 AI 基础设施，旨在解决企业级 AI 应用中长期存在的两大痛点：上下文管理混乱与决策过程不可追溯。项目定位为“AI Agent 的开源 Palantir”，即通过将企业数据转化为知识图谱（Knowledge Graph）与上下文图（Context Graph），为 AI 系统提供结构化的、可推理的决策基础，并内置完整的决策溯源机制。

该项目面向金融、医疗、法律、政府等高合规性、高风险的行业用户，以及需要构建复杂 AI Agent 应用的技术团队。Semantica 的核心价值在于，它不只是一个知识图谱工具，而是一套完整的决策智能基础设施——从数据接入、语义提取、图谱构建，到因果推理与决策审计，形成了端到端的闭环。

## 核心功能

- **多源数据接入与语义提取**：支持将结构化、半结构化和非结构化企业数据（如数据库、文档、日志）自动转换为 RDF 三元组或属性图（LPG）数据，并抽取其中有价值的关系与实体。
- **上下文图与知识图谱双重建模**：同时支持 RDF（资源描述框架）与 LPG（标签属性图）两种图数据模型，允许用户根据业务场景选择最合适的表示方式，满足 W3C 标准下的互操作性需求。
- **图分析与因果推理引擎**：内置图遍历、路径分析、社区发现等图算法，并支持基于图结构的确定性因果推理（区别于概率性的机器学习推理），为决策提供可验证的逻辑链。
- **决策溯源与审计日志**：每一次 AI 决策或推理过程都会自动记录数据来源、转换步骤、推理路径，形成完整的决策血缘（Lineage），确保任何结论都可回溯、可审计。
- **本体与知识建模管理**：提供工具来定义和管理领域本体（Ontology），包括类、属性、关系约束，帮助团队建立统一的数据语义层，避免各系统间术语歧义。
- **策略引擎与治理接口**：支持访问控制、数据使用策略与合规规则配置，在运行时对数据访问和推理操作进行约束，确保 AI 行为处于可控范围内。

## 技术架构

Semantica 采用“多语言图存储”架构，设计上不与任何特定图数据库绑定。底层通过抽象存储适配层，支持连接 Neo4j、JanusGraph、Amazon Neptune、Apache Jena（TDB）等主流图数据库，同时可以利用 RDF 三元组存储或原生 LPG 存储，并根据数据规模与业务需求动态切换。

核心架构分为三层：

1. **接入与转换层**：负责各类企业数据源的连接与标准化，将原始数据映射为图模型，并在此过程中应用本体定义，实现语义统一。
2. **推理与分析层**：提供图算法库、规则引擎和因果推理模块。所有推理步骤均以图结构为输入，并以可解释的路径作为输出，而不是黑盒结果。
3. **治理与溯源层**：记录所有数据流和推理过程，生成不可篡改的审计轨迹。同时集成策略执行点，在推理前后校验权限与合规要求。

值得注意的设计特点是“确定性优先”：Semantica 在处理关键决策时，倾向于使用确定性的逻辑推理（如基于规则或图结构的推导），而非完全依赖大模型的概率生成。这使其在高合规场景下比纯 LLM 应用更具可信度。

## 安装与使用

Semantica 采用 Python 编写，已发布到 PyPI，可通过 pip 快速安装。基础安装命令如下：

```bash
pip install semantica
```

安装完成后，可以通过 Python API 快速创建一个上下文图并执行基础推理。以下是一个最小示例：

```python
from semantica import ContextGraph, Entity, Relation

# 初始化一个上下文图，接入本地文件或内存数据源
graph = ContextGraph("memory://")

# 定义实体与关系
alice = Entity("Person", {"name": "Alice", "role": "Analyst"})
report = Entity("Document", {"title": "Q3 Financial Report", "risk": "high"})
graph.add_entity(alice)
graph.add_entity(report)

# 建立关系边
graph.add_relation(alice, Relation("authored", report))

# 执行图查询与因果推理
result = graph.query("""
    MATCH (p:Person)-[:authored]->(d:Document)
    WHERE d.risk = 'high'
    RETURN p.name, d.title
""")
print(result)

# 查看决策溯源
trace = graph.get_lineage(report)
print(trace)
```

对于生产环境，可配置连接外部图数据库（如通过 `NEO4J_URI` 环境变量），并启用审计日志与策略引擎。详细的配置说明可参考官方文档。

## 适用场景

- **金融合规审计**：银行或投资机构在处理交易、信贷审批等环节，利用 Semantica 构建决策图谱，自动记录每一笔审批的依据，满足监管机构的审计要求。
- **医疗临床决策支持**：将患者病史、检验结果、用药指南等异构数据融入知识图谱，辅助医生进行诊断推理，并提供可解释的推荐路径，降低误诊风险。
- **法律条款与案例检索**：法律科技公司可以构建判例知识图谱，让 AI Agent 在回答法律咨询时，能够关联法条、相似判例和司法解释，并展示完整的推理链路。
- **企业知识管理（Agent 记忆）**：为大型语言模型 Agent 提供结构化的长期记忆和上下文背景，使其在多轮对话或复杂任务中保持语义一致，且每一次响应都可追溯到具体知识源。

## 项目亮点

- **决策溯源内建**：与多数知识图谱工具不同，Semantica 将审计轨迹作为一等公民，而非事后追加的功能。这使得“可解释 AI”不仅仅停留在论文层面，而是真正落实到产品机制中。
- **多模型图存储，拒绝锁定**：同时支持 RDF 和 LPG 两种图范式，并兼容多个底层图数据库，用户可根据现有技术栈自由选型，无需被某一家厂商绑架。
- **确定性与概率性推理的混合**：在依赖大模型的年代，Semantica 强调对关键步骤采用确定性推理，既保留了 AI 的智能性，又规避了幻觉带来的风险，尤其适合高精度要求的专业领域。
- **完整治理与策略支持**：从底层存储到上层 API，均内置访问控制与数据使用策略接口，让数据治理不再是外挂模块，而是基础设施的有机组成部分。
- **社区活跃，快速迭代**：目前项目在 GitHub 上获得超过 2300 星标，单日增长超百星，且采用 MIT 许可证，允许商业免费使用与二次开发。
