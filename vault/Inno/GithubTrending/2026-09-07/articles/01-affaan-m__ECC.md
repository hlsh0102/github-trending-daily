## 项目概述

ECC（Enhanced Claude Code）是一个面向 AI 编程代理（Agent）的运行时性能优化与能力增强系统。它并非一个独立的 AI 模型或 IDE，而是一套为 Claude Code、Codex、Opencode、Cursor 等主流编程代理打造的“操作系统层”工具。该项目旨在解决当前 AI 编程代理在复杂项目协作中普遍存在的几个痛点：上下文窗口有限导致的长任务“失忆”、多代理协作时指令遵循不一致、重复性低级错误频发，以及缺乏对用户偏好的长期记忆。通过注入一整套工程化的“技能、直觉、记忆与安全体系”，ECC 帮助开发者将 AI 从“偶尔能写出代码片段”的工具，升级为稳定、可靠、具备项目上下文的“虚拟资深工程师”。ECC 采用 MIT 许可证，完全开源，且适配远超 GitHub 星标数所反映的活跃社区（项目当前拥有超过 25 万 Star），适合所有依赖 AI 编程代理进行日常开发的个人开发者与团队。

## 核心功能

- **复合技能库（Skills）**：预置超过 200 个针对代码生成、重构、调试、测试、文档编写等任务的精细技能。这些技能不仅是提示词模板，而是包含多步骤推理链与自检机制的可执行指令包，能显著提升模型对复杂任务的拆解能力。

- **内隐直觉引擎（Instincts）**：通过分析模型的输出模式与错误历史，自动生成一套“行为准则”。例如，当检测到模型反复在异步代码中忽略错误捕获时，ECC 会动态注入一条“直觉”，提示模型在生成异步代码时优先考虑错误边界，从而减少运行时崩溃。

- **分层记忆系统（Memory）**：具备短期工作记忆与长期项目记忆。短期记忆用于在单个会话内追踪未完成的任务与待办事项；长期记忆则将用户的关键偏好（如代码风格、框架选择）、项目架构决策与历史经验持久化存储，并在新会话开始时自动加载，有效解决“每次对话都像第一次见面”的问题。

- **安全护栏（Security）**：内置动态沙箱策略与危险操作熔断机制。在授权 IDE 或 CLI 环境下，可拦截高风险的 shell 命令（如 `rm -rf`）、检测凭证泄露风险，并在执行文件系统级写操作前进行变更预览确认。

- **多重代理适配层（Harness Adapter）**：提供统一的中间件 API，允许同一套 Skills 与 Memory 在 Claude Code、Codex、Opencode、Cursor 等不同代理间无缝迁移，降低用户切换工具的迁移成本。

- **研究优先型开发模式（Research-First）**：在开始生成实质代码前，强制引导代理执行“阅读 API 文档 → 搜索代码库历史 → 编写最小验证原型”的预研流程，确保产出遵循项目既定约定而非凭空想象。

## 技术架构

ECC 的底层完全基于 JavaScript 构建，以 NPM 包形式分发，可轻松作为一个插件或包装器集成到主流代理工具中。其核心架构分为三层：

1.  **核心调度器（Core Scheduler）**：作为运行时的中枢，它拦截代理模型的输入与输出流。输入侧，调度器根据当前任务类型，从记忆库中检索上下文并组合相关的技能与直觉指令；输出侧，则执行安全过滤与行为审计。

2.  **记忆与状态存储**：采用混合存储方案。对于需要高吞吐量的会话状态，使用内存数据结构；对于需要持久化的长期记忆与项目档案，采用基于文件系统的结构化 JSON 存储，并以 SQLite 作为可选的高性能后端，便于在大型项目中高效检索历史决策。

3.  **上下文工程引擎（Context Engineering）**：项目独创的“上下文组装”机制，并非简单地将所有信息塞入提示词，而是通过一套 RAG（检索增强生成）算法，根据当前任务的令牌预算，动态筛选最相关的记忆片段、技能步骤与历史代码片段进行融合。

设计上强调可观测性。所有注入的指令与记忆均带有元数据标签，开发者可通过提供的内置 TUI 面板实时查看“代理当前为什么这么说”，完全透明地理解代理的决策逻辑，从而精准调优技能库内容。

## 安装与使用

ECC 需要 Node.js 20+ 环境，并已安装任一受支持的 AI 编程代理（如 Claude Code CLI 或 Cursor）。安装可以通过 npm 一键完成：

```bash
# 全局安装 ECC
npm install -g @affaan-m/ecc

# 在项目目录中初始化 ECC（会创建 .ecc 配置目录）
ecc init

# 启动代理（以 Claude Code 为例）
ecc run --agent claude -- "你的开发任务描述"
```

首次初始化时，ECC 会自动扫描当前 Git 仓库的结构、识别项目技术栈，并尝试从 `.env.example` 等文件中学习潜在的配置规范。运行上述指令后，ECC 将自动肩负起所有注入逻辑。对于 Cursor 用户，可直接在 Cursor 设置中指向 ECC 提供的内置插件路径即可启用。

最小可用示例：初始化后直接运行 `ecc run` 并请求“为项目添加用户登录功能”，ECC 会自动执行研究流程（检查是否已有认证中间件）、参考记忆中的代码风格，再输出实现方案与代码。整个过程中，终端会打印记忆注入日志与安全检查记录。

## 适用场景

- **大型代码库重构**：当需要跨模块修改代码时，ECC 的记忆系统能帮助代理保持对既有接口与调用链的全局认知，避免“改 A 处而不知 B 处逻辑”的连锁错误。

- **团队协作与新成员培训**：团队可将共同的架构决策与编码规范录入 ECC 记忆，使每个开发者启动的 AI 代理都带着“团队标准”，有效统一代码风格，加速新人调试。

- **自动化测试用例生成**：利用其复合技能库，让代理理解复杂业务逻辑后，自动生成覆盖边界条件的测试用例，并将先前的测试失败模式存入记忆以防止重蹈覆辙。

- **安全审计与合规检查**：利用安全护栏对所有代理生成或执行的命令进行审计，可快速发现潜在的路径穿越、注入攻击或密钥泄露风险。

## 项目亮点

与市面上简单的“API 代理包装器”或单一的提示词工程模板不同，ECC 的最大优势在于其**系统性、可扩展的复合生态**。它不仅仅优化一次对话，而是通过持久的记忆与进化的直觉，让代理在每次任务中表现得更“聪明”。其“技能即代码”的开发模式允许开发者将内部最佳实践封装为可复用资产，而非散落在文档中的文本片段。此外，其高度成熟的代理适配层在同类开源项目中颇为罕见，真正意义上解决了 AI 编程工具碎片化的问题。支持多语言文档与 Mirrored 的容器化部署，也让其在企业级环境中更容易落地。
