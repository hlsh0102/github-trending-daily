## 项目概述

Skills for Real Engineers 是由知名 TypeScript 教育家 Matt Pocock 维护的开源项目，它直接来源于作者本人日常使用的 `.agents` 目录。该项目不是另一个试图“接管”软件开发全流程的宏大框架，而是一套**小型、可组合、易适配**的 AI 辅助开发技能集。它解决的核心痛点是：像 GSD、BMAD、Spec-Kit 这类方案虽然功能强大，却通过掌控流程剥夺了开发者的控制权，使得流程自身的缺陷难以定位和修复。该项目面向真正进行工程实践（而非“vibe coding”）的开发者，目标用户是那些希望 AI 助手理解真实工程约束、能灵活融入自身工作流而不被框架绑架的工程师。

## 核心功能

- **即用型技能集**：从作者真实使用的 `.agents` 目录直接提取，每个技能都经过真实工程场景检验，而非理论推演。
- **模型无关设计**：技能不绑定特定 AI 模型或平台，无论是 Claude、GPT 还是其他模型，均可直接调用。
- **透明可审计**：所有技能以普通文件形式存在，开发者可以逐行审查 AI 将被赋予的指令，不存在黑盒逻辑。
- **极速安装**：通过 Claude Code 插件机制实现 30 秒安装，将整套技能作为受管、只读的捆绑包注入环境。
- **高度可修改**：技能文件采用纯文本/脚本格式，用户可以自由 fork、修改、增删，完全掌控 AI 的行为边界。
- **组合复用**：技能之间相互独立、无隐式依赖，开发者可按需挑选组合，并轻松编写自己的新技能。

## 技术架构

该项目的架构哲学是“以小博大”，避免了传统框架的层级化设计。技能以**扁平文件结构**存放于 `.agents` 目录中，每个技能本质上是一个独立的指令包或工具定义，遵循 Unix 哲学中“做一件事并做好”的原则。这种架构带来几个关键优势：首先，技能之间的耦合度极低，单个技能的故障或修改不会波及其他技能，降低了调试成本；其次，所有内容均是可读的纯文本，天然适配版本控制，开发者可以清晰地追踪每次变更对 AI 行为的影响。与采用固定流程编排的 GSD 等项目不同，本项目不强制规定“先做什么后做什么”，而是将决策权保留给开发者，AI 只在被明确调用的技能范围内提供帮助。这种设计基于 Matt Pocock 数十年的工程经验，强调**可控性优先于自动化程度**。

## 安装与使用

### 安装步骤（约 30 秒）

1. **方式一（插件安装）**：使用 Claude Code 的插件系统直接安装完整技能集。
   ```bash
   claude plugin install mattpocock/skills
   ```
   安装后，所有技能将以受管、只读的捆绑包形式注入你的 `.agents` 目录。

2. **方式二（手动复制）**：将仓库中的 `.agents` 目录内容复制到你的项目根目录。
   ```bash
   git clone https://github.com/mattpocock/skills.git
   cp -r skills/.agents ./your-project/.agents
   ```

### 最小使用示例

在项目目录中启动你的 AI 助手（如 Claude Code），技能会自动加载。例如，若仓库中包含 code-review 类技能，你可以直接命令：

```
请使用 code-review 技能对 src/main.ts 进行审查
```

AI 将按照技能文件中的指令执行，而不是自由发挥。若要自定义，只需编辑 `.agents` 目录下对应的技能文件。

## 适用场景

- **自动化代码审查**：将团队代码规范固化在技能文件中，确保 AI 的审查标准与团队保持一致，而不是依赖模型的通用知识。
- **规范化提交信息**：使用技能强制遵循 Conventional Commits 等规范，让 AI 在生成提交信息时自动符合格式要求。
- **内部工具开发**：当项目使用特定库或架构模式时，通过技能注入相关知识库，避免 AI 给出与现有代码风格不符的建议。
- **教育学习**：通过阅读技能的定义文件，开发者可以了解 Matt Pocock 是如何结构化地指导 AI，从而建立自己的最佳实践。

## 项目亮点

与 GSD、BMAD 等“重流程”方案相比，本项目最大的差异化优势在于**最小的约束面和最大的透明度**。其技能定位为“脚手架而非施工队”，AI 的每个行为都能直接追溯到精确的技能文件，这也让团队内的知识传递变得前所未有的简单——新成员只需阅读仓库即可理解 AI 的行为准则。项目获得了 255,000+ 的 Stars 和持续的高关注度，验证了其在极简主义与实用性之间找到了正确平衡。另一个亮点是它鼓励“创造性破坏”——作者明确建议开发者 hack 这些技能并使其成为自己的，这与许多闭源或强约束框架形成鲜明对比。
