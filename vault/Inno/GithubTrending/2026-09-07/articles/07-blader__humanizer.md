## 项目概述

Humanizer 是一个面向 AI 写作场景的 Agent 技能（Skill），它的核心使命是去除文本中的“AI 味”，让机器生成的文字读起来像真人撰写，同时完整保留原文的信息与语义。该项目以纯 Markdown 形式分发，不依赖特定运行时，因此可以无缝适配任何支持技能（Skills）机制的 AI 代理，如 Claude Code、Claude Desktop 或自定义 Agent。目标用户包括内容创作者、技术写作者、营销人员，以及任何需要借助 AI 产出内容、又希望最终文本更自然、更贴合个人风格的群体。Humanizer 在 GitHub 上已获得超过 44000 星，并保持高速增长，足见其切中了大量用户的真实痛点。

## 核心功能

- **去 AI 化改写**：识别并消除 AI 写作中常见的刻板句式、过度工整的排比、空洞的连接词及机械化的过渡，使文本呈现真人写作的节奏变化与随机性。
- **语义完整保留**：改写过程严格遵循原文信息，不删减、不添加事实性内容，只针对风格与措辞进行优化，确保最终输出不违背作者原意。
- **自带风格匹配**：用户可以提供自己撰写的 2–3 段文字作为参照，Humanizer 会学习其中的节奏、词汇偏好、标点习惯乃至个性化的“小怪癖”，使改写结果更贴近用户个人文风，而非通用的“真人感”。
- **文件级重写**：除直接粘贴文本外，Humanizer 支持传入文件路径，直接改写文档中的散文部分，适用于长文博客、报告或书籍章节的批量润色。
- **多入口调用**：支持通过显式斜杠命令（`/humanizer`）或自然语言指令触发，兼容直接对话与内联使用场景，接入成本极低。
- **跨代理、跨平台兼容**：以纯 Markdown 技能包形式发布，既可配合官方 Skills CLI 安装至全局或项目级，也能作为插件集成进 Claude Code 2.1.142+，甚至可手动解压复制至任何 Agent 的技能目录。

## 技术架构

Humanizer 的技术形态极其轻量，核心在于一份规范的 `SKILL.md` 文件，文件内通过结构化的 Markdown 定义了技能的名称、描述、触发指令以及处理逻辑。这种设计使得 Humanizer 不具备独立运行的程序逻辑，而是完全依赖宿主 Agent 的语言模型能力来理解和执行改写任务——本质上，它是一份精心设计的提示词工程模板，外加一套完整的调用约定。

由于不包含编译代码或依赖模块，Humanizer 自然绕过了环境配置、依赖冲突和跨平台兼容等问题。任何能够解析 Markdown 技能定义的 Agent 框架（如 Anthropic 的 Agent Skills 规范）均能直接调用。此外，Humanizer 提供了可选的“风格样本”输入机制：用户在指令中附带的个人写作样本会被视为高优先级的上下文线索，引导模型在生成时进行风格迁移，而非每次一律套用默认的“反 AI 特征”。这种“提示词+样本”的双层设计，在不增加系统复杂度的前提下显著提升了输出质量的个性化程度。

## 安装与使用

### 安装

使用官方 Skills CLI 进行全局安装（推荐）：

```bash
npx skills add blader/humanizer --global
```

若希望仅限当前项目使用，去掉 `--global` 参数。也可以附加 `--agent <名称>` 或 `--agent '*'` 指定需要启用此技能的代理，安装完成后重载技能列表即可。

对于 Claude Code 2.1.142 及以上版本，可直接以插件形式安装：

```text
/plugin marketplace add blader/humanizer
/plugin install humanizer@humanizer
```

在 Claude Desktop 中，可下载本仓库 ZIP 包并作为用户技能上传；手动安装时，只需将 `SKILL.md` 复制至目标 Agent 的技能文件夹。

### 最小使用示例

最直接的方式是通过斜杠命令触发，粘贴待改写文本：

```
/humanizer

请将以下文本改写得更像真人写作，保留原意：
[在此粘贴你的文本]
```

也可以直接对话下达指令：

```
请人性化改写这段内容：[你的文本]
```

对于文本文件，直接指定路径即可：

```
将 docs/launch-post.md 中的散文部分做去 AI 化处理
```

若想匹配个人声音，在命令中附上风格样本：

```
/humanizer

以下是我个人的两段写作，用于风格参照：
[粘贴你的写作片段]

接下来请将这段 AI 生成的内容改写得像我写的：
[粘贴待改写文本]
```

## 适用场景

- **内容创作与博客发布**：使用 AI 辅助起草初稿后，用 Humanizer 进行二次改写，消除模板化腔调，让发布内容保留个人笔触，减少读者对 AI 生成内容的“识别感”。
- **营销文案与广告物料**：品牌方需在高效产出的同时维持真诚的品牌语调，Humanizer 可将标准化的产品描述转化为亲和力更强的口语化表达，且不会扭曲核心卖点。
- **技术文档与官方公告**：技术写作中经常需要将内部 AI 生成的草稿转为面向社区或用户的外发版本，Humanizer 能弱化机器指令感，提升文档的可读性与人文温度。
- **学术与个人表达的辅助审校**：对于非母语写作者而言，先用 AI 生成底稿再通过 Humanizer 适配个人风格，是降低写作门槛、同时保留表达主体性的有效手段。

## 项目亮点

Humanizer 与同类“去 AI 化”工具相比，差异化优势体现在三个维度：

1. **零依赖的格式标准**：坚持只做纯 Markdown 技能，不写独立后端或自研解析器，彻底告别版本碎裂与安装困境，使其可被任何遵循 Agent Skills 生态的系统复用。
2. **以风格样本驱动的个性化**：多数改写工具采用固定的“去模板”策略，结果千篇一律。Humanizer 独辟蹊径地引入“写作样本”作为可选输入，让模型感知个人节奏与偏好，实现真正的 per-writer 风格映射。
3. **多形态分发与活跃社区验证**：早期即获得数千 Star 并发售由社区持续贡献的使用案例，从 CLI 到插件再到桌面端手动安装，覆盖了主流 AI 代理的全部接入路径。MIT 许可证也保证了商用与二次开发的自由度，形成了快速迭代的良性循环。
